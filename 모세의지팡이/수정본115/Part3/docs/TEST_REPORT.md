# 배포 점검 기록

이 문서는 실제 수행한 점검 범위입니다. 전략 수익성 평가나 자동 합격 기준이 아닙니다. 프로그램을 시작하거나 전략을 생성할 때 아래 개발 테스트가 자동 실행되지 않습니다.

## 코드 점검

`python tests/test_smoke.py` — **14개 테스트 통과**.

| 점검 | 확인한 내용 |
|---|---|
| 원본 참조 보존 | 포함한 원본153개 파일의 SHA256이 복사 당시 목록과 일치 |
| SPECIAL1~7 기본 생성 | 원본과 생성 파일의 등록 전략/시간 연결 정의, watch payload, handler ID를 namespace 정규화 후 비교 |
| 원본 파서 | 실제 ComposerManager의 StrategySpec/ConfigTimedChainSpec 파서가 생성 정의를 수락 |
| 일반 슬롯 수정 | SPECIAL1/2/6/7의 TF 변경 및 SPECIAL2 ATR 설정 반영 |
| SPECIAL3 수정 | 교차 TF/기간, 연결 제한 시간, 최종 TF, 반대 FVG 취소 설정 반영 |
| SPECIAL4 경계 | 선행 극값 이동의 ATR `>=` 경계와 ATR 취소 해제 분기 |
| SPECIAL4 최종 검사 | 재작성된 최종 gate의 기본 의미 및 반대 EMA 배열 차단 |
| SPECIAL5 감시 | 부모 일반/레짐 선택에 따른 watch 수와 하위 만료 봉 수 설정 |
| 4 TF 조합 | 활성 네 카드의 AND가 원본 조건 정의4개로 생성 |
| 번호 보호 | 기존 SPECIAL021/Test_SPECIAL022 보존, 새023/024 생성 |
| 수동 편집 | 새로운 Test 번호와 클래스/watch/state namespace 변경 및 본문 보존 |
| 입력 계약 | 모든 카드 해제/실전 파일명/경로 이탈/지원하지 않는 MA 기간 거부 |
| 실제 엔진 연결 | 7개 생성 파일을 원본 이벤트 엔진에 각각 하나씩 등록하고 실제 Composer kernel 생성 |
| 직접 작성 파일 재열기 | .recipe.json이 없는 Test Python도 수동 코드로 열림 |

원본 이벤트 커널 점검은 포함된 reference와 사용자가 제공한 실제 Part1 경로 양쪽에서 수행했습니다. 각 커널의 선택 플러그인이 해당 Test 하나인 점을 확인했습니다. SPECIAL4/5처럼 일반 StrategySpec 없이 runtime handler로 작동하는 경로도 실제 생성자까지 확인했습니다.

표준 라이브러리만 있는 경로는 `python -S cli.py preview --recipe examples/SPECIAL4.json`으로 확인했습니다. GUI/생성기에 pandas나 duckdb를 미리 설치하지 않아도 코드 미리보기 생성이 가능합니다.

## 실제 UI 조작 점검

로컬 Python API에 연결한 Chromium DOM에서 다음을 조작했습니다. 환경의 브라우저 탐색 정책 때문에 테스트 harness가 로컬 HTML/CSS/JS를 불러오고 API 요청을 같은 실제 Python 서버로 전달했습니다. Python 서버와 분리된 가짜 전략/저장 응답을 사용하지 않았습니다.

- SPECIAL1~7 불러오기, 네 카드 자동 입력, 실제 Python 미리보기
- 4 TF JSON 가져오기, 사용안함/복구, 카드 삭제·추가·최대4개 제한
- 지표 수치 조건 값 변경과 코드 반영, TF 묶음, 최종 OZ 설정
- 설정 JSON 저장, 실제 새 Test 파일 생성, 최근 작업 재열기
- 수동 Python 편집본 보존과 새로운 번호 생성
- GPT 문서 탭, SPECIAL4 역할 상세 설정
- 1413×1056 / 1366×768 / 1920×1080에서 문서 전체 가로 넘침 없음
- 조작 과정의 JavaScript page error 없음

`UI_preview.png`, `UI_SPECIAL4.png`는 배포 코드의 실제 화면입니다. 이미지 생성 모델로 만든 기능 시안이 아닙니다. 개발용 임시 생성 파일과 초안/경로는 배포 전에 제거했습니다.

## 이 환경에서 실행하지 않은 항목

Windows 기본 브라우저/배치 실행, 사용자 MT5 터미널을 통한 데이터 구축, 전체 캡처를 이용한 장기간 TICK/EVENT 재생 및 원본과의 모든 신호 시각·가격 일치 비교는 사용자 환경에서 확인해야 합니다. Windows spawn 경로는 요청 전달과 초기화 구조를 구현했으며 Windows 실환경 전체 실행까지 완료했다고 표시하지 않습니다.

이 개발 환경에는 데이터 창고용 duckdb와 사용자 MT5 캡처가 없었습니다. 실제 PART2 데이터 구축/재생 완료나 백테스트 수익률을 만들어 보고하지 않습니다. 기존 Part2 환경으로 연결한 다음 계획 확인 → 실제 실행 순서로 확인하세요.

원본 모니터 모듈의 로그 설정에서 개발 테스트 중 ResourceWarning이 한 번 관측되었으며 테스트 실패는 아니었습니다. 원본을 고치거나 경고를 숨겨 배포 기준을 바꾸지 않았습니다.

## 사용자가 비교할 때

같은 엔진 코드, 같은 원본 프로필, 같은 시세 캡처와 시각 설정, 동일한 초기 상태에서 원본과 생성 파일을 따로 실행하세요. 새로운 namespace는 원본 운영 감시/상태 파일을 이어받지 않습니다. 코드 편집 또는 슬롯 설정을 바꾼 전략은 원본과 다른 결과가 나오는 것이 정상일 수 있으므로 변경된 조건을 기준으로 확인합니다.

실제 비교가 필요할 때 추가 개발 테스트를 만들 수 있지만 UI에 자동 합격 판정 또는 실전 승격 기능을 추가하지 않습니다.
