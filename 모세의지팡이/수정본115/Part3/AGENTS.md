# 이 코드베이스에서 작업하는 GPT/개발자 규칙

이 폴더는 현재 기준본입니다. 별도 지시 없이 과거 버전 또는 임의의 다른 구조로 되돌리지 않습니다.

## 수정 경계

`reference/`는 과거에 복사된 역사 자료이며 실행·AI 계약의 기준이 아닙니다. 현재 계약은 공통 상위 폴더의 `Part1/`, `Part2/`에서 읽습니다. 두 폴더는 이 작업에서 절대 수정하지 않습니다.

사용자가 새로운 전략만 요청하면 `generated/`의 새 Test 파일과 그 Recipe/설명만 추가합니다. 기존 생성 파일도 덮어쓰지 않습니다. 생성기 기능 수정이 필요할 때만 `lab/`, `web/`의 해당 부분을 수정하고 문서에 변경점을 남깁니다. Part1/Part2의 실제 파일은 이 작업 범위가 아닙니다.

## 꼭 유지할 계약

- 파일명은 `Test_SPECIAL001.py`부터 `Test_SPECIAL999.py` 형식이며 새 번호를 자동 배정합니다.
- `register(manager)`가 실제 PART1 플러그인 진입점입니다. 임의의 `BaseStrategy.check_entry()`로 바꾸지 않습니다.
- spec ID, watch 접두사, runtime 상태 키/파일명을 새 전략 전용으로 분리합니다.
- 생성 파일이 `lab`, `Part3`, 원본 `SPECIALn`을 import해 대신 실행하지 않게 합니다.
- 사용자 = 자연어 전략 아이디어, AI = 자연어 해석, Part3 = JSON 검증 + 코드 생성입니다. 자연어 재판정·자동 보정과 수동 생성기는 제거했습니다. 조건은 길이 제한 없는 steps/branches로 전달합니다. 생성은 Recipe v2만 받으며, 과거 생성 파일은 읽기 전용 조회만 유지합니다.
- Part3는 미검증 프로토타입입니다. 사용자 의미의 정상 전달·계산·생성을 검증하며 과거 Part3 구조/출력에 억지로 맞추지 않습니다.
- 순서/취소/봉 기준을 단순 현재값 AND로 축약하지 않습니다.
- 사용자 확정 #001~#050의 구조적 기능 완성이 우선입니다. schema→Recipe→validator→compiler→생성 코드 문법을 확인합니다. 번호/문장별 분기는 운영 코드에 넣지 않습니다. Qwen 실모델의 추가 해석 시험·프롬프트 튜닝·학습 데이터 생성은 별도 지시 전까지 하지 않습니다. 구조화 JSON 강제와 validator 차단은 유지합니다.
- 주문·리스크·재현확인 패널, 자동 실전 승격, 복잡한 자동 검증 시스템을 다시 추가하지 않습니다.
- 기존 생성 파일을 조회할 수 있어도 AI 화면에서 조용히 덮어쓰지 않습니다.
- AI(Qwen3:8b)는 신규 SPECIAL의 구조화된 의도만 반환합니다. 조회 도구는 현재 프로젝트의 제한된 텍스트만 읽고, Recipe 적용·검증·코드 생성·저장은 신뢰된 Part3 코드가 담당합니다.

## 확인과 보고

먼저 실제 대상 원본을 읽고 수정합니다. 원본 주석과 실행 코드가 충돌하면 현재 실행 코드의 동작을 분석하고 사용자 요청에 없는 동작 변경을 하지 않습니다. 생성기에서는 원본 설명 주석을 보존하므로 수정된 값은 `PART3_RECIPE`와 실행 본문에서 확인합니다.

문법 및 작은 함수/등록 정의 점검은 `tests/test_ai_only_generation.py`를 활용할 수 있습니다. 실데이터, 캡처, Windows MT5가 없는 상황을 숨기고 전체 백테스트 완료 또는 완벽한 성과를 선언하지 않습니다.
