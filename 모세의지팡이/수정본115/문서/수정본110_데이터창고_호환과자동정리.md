# 수정본110 데이터창고 호환과 자동 정리

## 기존 구축 데이터 재사용

개발자 EA로 만든 창고를 라이선스 EA가 사용하는 경우, 검증된 원본 소스와 EA의 대응 관계를 배포 호환 목록에 연결합니다. 배포 기간만 달라진 EA도 같은 소스의 발급 이력과 연결합니다.

원본 EA 파일과 전체 MQL 소스 식별값이 모두 검증 항목과 일치해야 연결됩니다. 실제 소스가 변경되거나 검증되지 않은 원본 EX5로 바뀌면 기존 데이터 호환을 자동 승인하지 않습니다. 종목·녹화 모드·스키마·타이머·데이터 무결성 검사는 그대로 유지합니다. 창고 데이터의 원래 EA 식별값을 덮어쓰지 않습니다.

검증 근거는 `EA_녹화호환_소스검증.json`에 보관합니다. 이 문서는 다음 수정본에도 복사되며, 이전 수정본의 검증결과 폴더를 복사할 필요가 없습니다. 발급 이력과 원본 호환 설정도 다음 수정본에서 그대로 이어집니다.

## 자동 정리

창고 연결 저장, 웹 백테스트 작업 시작 전, CLI 계획·실행 시작 전에 확인된 작업 잔여물을 정리합니다. 웹 작업을 등록하는 동안과 계획·구축·재생이 진행되는 동안에는 운영체제 잠금으로 정리를 막습니다. 이전 버전의 작업 기록은 PID와 생성 시각까지 확인합니다. 실행 중이거나 상태를 확인할 수 없으면 정리를 미룹니다.

삭제 대상은 복구 완료 후 남은 생성 작업 폴더, 완성되지 않은 공식 MQL 빌드 캐시, 확인된 미완료 변환 임시 폴더, 종료가 확인된 작업의 임시 저장 파일·정지 요청입니다. 정상 캡처 파일 목록을 훑거나 덕디비를 수정하여 정리하지 않습니다.

실제 녹화 데이터, 덕디비, 완료·취소·부분 백테스트 결과, 로그, 완성된 EA 캐시, 미완료 MT5 원본 복구 기록과 백업, 데이터 부족 진단 기록은 보존합니다. 알 수 없는 파일, 연결 폴더, 사용 중인 파일은 삭제하지 않습니다. 정리에 실패해도 파일을 보존하고 실행을 계속합니다.

## 확인 결과

- 실제 배포 창고를 읽기 전용으로 사용한 동일 요청: 이전 새 구축 13개월·재사용 0개 → 새 구축 0개월·기존 데이터 재사용 13개·재변환 0개. 재사용 파일 약 2.93GB의 해시를 검사했습니다.
- 실제 작업 잔여물만 복사한 시험 창고: 복구 완료 작업 폴더 39개, 14,131,252바이트 정리. 덕디비·결과·완성된 빌드 파일의 해시는 유지됐습니다.
- 소스 없는 실제 배포 코드 묶음 300개 모듈: 새 정리 기능과 연결·작업 시작 모듈을 불러왔고, 같은 실제 창고에서 재사용 13개를 확인했습니다.
- 호환 및 발급 이력 26개, 창고·기간·웹 작업·별도 프로세스·자동 정리 88개, 배포 코드 묶음 15개 검증 통과. 실제 Windows 파일 잠금, 별도 프로세스 실행 잠금, 연결 폴더, 창고 이동을 포함합니다.

수정본109의 코드, Part1 거래·EA 원본, UI, 실제 설치된 배포본과 실제 데이터창고는 수정하지 않았습니다. 이 기능은 수정본110에서 새로 생성한 통합설치로 배포됩니다. 완성된 통합설치 EXE 전체 빌드는 이번 검증에 포함하지 않았습니다.
