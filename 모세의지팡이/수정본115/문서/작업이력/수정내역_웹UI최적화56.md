# 수정본56 — 웹 백테스트 UI 최적화 5항목

2026-10-01. 사용자의 지시에 따라 기존 수정본56에서 작업했다. 제품 소스 2개 수정, 회귀 테스트 2개와 이 문서 추가. 이번 검증 증거는 `검증결과/웹UI최적화/`에 새로 저장했다.

## 적용 내용

1. **실행 즉시 잠금:** 클릭 직후 실행 버튼을 잠그고 진행 중 시작 요청을 공유 상태로 차단한다. API 실패나 로컬 입력 오류이면 버튼을 복구한다. 활성 작업이 있는 동안 새 시작 요청을 보내지 않는다.
2. **조회 중복 방지:** 상태와 결과 조회 각각 진행 중인 Promise를 공유한다. 결과를 화면에 표시한 뒤에만 표시 완료로 기록하므로 실패 시 재시도할 수 있다. 이전 실행의 늦은 응답은 새 실행 화면에 반영하지 않는다.
3. **조각 목록 표시 대기 축소:** 실행 ID를 받으면 즉시 상태를 조회한다. 계획 조회·시작 대기는 응답이 끝난 뒤 300ms, 녹화 승인 대기·실행 단계는 1500ms 뒤 다음 요청을 예약한다. 고정 주기에 새 요청을 계속 보내는 방식을 제거했다. 녹화 승인과 정지 요청 후에도 즉시 상태 조회를 예약한다.
4. **종료 뒤 조회 중단:** 완료·중단·오류에서 제공된 결과 표시까지 끝나면 상태 조회를 중단한다. 결과 조회 실패 시에는 재시도한다. 백테스트 메뉴를 떠나면 예약을 취소하고, 돌아오면 진행 중 실행의 상태를 다시 조회한다. 안전 정지 요청 자체를 완료로 취급하지 않고 부분 결과를 기다린다.
5. **강제 재녹화의 기존 파일 검증 생략:** `rebuild=True`이면 `find_capture()`를 호출하지 않는다. 재사용하지 않을 기존 조각 파일 전체를 해시하는 비용을 없앴다. 일반 실행의 재사용 후보 검증, EA 빌드 확인, 조각 경계·추정치·녹화 승인 토큰 계산과 실제 녹화/교체 절차는 그대로 유지한다.

## 검증 결과

- 웹 UI 회귀 테스트 **16개 통과**. 현재 HTML·JavaScript를 별도의 headless Edge에서 실행하고 API를 대체했다. 연속 클릭, 시작 실패·입력 오류, 느린 상태·결과 응답, 300/1500ms 단계 전환, 완료·중단·오류의 조회 종료, 결과 실패 재시도, 안전 정지와 부분 결과, 메뉴 왕복, 완료 후 재실행, 이전 실행의 늦은 응답을 확인했다. 외부 네트워크는 차단했다.
- 조각 계획 회귀 테스트 **6개 통과**. 강제 재녹화의 기존 파일 검사 0회, 정상 재사용 검증 유지, 손상 후보 재사용 차단, 기존 형식 변환 유지, 월/일 경계, 승인 토큰 변경에 따른 재승인, 웹 데이터 구축 시나리오를 확인했다. 후보 목록은 테스트용이며 실제 DuckDB·MT5를 실행하지 않았다.
- 기존 백테스트 연결·화면 계약 테스트 **5개 통과**. 웹/기존 UI 시나리오 일치, 녹화 승인·안전 정지 연결, 화면 컨트롤과 강제 재녹화 입력 전달을 확인했다.
- 변경 JavaScript와 새 JavaScript 테스트의 구문 검사 통과. 변경 Python과 새 Python 테스트의 AST 구문 검사 통과.
- 계획이 이미 준비된 격리된 화면 시험에서 실행 응답 후 표시까지 **0.4ms**였다. 실제 계획 생성 시간이나 네트워크 시간을 포함한 성능 수치가 아니다. 계획이 아직 준비되지 않았을 때는 응답 완료 후 300ms마다 확인한다.

합계 **27개 관련 시험 통과**. 실제 MT5 강제 재녹화와 장기 백테스트의 종단 실행은 하지 않았다. 진단 Python에는 DuckDB가 없으므로 전체 DB 구축/교체 시험을 실행했다고 주장하지 않는다. 이번 수정은 그 실행 절차를 바꾸지 않았고, 강제 재녹화 계획의 입력별 의도와 UI 상태 흐름을 검증했다.
