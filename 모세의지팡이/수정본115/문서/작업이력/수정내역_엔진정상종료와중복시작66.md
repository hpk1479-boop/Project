# 수정본66 후속 — 엔진 정상 종료와 중복 시작 제어

사용자 요청대로 수정본66에서 우선순위 3·4번을 함께 처리했다. 1·2번의 설정 손상 차단·백테스트 시작 직전 취소를 유지했다. 원본과 다른 수정본은 수정하지 않았다.

## 동작

### 정상 종료와 저장 확인

- 웹의 전체 종료·전용 창 닫기·브라우저 서버 종료·Part1 독립 stop은 같은 Part1 공개 제어 API를 사용한다.
- 대상 엔진에 먼저 정상 종료 요청을 보내고 기존 상태와 `signal_receipts.json` 저장 완료 및 프로세스 종료를 확인한다.
- 모든 대상에 요청한 뒤 하나의 45초 제한시간으로 기다린다. 제한시간 후에도 살아 있는 대상만 기존 `taskkill /T /F`로 종료한다.
- 저장 실패·미확인·종료 실패를 성공으로 숨기지 않는다. 종료 실패이면 웹 오류를 반환하고 전용 창 닫기를 보류한다. 강제 종료의 저장 미보장 경고는 웹 메시지와 전용 창 안내에 표시한다. 브라우저 실행기의 경고는 stderr가 있을 때 기록한다.
- 입출력 worker는 공통 30초 한도로 기다린다. 살아 있는 worker가 남으면 변경 중인 기록을 저장 완료로 표시하지 않는다.

엔진의 기존 `export_engine_state`/`write_event_state_files`와 전송 기록 저장을 그대로 사용한다. 새 정상 종료 신호가 기존 finally를 통과하도록 시작·실행·정리 흐름을 묶었다.

### 실행 중인 엔진 확인과 재시작

- 다른 수정본을 포함해 공식 경로로 실행 중인 Part1 `event_host.py`를 조회한다. 단순 문자열 포함 대신 실제 Python의 실행 스크립트 인자를 확인하므로 다른 스크립트·`-c`·`-m`의 참고 인자를 엔진으로 오인하지 않는다.
- 조회 실패를 엔진 0개로 처리하지 않고 실행·종료를 중단한다.
- 엔진이 있으면 웹에서 **이전에 작동중인 엔진을 종료하고 다시 시작하시겠습니까?**와 수정본 이름·PID를 표시한다. 취소하면 기존 엔진을 유지한다.
- 확인한 PID와 생성 시각을 재시작 요청에 함께 보낸다. 공통 잠금 안에서 목록을 다시 확인하고, 달라졌으면 새 확인을 요구한다. 확인 후 나타난 다른 엔진을 임의로 종료하지 않는다.
- Windows 공통 named mutex로 여러 웹 서버·CLI·수정본의 시작과 종료를 직렬화한다. PID와 생성 시각을 확인하고 원래 프로세스 handle을 유지해 PID 재사용 때 다른 프로세스를 종료하지 않는다.
- 새 엔진은 실제 파이프를 확보하고 전체 서비스 시작이 완료됐으며 해당 Popen 프로세스가 살아 있어야 준비 완료다. 시작 실패·준비 시간초과는 실패로 반환하고 이 요청이 만든 프로세스를 정리한다. 기본 준비 제한시간은 30초다.
- 파이프가 이미 점유됐으면 첫 생성 실패를 기록하고 엔진을 종료한다. 0.2초마다 같은 생성 오류를 무한 재시도하지 않는다. EA 재연결 동안 같은 파이프 handle을 유지해 소유권 공백을 없앴다.
- 엔진 준비 완료와 MT5 연결 여부를 구분해 **감시 엔진 준비 완료 · MT5 연결 대기/연결됨**으로 표시한다. 이후 진단 상태도 MT5 연결 여부를 별도로 표시한다.

웹에서 실행한 엔진에만 UI 서버의 PID·생성 시각을 전달한다. 서버가 비정상 종료되거나 PID가 재사용되면 엔진이 이를 감지해 기존 상태를 저장하고 종료한다. CLI 실행은 부모 감시 환경 값을 제거해 웹 없이 독립 운용한다.

## 공개 API와 저장 형식

`Part1/engine_processes.py`:

- `list_live_engines`, `find_engine_instances`, `current_process_identity`
- `lifecycle_lock`, `confirm_restart`, `wait_until_ready`
- `stop_engine_instances`, `stop_all_engines`
- `parse_engine_arguments`, `is_engine_command`, `hold_process_identity`

`Part1/live_control.py`의 `start_live(restart=False, expected_engines=None, ui_owner=None)`, `stop_live(all_copies=False)`, `list_live_engines()`를 공개한다. 기존 `(ok, message)` 반환과 SPECIAL 선택·OZ·시간 전달을 유지하며 `LiveStartResult`에는 경고를 부가한다. `EngineConflictError.engines`로 재시작 확인 목록을 전달한다. `python -m Part1 start/status/stop`은 유지한다.

`Part1/program/event_lifecycle.py`의 `HostLifecycle`, `read_status`, `request_stop`은 상태·종료 요청 I/O만 맡는다. `Part1/runtime/engines/<pid>.json`, `<pid>.stop.json`에 PID·생성 시각·실행 토큰·시작/준비/종료 상태·파이프 상태·저장 완료·오류를 원자적으로 기록한다. 기록에 설치 절대 경로를 넣지 않는다. 생성 시각과 실행 토큰이 맞지 않는 과거 파일은 읽기·종료 요청 대상에서 제외한다.

Part3는 Part1 공개 API를 호출하는 얇은 연결 코드로 정리했다. `Part3/lab/live_processes.py`의 기존 진단용 함수 이름도 내부에서 Part1 공개 연결 함수를 사용한다.

웹 API:

- `GET /api/mo/live/engines`: 전체 수정본 엔진의 PID·생성 시각·수정본 이름·현재 수정본 여부·상태·MT5 연결·정상 종료 지원 여부. 내부 절대 경로는 응답하지 않는다.
- `POST /api/mo/live/start`: 기존 빈 요청 유지. 충돌 시 `ok:false`, `confirmation_required:true`, `engines`를 반환한다. 확인한 요청은 `restart:true`, `expected_engines`를 전달한다.
- `POST /api/mo/live/stop`: 모든 수정본의 라이브 엔진 정상 종료·시간초과 처리 결과와 `saved_pids`, `forced_pids`, `warnings`를 전달한다.

## 변경 경계

Part1에서는 `live_control.py`, 새 `engine_processes.py`, `program/event_host.py`, `program/event_pipe_host.py`, 새 `program/event_lifecycle.py`의 실행·통신·종료 I/O만 변경했다. Part3 변경은 `lab/live_processes.py`, `lab/unified_live.py`, `lab/server.py`, `lab/desktop_window.py`, `run.py`, `web/unified.js`, `web/index.html`에 한정한다. 비교와 보호 범위 증거는 `검증결과/엔진제어66/change_scope.json`에 있다.

공식 실행기는 모두 절대 스크립트 경로를 사용한다. 사용자가 임의의 상대 스크립트 경로로 직접 실행한 프로세스는 현재 조회 규칙에 포함되지 않으며, 같은 파이프 점유 때 새 엔진이 준비 실패로 차단된다. 이전 수정본 엔진에는 새 정상 종료 인터페이스나 부모 감시를 소급 적용하지 않으므로 그 엔진은 제한시간 강제 종료/저장 미확인 안내를 사용한다.

이번 범위는 3·4번이다. 동시 설정 저장·창고별 작업 제어, 생성 전략 작업 경로 통합, 실행 이력 복구, AI 대화 기록 제한은 다음 목록으로 남아 있다.
