# 수정본67 — 공통 백테스트 작업 관리

수정본66을 복사해 작업했다. 이전 검증결과·캐시는 복사하지 않았다. Part1, Part2, 기존 생성 전략, 전략 canonical schema/Recipe v2/validator/execution_plan/compiler는 수정 대상이 아니다.

## 실행 흐름

일반 SPECIAL/WATCH·데이터 구축, 생성 Test 전략, AI 백테스트 명령은 모두 `lab.backtest_jobs`가 발급한 32자리 작업 ID를 사용한다. 작업 관리자는 실행·중지·계획 승인·상태·진행·최근 목록·재연결을 담당한다. Part2의 기존 proposal/execute 또는 CLI가 계산·캡처·재생·체결·통계를 담당한다.

창고 `runs/<작업 ID>/job.json`에 작업 상태를 저장한다. 별도 supervisor가 기존 Part2 프로세스의 출력과 ProgressView 투영을 저장하므로 웹 서버의 메모리가 초기화되어도 작업을 조회할 수 있다. 재연결은 기존 프로세스와 결과 파일 조회이며 계산을 재개하거나 중복 실행하지 않는다. 프로세스의 PID와 시작 시간을 함께 확인한다. 관리 프로세스가 사라졌는데 Part2가 남아 있으면 연결 중단 상태로 알리고 기존 정지 파일을 사용할 수 있다.

일반·생성 전략 모두 계획 확인부터 시작한다. 새 녹화가 필요하면 Part2가 만든 계획과 승인 토큰을 사용한다. 계획이 변경되면 다시 확인한다. 계획 조회만 요청하면 실행하지 않는다. 생성 전략은 해시로 선택 파일 변경을 확인하고 기존 공식 register_strategy_loader와 Windows spawn 초기화를 유지한다.

## API와 화면

기존 `/api/mo/backtest/start`, `confirm`, `stop`, `status`, `log`, `result`, `trades`, `download`를 유지했다. `recent` 조회와 `reconnect` 요청을 추가했다. 기존 `/api/backtest`, `/api/job`도 공통 관리자에 연결한다. 생성 전략은 공통 진행·결과 대시보드와 원본 다운로드를 사용한다. 생성 전략 화면의 창고는 현재 공통 연결 설정을 사용하며 CLI에서는 명시한 창고를 작업 조회에도 전달할 수 있다.

`/api/ai/backtest/chat`, `confirm`, `cancel`, `reset`은 별도 백테스트 명령 상태를 관리한다. START/STOP은 사용자 확인 후 한 번만 실행한다. STATUS/RECENT/RECONNECT는 조회한다. 종목·기간·전략이 부족하면 질문하며 후속 수정은 직전 명령을 참고한다. 설정 변경·취소·오래된 확인·이중 클릭은 차단한다. 종료일은 UTC 기준 미포함 경계로 표시한다. 백테스트 명령은 현재 설정한 Ollama 모델을 사용하며 모델 기본값을 추가하지 않았다.

전략 생성의 canonical intent와 백테스트 작업 상태는 서로 독립적이다. 이번 화면에는 백테스트 메뉴의 명령 입력란을 연결했다. 내부 상태 분리는 같은 대화창을 사용하는 경우에도 유지할 수 있으며 별도 화면 자체는 엔진 계약의 필수 조건이 아니다.

## 검증

공식 목록에 작업 관리자·생성 전략 adapter·AI 명령·HTTP/웹 동작·독립 실행 프로세스 회귀 검사를 추가한다. 이전 private worker를 고정하던 검사는 공통 supervisor의 동일한 승인·정지·로그 의미 검사로 옮긴다. 제외를 추가하거나 실패를 강제로 통과시키지 않는다.

새 증거는 이 수정본의 `검증결과`에만 보관한다. 공식 검사 집계는 `CURRENT_VERIFY.md` 및 `검증결과/current_verify/latest.json`에 기록한다. 합성 UI 화면과 390px 너비 확인은 `검증결과/화면67`에 보관한다. 테스트의 실제 subprocess는 임시 합성 CLI만 사용하며 사용자 엔진·MT5·Ollama·실제 시장 이력 백테스트를 실행하지 않는다.
