# 수정본60 Part3 공통 전략 언어 확장

수정본59에서 수정본60을 만들었다. 이전 검증결과와 캐시는 복사하지 않았다. 이번 변경은 Part3의 Recipe v2 공통 언어에만 적용했다. Part1·Part2와 기존 테스트 파일은 변경하지 않았다. 교육 문서는 의미 확인에만 사용했으며 번호·원문에 따른 운영 코드 분기는 추가하지 않았다.

## 추가한 기능

| 기능 | 공통 표현과 동작 |
|---|---|
| 시간 제한 없는 순차 연쇄 | `order_mode=SEQUENTIAL`, `within_sec` 생략/null. A 이후 B를 기다리며 시간 경과만으로 후보를 만료하지 않는다. |
| 기존 시간 제한 | 양의 정수 `within_sec`를 지정하면 기존 제한을 유지한다. 제한 시각까지는 허용하고 그 이후에는 만료한다. |
| 가격-MA 교차 | `MA_PRICE_CROSS`, `ma_family`, 양의 정수 `slow_period`, `relation=BREAK_UP/BREAK_DOWN/BOTH`. |
| 가격-MA 터치 | `MA_PRICE_TOUCH`, `ma_family`, 양의 정수 `slow_period`. 선행 사건 뒤의 다음 단계로도 사용할 수 있다. |

MA 계열은 SMA/WMA/EMA/HMA다. 기간에 별도 상한이나 지원 기간 목록을 두지 않았다. MA 두 개의 교차인 기존 `MA_CROSS`와 가격-MA 교차를 구분한다.

교차는 기존 `MACondition`의 GOLDEN/DEAD 판정을 사용한다. 상향은 이전 가격 ≤ 이전 MA, 현재 가격 > 현재 MA이며 하향은 반대다. 터치는 판정 봉의 저가 ≤ MA ≤ 고가다. MA 값은 기존 `WatchMAStore`와 `indicator_facts`를 이용한다. SMA/WMA/HMA의 시가 입력과 EMA의 종가 입력 등 기존 계산 계약을 유지했고 계산식을 복제하지 않았다.

두 새 MA 사건은 봉 기준 생략/UNSPECIFIED/CLOSED이면 확정봉, FORMING이면 진행봉을 사용한다. 초기 관찰에서 이미 발생한 사건, 동일 확정봉의 반복 관찰, 계산 준비 전의 값으로는 알리지 않는다. 진행봉은 새 충족 사건을 감지하며 터치는 다음 봉에서도 다시 발생할 수 있다. EMA1은 종가 자체이므로 가격-EMA1 교차가 생기지 않는 기존 계산 계약도 그대로 유지한다.

## 순서 판정의 영향

단순히 첫 사건보다 뒤인지뿐 아니라 **직전 소비한 사건보다 뒤인지** 확인한다. 같은 시각의 교차와 터치를 한 번에 소비해 `A 이후 B`를 완성하지 않는다. 세 단계에서도 B보다 오래된 C를 소비하지 않는다. 이는 시간 제한 유무와 관계없이 적용되는 순서 의미의 보완이다. 기존 구현에서 동일 시각의 서로 다른 두 사건으로 연쇄가 완성되던 입력은 이제 다음 사건을 기다린다. `이후` 관계에는 새 판정이 맞다. 기존 시간 제한 길이·만료 경계와 최종 감시 시간 규칙은 유지했다.

`final_window_sec`는 순차 연쇄 완성 시점부터 계산한다. 선행 사건 후 오래 기다렸다고 최종 감시 시간을 미리 소모하지 않는다. 취소하면 부분 연쇄와 활성 감시를 초기화한다. 대화 해석만으로 Recipe 적용이나 파일 생성을 수행하지 않는 기존 사용자 확인 흐름도 유지했다.

## 정식 경로

canonical schema → validate_intent → Recipe v2 → validator → execution_plan → compiler → Python 생성 → register(manager).

schema_version은 2다. 두 새 사건은 schema의 정식 kind와 매개변수로 추가했으며 실행 계획과 신뢰된 Python 템플릿으로 내려간다. AI 조회용 어휘·계약 설명에도 두 사건과 제한 없는 SEQUENTIAL을 추가했다. 실모델 프롬프트 실험이나 원문 비교 재판정은 하지 않았다.

웹 해석 화면에는 “1일봉 가격이 SMA20 상향 또는 하향 교차”, “1분봉 가격이 EMA200 터치”, “선행 사건 이후 대기 시간 제한 없음”처럼 표시한다. 원본 canonical JSON은 기존 상세 보기에 보존한다.

## 검증 결과

- Part3 Python 테스트 **169개 통과**, 실패·오류·건너뜀 0개. 기존 145개를 유지하고 새 공통 기능 테스트 24개를 추가했다.
- 웹 UI 테스트 **70개 통과**. 기존 66개와 새 공통 표시 4개다.
- 네 MA 계열, 기간 1/21/37/503/10007, 세 교차 관계를 schema/validator에서 확인했다. 실행에서는 네 계열의 가변 기간 21/37과 기간 1 계약, 준비되지 않은 긴 기간, 확정봉/진행봉, 같음 경계, 반복 관찰, 터치/미터치를 시험했다.
- 실제 생성 파일을 기존 `Part3/backtest.py`의 loader로 읽어 등록하는 경로도 확인했다.
- 기존 Windows 프로세스 종료 시험은 샌드박스의 프로세스 조회 제한으로 처음 실패했다. 정상 권한 환경에서 시험이 만든 임시 프로세스만 대상으로 다시 실행해 통과했다. 해당 제품 코드는 변경하지 않았다.

| 교육 사례 | 확인한 결과 |
|---|---|
| #054 | 1분 EMA50/200 상향 교차 → 5분 상승 FVG 신규 발생을 제한 없이 기다림 → 그때부터 1·2·3분 일반 올존을 1시간 감시. 실제 FVG 처리기로 연쇄를 완성했고, 정상 입력에서 1분 최종 올존 알림 1회, 새 하락 FVG 입력에서 취소를 확인했다. |
| #059 | NAS100 일봉 SMA20 가격 상향·하향 교차를 각각 1회 알림. 양방향 분기로 같은 사건을 중복 발송하지 않았다. |
| #060 | 1분 EMA50/200 상향 교차 뒤 후속 EMA200 터치에 1회 알림. 교차와 같은 봉의 터치나 초기 관찰의 과거 터치로는 완료하지 않았다. |

세 사례에 동일한 STAFF wire 입력을 사용했다. LIVE는 현재 Part1 이벤트 엔진의 실제 바이트 수신 경로, 재생은 현재 Part2 `CaptureInputs`와 백테스트 이벤트 엔진을 사용했다. 알림 내용·시각·방향·횟수와 최종 연쇄 상태가 같았다. #054는 최종 올존 알림과 이후 취소까지 포함했다. 번호와 무관한 WMA43 가격 하향 교차 → HMA71 터치 등의 신규 전략도 같은 schema로 생성했다.

이 검증은 합성 OHLC 및 지표 입력으로 수행했다. 실제 Qwen 자연어 해석, MT5 실데이터 수집, 전체 역사 구간 백테스트, 텔레그램 전송을 실행한 결과는 아니다.

## 변경 파일과 증거

제품·문서 변경은 다음 8개다.

- `Part3/lab/ai/schema.py`: 정식 kind와 검증, SEQUENTIAL 시간 제한 선택화.
- `Part3/lab/ai_compiler.py`: 사건 실행 계획과 교차 방향 연결.
- `Part3/lab/intent_port.py`: 기존 MA 계층에 연결한 교차·터치 관찰.
- `Part3/lab/intent_runtime.py`: 직전 사건 시각과 순차 상태 보존.
- `Part3/lab/ai/agent.py`, `Part3/lab/ai/tools.py`: 공통 출력 계약과 조회 어휘.
- `Part3/ai_context/STRATEGY_LANGUAGE.md`: 언어 계약 설명.
- `Part3/web/ai_display.js`: 한국어 표시.

새 테스트는 `Part3/tests/test_common_recipe60.py`, `Part3/tests/test_common_recipe_ui60.cjs`다. Part1 286개, Part2 1,729개 파일의 내용과 기존 테스트 파일은 모두 그대로다. 파일 보존 비교는 수정 범위 확인용이며 전략 로직의 정답 기준으로 사용하지 않았다.

증거는 [검증 요약](../../검증결과/공통전략언어60/verification.json), [전체 Python 테스트](../../검증결과/공통전략언어60/python_tests.txt), [수정 범위](../../검증결과/공통전략언어60/change_scope.json), [새 UI 검사](../../검증결과/공통전략언어60/ui_tests.json)에 있다. `검증결과/공통전략언어60/examples/`에는 사례별 intent, Recipe, execution_plan 및 정식 생성 Python을 보존했다. 이전 번호가 들어간 UI 증거 폴더도 수정본60에서 기존 테스트를 새로 실행해 만든 파일이다.

재실행은 프로젝트가 사용하는 Python으로 `검증결과/공통전략언어60/run_verification.py`를 실행한다. Windows 종료 시험을 포함할 때는 정상 프로세스 조회 권한 환경에서 `--windows-smoke`를 사용한다. UI 재실행은 기존 CJS 테스트와 `Part3/tests/test_common_recipe_ui60.cjs`에 사용 환경의 Playwright 경로를 전달한다.
