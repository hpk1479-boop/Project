## 1. Part3 명령 백테스트

`.\python.exe Part3\cli.py backtest Test_SPECIAL005.py --start 2024-01-01 --end 2026-01-01 --action run --available-only ...`

| 옵션 | 뜻 | 생략하면 |
|---|---|---|
| `--result-mode` (새) | `ALERT_ONLY` / `VIRTUAL_ENTRY` | `ALERT_ONLY` |
| `--virtual-entry 파일` (새) | 가상진입 정책(공통 가상진입 계약, `tested_settings.json`의 `virtual_entry`와 같은 모양) | 레시피 값 |
| `--base-frame` (새) | 기준 프레임: 레시피를 그 시간봉으로 쓴 값으로 전략·진입을 함께 옮김 | 레시피 시간봉 |
| `--spread-points` (새) | 스프레드(포인트) | 0 |
| `--available-only` (새) | 있는 데이터만, 녹화 안 함 | 꺼짐 |
| `--warehouse` | 창고(상대 경로는 프로젝트 기준) | 연결 설정의 창고(전에는 필수) |
| `--cores` | 작업 프로세스 수 | 화면과 같은 값(전에는 1) |
| `--symbol`, `--mode`, `--action`, `--yes` | 그대로 | 그대로 |

- 경로는 화면(AI 명령)의 생성 전략 실행과 같다: `cli.py` → `integration.backtest` → `backtest_adapters.prepare_generated` → Part2 `settings.scenario` 검사 → 공통 작업(`backtest_jobs`).
- 기준 프레임은 화면과 같은 함수(`virtual_defaults.recipe_on_base`)로 레시피 값을 다시 채운다(`backtest_adapters.base_frame_policy`).
- `--virtual-entry`와 `--base-frame`을 함께 주거나, `VIRTUAL_ENTRY` 없이 주면 작업을 만들기 전에 거절한다.

기존과 달라진 동작:

| 항목 | 전 | 후 | 판단 |
|---|---|---|---|
| `--cores` 생략 | 1개 | 화면과 같음(설정값 → 이 PC 측정값 → 물리 코어) | 화면과 같은 경로가 요청이다. 1개로는 대량 백테스트가 느리다. 실시간 감시 중에는 167의 자동 낮은 우선순위가 그대로 적용된다 |
| `--warehouse` | 필수 | 생략하면 연결 설정의 창고 | 화면과 같다 |
| 상대 창고 경로 | 실행은 프로젝트 기준, 상태 조회는 현재 폴더 기준(다른 창고를 볼 수 있었다) | 둘 다 프로젝트 기준(`job` 명령도) | 실행과 조회는 같은 창고여야 맞다. 창고 위치 결정은 `integration.warehouse` 하나로 모았다 |
| 끝난 뒤 출력 | 로그만 | 끝나면 `결과 폴더(창고 기준): runs/<ID>`, 계획만이면 계획, 실패면 메시지 | 보고용 |

엔진(Part1·Part2) 코드는 바꾸지 않았다.

## 2. 배포본 AI 규칙

- 원본: `통합설치/releasekit/agent_rules.md`
- 빌더(`builder.prepare_data`)가 설치 폴더 루트에 `AGENTS.md`·`CLAUDE.md`로 같은 내용을 넣는다.
- 업데이트 때 새 파일로 바뀐다(설치기 사용자 보존 목록에 없음).
- 개발본 루트 `CLAUDE.md`·`AGENTS.md`와 `Part3/AGENTS.md`는 배포되지 않는다(시험으로 확인).

| 장 | 내용 |
|---|---|
| 1. 하지 않는 일 | 프로그램·`스페셜/기본`·데이터창고·실시간 설정을 고치지 않음, 전략 파일 손으로 쓰지 않음, 녹화 승인(`--yes`·`job confirm`) 금지, `cli.py connect` 금지, 삭제 금지 |
| 2. 명령 실행 | 설치 폴더의 `python.exe`, 한 번에 하나, UTC 날짜·끝 날짜 미포함 |
| 3. 전략 만들기 | 초안 → `preview`(검사) → `generate` → `list`, 번호 001~999 |

| 5. 기존 전략 | Part2 명령(`Part2`에서 `..\python.exe -m event_backtest run --scenario … --warehouse …`), 시나리오 칸 |

| 7. 남길 전략 | 사용자가 말한 것만 `스페셜/내 전략/SPECIAL1xx.py`로 복사 |
| 8. 보고 | 한국어, 상대 경로, 실행 ID·설정 함께 |

## 6. 올라마 종료 메시지 정리

- 전체 시험 끝에 나오던 "Ollama AI 모델 종료를 확인하지 못했습니다"는 프로그램이 낸 것이 아니라 시험 하나가 남긴 것이다.
  - `Part3/tests/test_ollama_models58.py`의 모의 올라마 대화 시험이 공용 런타임에 "올린 모델(qwen3:8b)" 기록을 남겼다.
  - 시험이 끝나 모의 서버가 닫힌 뒤, 파이썬 종료 정리(`common_ai/model_runtime.py`의 `atexit`)가 그 모델을 실제 올라마 주소에서 내리려다 실패했다(이 PC에는 올라마가 없다).
- 실제 프로그램은 이 실행이 올라마 모델을 올렸을 때만 올라마에 연결한다(149). 제미나이를 고른 상태에서는 이 메시지가 나오지 않는다.
- 고친 것: 그 시험만 150의 다른 두 시험처럼 시험 전용 런타임(빈 잠금)을 쓴다. 공용 런타임이 바뀌지 않았는지도 시험 안에서 확인한다. 프로그램 코드는 바꾸지 않았다.
- 후보 시험 15개를 하나씩 따로 돌려 이 파일만 메시지를 남기는 것을 확인했다.
