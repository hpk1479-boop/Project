# 수정본172 — 봉 시각을 실제 한국시간으로 통일

수정본171을 복사해 만들었고, 171의 검증결과 폴더는 복사하지 않았다. 배포는 하지 않았다.

사용자 지시: "이게 동일해야지", "한국시간으로 고정해", "utc는 설정에서 변경할수 있게", "서버시간이라는게 다 다를수 있어 브로커 마다", "알림도 왓치도 한국시간 기준이 맞아", "영향 받는건 중요하지 않아 여태 틀렸던거니까".

## 무엇이 틀렸었나

- MT5 봉 시각과 녹화에 찍힌 시각은 **브로커 서버 시각**이다. 지금 브로커는 UTC+2이고, 미국 서머타임 때는 UTC+3이다(뉴욕 시각 + 7시간).
- 코드는 봉 시각을 UTC로 보고, 9시간을 더해 한국시간으로 썼다.
- 엔진이 판단하는 "지금"은 라이브와 백테스트가 서로 달랐다.
  - 라이브: EA의 TimeGMT(진짜 UTC)
  - 백테스트: 녹화의 서버 시각

| 판정 | 171 라이브 | 171 백테스트 |
|---|---|---|
| 거래시간 필터·세션 시작 조건 | 맞음 | 2~3시간 늦은 시각으로 판정 |
| SWEEP "이전 세션 고가·저가" | 세션을 2~3시간 이르게 잡음 | 라이브와 같이 틀림 |
| 등록·조건 시각과 봉 시각 비교 (`strategy_recipe/port.py`의 `at`/`now`, 올존 "등록 뒤 첫 봉") | 2~3시간 어긋남 | 맞음 |
| 결과 화면 시간대·알림 시각 | — | 2~3시간 늦게 표시 |

## 바꾼 것

1. **`Part1/program/server_time.py` (새 파일)**
   - 브로커 서버 시각을 실제 시각으로 바꾸는 함수 하나이고, 라이브와 백테스트가 모두 이것을 쓴다.
   - 설정 `SERVER_UTC_OFFSET`: 서머타임이 아닐 때의 UTC 시차, 기본 2.
   - 설정 `SERVER_DST`: `US` / `EU` / `NONE`, 기본 `US`. 서머타임은 날짜마다 정확히 계산한다.
   - 한국시간은 UTC+9로 고정했다.
2. **입구에서 한 번 변환**
   - STAFF 어댑터(`event_engine/staff_adapter.py`, 라이브·재생 공통)가 엔진에 넘기는 봉 시각을 실제 시각으로 바꾼다. STAFF 자체는 받은 시각을 그대로 보관한다.
   - 재생 입구(`Part2/event_backtest/bridge.py`)는 녹화의 관측 시각을 실제 시각으로 바꿔 엔진의 "지금"으로 넘긴다.
   - 가상진입의 녹화 읽기(`virtual_source.py`)도 같은 함수로 바꾼다.
3. **기간 경계**
   - 백테스트 기간 날짜는 지금처럼 녹화(서버) 날짜를 가리킨다.
   - 엔진 시각과 비교하는 곳은 경계를 같은 함수로 바꿔 비교한다: 알림 기록 범위, 준비 구간, 진행률, 블록 이어 붙이기, 남은 구간.
4. **거래일 경계는 지금과 같게**
   - 주간 고가·저가(PWH/PWL), 일봉·4·8시간 레벨 ID, 기간별 VWAP 기간, 기록 범위 계산은 서버 날짜(뉴욕 17시 마감)로 계산한다.
   - 그래서 결과가 이전과 같다.
5. **녹화마다 브로커 시간**
   - 새로 만드는 녹화의 목록 항목에 `server_time`(그때의 설정)을 적는다.
   - 172 이전 녹화는 기본 브로커(UTC+2, 미국 서머타임)로 본다. 데이터창고와 EA는 그대로 쓴다.
   - 한 실행 안에 브로커 시간이 다른 녹화가 섞이면 멈춘다.
6. **라이브 확인**
   - EA가 보낸 실제 UTC와 진행 중인 1분봉의 서버 시각 차이로 실제 시차를 읽는다.
   - 30번 연속 설정과 다르면 진단 기록에 경고한다: "브로커 서버 시각이 설정과 다릅니다".
7. **라이브 저장 상태**
   - 172부터 저장하는 상태에는 `event_time_base.json` 표시가 붙는다.
   - 표시가 없는 옛 상태는 **라이브를 시작할 때 한 번만** `event_state/서버시각_이전상태_<날짜>/`로 옮긴다. 지우지 않는다.
   - 보낸 알림 기록(`signal_receipts.json`)은 그대로 둬서 같은 알림이 다시 나가지 않게 한다.
   - 시험이나 다른 도구가 엔진을 만들 때는 옮기지 않는다.
8. **화면**
   - 설정 → 상세 설정 → MT5 연결에 두 칸을 추가했다.
     - "브로커 서버 시간 (서머타임 아닐 때)": UTC-12 ~ UTC+14
     - "브로커 서머타임": 미국 / 유럽 / 없음
   - 기존 `config.txt`에 이 줄이 없으면 기본값을 보여 주고, 저장할 때 줄을 추가한다.
   - 백테스트 목록의 "당시 설정"에 그 실행의 브로커 서버 시간을 보여 준다.
9. **매뉴얼 원본**(`매뉴얼/편집원본/제작.py`)의 상세 설정 표에 두 줄을 추가했다. PDF는 다시 만들지 못했다(아래 "남은 것" 참고).

바꾸지 않은 것: EA, 녹화 파일, 데이터창고, 전략 조건, 세션 설정 값(한국시간), 한국시간 고정.

## 확인

### 지금 녹화가 "UTC+2, 미국 서머타임" 규칙인가

데이터창고 녹화에서 화~금요일의 첫 묶음 서버 시각을 셌다. 뉴욕 18시 재개장 시각이다.

| 종목 | 미국·유럽 모두 여름 | 미국만 여름(엇갈린 주) | 겨울 |
|---|---|---|---|
| 나스닥 | 835일 모두 01:00 | 95일 모두 01:00 | 485일 모두 01:00 |
| 금 | 832일 모두 01:00 | 95일 모두 01:00 | 467일 모두 01:00 |

유럽 기준 브로커라면 엇갈린 주에는 00:00이 나와야 한다. 따라서 미국 기준(뉴욕+7)이 맞다. 2026-10-06 라이브 기록에서도 봉 시각(11:25)이 실제 UTC 알림 시각(08:26)보다 3시간 앞서 있었다.

### 회귀 시험 `tests/test_server_time172.py` (16개)

- **변환 규칙**: 기본 브로커, 미국·유럽 서머타임 경계 주의 월요일 개장, 유럽·고정 시차 브로커, 배열·단일 값 일치, 설정·녹화 기록 읽기와 잘못된 값 거부.
- **라이브 ≡ 재생**: 같은 순간의 봉을 두 경로로 넣었을 때 엔진이 받는 "지금"과 봉 시각이 같다. STAFF는 받은 시각을 그대로 둔다. 시계 없이 만든 어댑터는 시각을 바꾸지 않는다.
- **판정**
  - 거래시간 필터: 서버 00:30(여름)은 한국 06:30으로 판정한다. "0600-0700"은 통과하고 "0900-1000"은 통과하지 않는다.
  - 이전 세션 고가·저가: 한국시간 16:00·21:00에 바뀐다.
  - 주간 고가·저가, VWAP 기간, 기록 범위: 바꾸기 전과 같은 값이다.
- **라이브 확인**: 설정과 같은 시차는 조용하다. 다른 시차가 30번 이어지면 한 번만 경고한다. 장이 닫혀 오래된 봉은 읽지 않는다.
- **가상진입·블록 경계**: 녹화를 실제 시각으로 읽고, 이어 붙이기 경계도 변환한다.
- **옛 라이브 상태**: 한 번만 옮기고, 보낸 알림 기록은 남긴다. 라이브 시작에서만 옮긴다.
- **설정 화면**: 값을 확인하고, 기본값을 보여 주고, 저장할 때 줄을 추가한다.

## 남은 것·알아 둘 것

- **배포 후 라이브를 처음 켤 때** 옛 라이브 상태가 `event_state/서버시각_이전상태_<날짜>/`로 옮겨진다.
  - 텔레그램으로 등록한 개인 감시는 다시 등록해야 한다. 지금 배포본에 있는 것은 다음 두 명령이다(하락추세는 두 번 등록돼 있었음).
    - "골드 모든 프레임이 상승추세일때 1분 브레이커 올존 알려줘"
    - "골드 모든 프레임이 하락추세일때 1분 브레이커 올존 알려줘"
  - 진행 중이던 전략 상태와 올존 후보는 새로 설치했을 때처럼 들어오는 이력으로 다시 만들어진다.
- **172 이전 실행 결과**: 데이터창고 runs에 있는 실행 결과의 시각은 서버 시각 기준 그대로다(결과 화면에서 2~3시간 늦게 보임). 171의 스페셜1·8 분석 보고서는 이미 실제 한국시간으로 바꿔 계산했다.
- **매뉴얼 PDF**: 다시 만들려면 reportlab이 있는 Python이 필요하다. 이 PC의 Python에는 없어서 원본만 고쳤다. 설치하려면 패키지를 내려받아야 하므로 허락이 필요하다.
- **백테스트 목록의 기간 표시** "UTC (종료일 미포함)"는 바꾸지 않았다. 기간 날짜는 녹화(서버) 날짜를 뜻한다.
