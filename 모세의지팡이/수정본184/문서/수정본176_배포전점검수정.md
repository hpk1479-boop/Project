# 수정본176 배포 전 점검 수정

수정본175 독립 점검에서 확인한 6건을 수정했다. 사용자의 요청은 “이걸 문서로 남기고 다음 수정본에서 작업해줘”였다. 점검 보고서는 `문서/수정본175_독립배포전점검.md`에 별도로 보관했다.

수정본176은 수정본175를 복사하여 만들었으며 이전 검증결과, 시험 캐시, 임시 빌드 폴더와 가상환경은 복사하지 않았다. 새 검증결과에는 이번 수정본에서 만든 자료만 둔다. 원본175, 실제 설치본과 실제 데이터창고는 수정하지 않는다. EXE 빌드, 설치, 배포와 업데이트는 작업 범위에 포함하지 않는다.

## 세부 동작

### 설치형 스페셜 변경과 알림 재사용

`Part2/event_backtest/runner.py`의 코드 식별값에 공용 `read_special_entries()`가 반환하는 설치형 전략 정의를 포함했다. JSON 레시피와 Python 파일의 literal `PART3_RECIPE`를 같은 실제 로더 규칙으로 읽으며, 사용자 Python 파일의 코드를 실행하지 않는다.

같은 번호 전략의 의미를 바꾸면 새로 재생하고, 의미가 그대로면 기존 알림을 재사용한다. 해시에 프로젝트 절대 위치나 파일 수정 시각을 넣지 않으므로 프로젝트와 창고를 함께 이동해도 같은 입력의 재사용 키가 유지된다.

### 외부유동성 터치의 판정 시각

`touch_time`과 `event_time`은 기존처럼 터치한 확정봉을 식별한다. SWEEP Processor가 새 터치를 처음 판정한 입력의 실제 시각을 별도 `touch_confirmed_at`으로 저장한다. 공용 포트는 사건 모드에서 이 확인 시각으로 초 기간과 사건 순서를 계산한다. 봉 수 기간은 실제 터치한 확정봉의 끝을 함께 전달하여 해당 봉을 기준으로 센다.

관측이 5.5초 늦거나 주말 뒤 처음 판정되면 초 기간은 그 판정 시각부터 시작한다. 같은 사건을 반복 전달하거나 라이브를 다시 시작해도 확인 시각을 새로 만들지 않는다. 기존 시작 복원 경로인 `strategy_SWEEP.py`도 이 메타데이터를 보존한다.

확인 시각이 없는 옛 Fact는 제공된 봉 이력에서 해당 봉 다음의 경계를 찾을 수 있을 때 그 값을 사용한다. 이력 밖의 옛 사건은 기존 시각을 유지하며 현재 시각에 새로 발생한 사건으로 바꾸지 않는다.

### 세션 전환과 공용 레벨 캐시

16:00 런던 시작과 21:00 뉴욕 시작에 즉시 이전 세션 고저가를 제공한다. 세션 선택에는 진행 5분봉의 시작 시각만 사용하고, 진행봉 가격은 고저가 계산에 넣지 않는다. 캐시는 진행봉의 시작 시각이 바뀌면 갱신하며 진행봉 가격만 바뀔 때는 재계산하지 않는다.

### 가상진입 종료 정각

종료 시각과 같은 관측을 `observe()`에 전달한 뒤 추적을 끝낸다. `observe()`의 기존 제한에 따라 봉 시작이 종료 시각보다 앞선 확정 1분봉만 손절·익절에 쓴다. 종료 정각의 새 봉, 미완성봉, 종료 뒤 늦은 관측과 종료 정각의 확인 진입은 사용하지 않는다. 순차 실행, 병렬 실행과 보유 데이터 구간 경계에 같은 규칙을 적용한다.

### 가상환경 프로세스 소유권

`Part3/lab/backtest_supervisor.py`의 `bind_process()`가 작업 잠금 안에서 실행 ID와 프로세스 생성시각을 확인한다. 기존 기록과 실제 프로세스가 같으면 그대로 사용한다. Windows 가상환경의 직접 자식인 경우에는 기록된 부모가 같은 PID와 생성시각으로 살아 있을 때만 실제 자식으로 관리 대상을 바꾼다.

다른 부모, 재사용된 부모 PID, 종료된 부모와 이전 실행 ID는 거부한다. 관리 대상 필드만 바꾸므로 이미 들어온 취소 요청도 유지한다. 실제 가상환경을 만든 시험에서 계획·실행·재접속·안전 정지와 결과 저장까지 확인한다.

## 전체 검증

시험은 MOSES.exe가 없음을 확인한 뒤 각 묶음 285초 제한, `PYTHONDONTWRITEBYTECODE=1`, `-p no:cacheprovider`, TEMP 바로 아래의 짧은 `--basetemp`로 실행했다. 통합설치 시험은 `PYTHONPATH=통합설치`, `PYTHONUTF8=1`을 사용했다. 공식 verification의 실행기 `verification/current_worker.py`는 바꾸지 않고 임시 경로만 시험 플러그인으로 지정했다.

| 시험 | 결과 | 실행 시간 |
| --- | --- | ---: |
| 상시 `tests` + `Part3/tests` | **4,218 통과, 실패 0**, 기존 건너뜀 3·예상 실패 1; 하위 검사 278 통과 | 243.99초 |
| 통합설치 `통합설치/releasekit/tests` | **461 통과, 실패 0**; 하위 검사 123 통과 | 74.12초 |
| 공식 verification 83파일 | **최종 1,395 통과, 실패 0**. 처음 1,394 통과·1실패 후 해당 파일만 재검증하여 47 통과 | 최초 209.89초 + 해당 파일 2.60초 |

위 시간은 각 검사 실행기의 전체 경과 시간이다. 결과는 `검증결과/revision176/tests/full.txt`, `releasekit.txt`와 같은 이름의 JSON 요약에 보관한다.

첫 전체 실행은 4,198 통과·20실패였다. 새 가상환경 시험이 임시 가짜 엔진의 모듈 검색 경로를 남겨, 뒤의 Windows 병렬 시험이 `event_backtest.runner`를 찾지 못했다. 시험 종료 시 경로를 복원하도록 두 신규 시험의 격리를 보완했다. 제품 코드를 추가로 바꾸지는 않았다. 관련 네 파일을 연속으로 재실행해 60건 모두 통과한 뒤 전체 시험을 다시 실행했다. 최초 실패와 조사 내역도 `검증결과/revision176/tests/full_initial.txt`, `검증결과/revision176/virtual_boundary/test_isolation.txt`에 보관한다.

공식 검사의 첫 실패는 `verification/test_release_cache95.py`가 5분봉 시작 시각을 세션 레벨의 의존성에서 제외하도록 고정한 항목이었다. 이번 수정은 그 시각으로 세션을 선택하므로 기존 가정과 충돌한다. 4시간·8시간봉의 기존 캐시 검사는 유지하고, 5분봉 항목은 15:55→16:00에서 세션 고저가가 즉시 생기며 진행봉 가격은 제외되는지 확인하도록 대체했다. 진행봉 가격만 바뀔 때 재계산하지 않는 것도 검사한다. 시험 수는 47개로 같고 제품 코드 추가 변경은 없다. 최초 `검증결과/revision176/verification/48.json`은 보존하고 재검증은 `48_retry.json`·`48_retry.txt`에 따로 기록했다. 최종 수치는 처음 통과한 82파일과 해당 파일 재검증을 합한 것이다.

원본175의 작업 전 기록 2,144개 파일 해시와 작업 후 파일이 모두 일치한다. 수정 파일 목록과 원본 대조 결과는 `검증결과/revision176/file_audit.json`에 저장한다. 새 문서·시험·검증 기록에서 절대 경로와 사용자 이름이 남지 않았음을 검색으로 확인했다. 프로젝트와 창고를 함께 이동하는 재사용 시험도 통과했다.

## 배포와 남은 확인

이 수정본에서 EXE 빌드·설치·배포·업데이트는 하지 않는다. 실제 설치 EXE의 실행·프로세스 관리, 136 설치본의 실제 업데이트와 EA 교체는 별도 배포 검증이 필요하다. 알려진 올라마 종료 실패, 점 포함 종목의 포인트 칸 제약과 장기간 SPECIAL2 성능은 이번 6건 수정에 포함하지 않는다.
