수정본86: 외부 AI Provider 최소권한 정책

외부 API 추가 전에 공통 local/external 보안 경계만 정리했다.
모델 튜닝, UI 레이아웃, Part1/Part2 계산, Recipe/schema/validator/compiler,
기존 AI 설정 및 백테스트 데이터는 변경하지 않았다.

핵심 변경
1. common_ai/security.py
   명시적인 로컬 Provider만 local로 분류하고 나머지는 external로 분류한다.
   도구 권한, 외부 payload allowlist, 안전한 vocabulary/preset 요약,
   schema에 따른 현재 전략/Recipe 투영, 인증정보 마스킹을 중앙에서 처리한다.
   내부 시스템 문서와 과거 local 코드 조회 기록은 외부로 전달하지 않는다.
   전략 schema의 동적 snapshot/세션 이름은 보존한다.

2. common_ai/service.py / common_ai/gemini.py
   실제 현재 설정에 따라 전송 직전 필터를 적용한다.
   Gemini 직접 호출에도 같은 필터를 적용한다.
   Gemini 인증 redirect/키 echo를 차단하고 공통 응답·오류의 알려진 비밀값을 가린다.

3. common_ai/settings.py
   설정 조회에서 현재 및 향후 인증 필드를 공통 마스킹한다.
   기존 Gemini 키 설정 여부 표시는 유지한다.

4. Part3/lab/ai/agent.py / research_interpreter.py / research_chat.py
   external에는 원시 매뉴얼 대신 공통 계약 데이터를 제공한다.
   제공 도구를 제한하고 금지 요청은 실제 workspace 조회 전에 거부한다.
   현재 canonical을 유지한 후속 수정과 사용자 확인 후 적용 흐름은 그대로 유지한다.

5. Part3/lab/ai/shared_provider.py
   권한 판정은 생성 당시 설정이 아니라 현재 저장된 설정을 확인한다.
   설정 읽기에 실패하면 조회 권한을 열지 않는다.

6. common_ai/provider.py / local_gguf.py / local_lora.py / model_runtime.py
   기존 로컬 구현 및 오프라인 테스트 Provider에 local 권한을 명시한다.
   로컬 조회 도구와 실제 모델 로직은 유지한다.

테스트
- 신규 보안 테스트 3개를 공식 검증 목록에 추가했다.
- 기존 Gemini 도구 테스트 fixture는 실제 vocabulary dict와 안전한 계약 JSON으로 변경했다.
- 로컬 문맥 회귀 fixture는 local 권한을 명시했다.
- 결과: 286개 및 하위 검사 23개 PASS, FAIL 0.
- 실제 외부 API 호출 없이 모의 HTTP 및 공통 서비스로 검사했다.

사용
수정본86의 START_MOSES.pyw를 실행한다. 별도 보안 설정은 필요하지 않다.
기존 Gemini 선택 시 자동으로 external 정책이 적용된다.
추후 새 외부 Provider를 등록해도 공통 서비스에서는 같은 external 정책을 적용한다.
외부 Provider의 read_doc/read_project_code/search_project_code 거부는 의도된 동작이다.

추가 수정: Gemini API 키 입력·삭제·교체 및 인증 오류 안내
- common_ai/gemini.py: 키 접두사/문자 형식의 임의 제한을 제거하고 점을 포함한 표시 가능한 ASCII 문자를 허용한다. 공백·제어 문자와 과도한 길이는 차단한다.
- 같은 파일: HTTP 400의 인증 실패/사용 제한과 요청 형식 오류를 분리한다. Google 응답 원문과 키는 표시하지 않는다.
- Part3/lab/unified_settings.py: 새 키 저장 전에 모델 목록 GET으로 인증만 확인한다. 실패 시 기존 키와 대화 상태를 유지한다. 삭제만 하는 경우에는 불완전한 Gemini 설정 저장을 허용하며 실제 AI 호출은 키 입력을 요구한다.
- Part3/web/unified.js: 새 키 입력은 삭제 체크보다 우선한다. 입력 없이 삭제만 선택해 저장할 수 있다. 키 교체·확인·삭제 방법을 기존 설명에 표시한다.
- 새 Python 회귀 테스트를 공식 검증 목록에 추가했다. 실제 화면의 저장 핸들러는 별도 모의 API 브라우저 테스트로 확인했다.
- 검증: 관련 Python 129개 및 하위 검사 9개 PASS, 화면 시나리오 4개 PASS, JS/Python 문법 PASS.
- 실제 Google API 또는 실제 키로 연결 검사하지 않았다. 운영 설정과 Part1/Part2, 전략 schema/Recipe/compiler는 수정하지 않았다.
- 검증 증거: 검증결과/Gemini키수정86.txt

추가 수정: AI 전략연구 입력창과 실행 로그 겹침
- 실행 파일 변경은 Part3/web/style.css의 AI 화면 레이아웃 규칙뿐이다.
- 화면 높이에 고정된 작업 영역을 내용에 맞춰 늘어나도록 바꿨다. 최소 높이는 유지하고 좁은 창에서는 세로 배치한다.
- 대화 영역의 최대 높이 제한을 유지하여 긴 대화는 내부에서 스크롤된다. 입력창 확대와 확인·연결 정보 표시 시에도 패널이 로그를 덮지 않는다.
- 수정 전 1280x720에서 연결 정보가 패널 밖으로 나오는 것을 재현했다.
- Part3/tests/test_ai_layout86.cjs: 창 크기 5종 × 초기/긴 대화·입력 확대·확인 및 연결 정보 펼침, 총 10개 PASS.

추가 수정: Gemini 전략 요청 HTTP 400
- 실제 Google 응답에서 저장된 모델명의 대문자로 인한 unexpected model name format을 확인했다. 모델 목록의 정식 ID와 대소문자를 제외하고 일치했다.
- common_ai/gemini.py에서 Google 모델 ID를 소문자로 정규화한다. 특정 모델명·버전을 고정하지 않는다.
- 모델명을 바로잡은 후에도 현재 전략 schema를 native responseJsonSchema로 전송하면 HTTP 400이 발생했다. 작은 schema는 HTTP 200이었다.
- 참조/$defs가 있는 공통 전략 계약은 Gemini의 application/json 출력 모드로 요청한다. 전체 원래 schema는 승인된 프롬프트에 그대로 포함하며 응답은 기존 전체 schema로 검증한다. 단순 WATCH 등은 기존 native schema 방식을 유지한다.
- 요청 종류 분류·추가 재해석·자동 재시도·모델 튜닝은 추가하지 않았다. tool loop와 금지 tool 거부, 인증정보 차단도 유지한다.
- 런타임 변경은 common_ai/gemini.py만 해당한다. 원래 schema/intent/Recipe/validator/compiler와 로컬 Provider 및 운영 설정 파일은 변경하지 않았다.
- 회귀: 139개 및 하위 검사 9개 PASS. 원래 schema 위반 JSON과 금지 tool이 적용 경로로 넘어가지 않는지 확인했다.
- 실제 Gemini에서 화면의 기본더블비/1분 올존 요청을 해석하고 schema → intent 검증 → Recipe 변환까지 통과했다. 약 2.4초, 조회 도구 요청 없음. 생성·저장·적용은 실행하지 않았다. schema 통과 자체가 자연어 의미의 완벽한 해석을 보증하는 것은 아니며 기존 사용자 확인 흐름을 유지한다.
- 증거: 검증결과/Gemini요청수정86.txt
