# Part2 연결 — 녹화 창고 구축 / 수정본21

이번 산출 범위는 **MT5 MSP3 녹화와 이동 가능한 창고 구축**까지다. 모든 전략을 한꺼번에 실행한 기존 재생은 대상 전략을 선택한 백테스트가 아니므로 공개 실행을 중지했다. 대상 전략 선택 실행은 다음 작업으로 남긴다.

**재생 수치는 전체 감시 기준이며 백테스트 시간 아님.** 이를 실제 백테스트 소요 시간이나 1년 성능으로 환산하지 않는다.

## 마무리 상태

- 2026년 1월 조각을 파일·해시·DuckDB에 등록한 시점에서 녹화를 종료했다. 원래 설치되어 있던 EA/지표/헤더를 복원하고 일반 MT5를 다시 열었다.
- 하루 틱 재생은 사용자 지시로 중단했다. 분기 순차·병렬 비교와 1년 재생은 대기 상태에서 취소했으며 실행하지 않았다. 한 달 순차·주별 병렬 비교도 후속 마무리 지시에 따라 실행하지 않았다.
- 마무리 지시 이후 추가 시험·측정은 하지 않았다. 아래는 이미 완료된 결과와 중단 직전의 진행 기록이다.
- GUI는 녹화·목록 전용으로 정리했다. 전체 감시 `실행` 버튼을 제거했고 CLI `run`도 미구현된 전략 선택 실행을 안내하는 오류로 막았다. 기존 재생 모듈·도구는 진단 이력/후속 작업 재료로 보존한다.

## 완료된 녹화

종목 **XAUUSD+**, 월 BAR 조각 **6개**, 기간 **2025-08-01~2026-02-01**(UTC, 끝 미포함). 2025년 8월은 당초 겹침 준비용으로 녹화한 달이다. 2025년 9월부터 시작한 요청 구간에서는 2026년 1월까지 완료했다. 2026년 2~8월은 이번에 녹화하지 않았다.

BAR는 TIMER 관측 격자에서 M1 새 봉의 첫 관측만 기록한다. 시장 입력은 EA Wire v2 녹화인 MSP3이며, 기존 48열/schema를 유지한다. 보관 시 gzip으로 무손실 압축하고 파일 해시를 기록한다. native_snapshots는 엔진 입력으로 사용하지 않았으며 기존 네이티브 추출 자동화와 DuckDB 창고 코드는 보존했다.

**월 조각 6개 모두 생성 틱 사용 경고가 있다.** 실제 틱 전용 녹화로 간주하면 안 된다. 예를 들어 2025년 8월 저널은 28,932개 분봉 전부에서 실제 틱이 없어 생성 틱을 사용했다고 명시했다. 이 사실을 `MIXED_OR_GENERATED`로 목록에 보존했다. 이번 마무리에서 다운로드나 재녹화는 추가로 시도하지 않았다.

## 5년 저장 크기 예상 — BAR 기준

완료된 XAU 월 6개의 평균 보관 크기에 60개월을 곱했다. 실제 5년 녹화를 측정한 값이 아니다. NAS100은 이번에 녹화하지 않았으므로 같은 관측 수·압축률을 가정한 대리 추정이다. 거래시간·거래일·데이터 압축률에 따라 달라진다. TIMER 1초 녹화의 5년 크기로 해석하면 안 된다.

| 대상 | 5년 중심 추정 | 관측 월 최소~최대 크기를 60배 한 참고 범위 |
|---|---:|---:|
| XAU BAR | 1.102TB (1.002TiB) | 1.011~1.179TB |
| NAS100 BAR — XAU 대리 추정 | 약 1.102TB | 실제 NAS 표본 없음; 동일 가정 시 위 범위 |

임시 미압축 녹화 공간과 별도 백업은 이 보관 크기에 포함하지 않았다. 예측 산식과 실측 바이트는 `검증결과/part2_connection/storage_estimate.json`에 보존한다.

## 이미 확인한 결과

1. EA·PRICE/RSI/STO/DI 다섯 소스: 컴파일 오류 0, 경고 0.
2. 실제 XAU 하루 BAR와 TIMER를 봉 경계로 거른 입력: **1,377묶음**의 관측 시각·피드·값·준비 상태가 같았다. 같은 전체 감시 경로의 최종 알림 16건도 같았지만, 이를 선택 전략 백테스트 검증이라고 부르지 않는다.
3. 보존 XAU를 PipeReceiver → STAFF 경로와 재생 경로로 처리한 오프라인 확인: 239묶음, 최종 알림 2건 동일. 실제 온라인 대기나 텔레그램 전송은 하지 않았다.
4. 창고를 다른 폴더로 이동한 뒤 목록 조회와 재생이 같았다(**2알림**). 프로젝트와 창고를 함께 이동한 별도 시험에서도 DuckDB `runs`/`alerts`/`timings`와 CSV가 생성됐다(**2알림, 9처리기 시간 행**).
5. `captures`는 녹화 조각 메타데이터만 저장한다. 시장 본체는 MSP3 파일이다. `runs`/`alerts`/`timings`는 이미 구현한 결과 저장 형식이며, 이동 시험의 기록은 별도 시험 창고에서 확인했다. 공용 창고에 실제 선택 전략 백테스트 결과가 있다고 주장하지 않는다. OZ 이벤트 저장 테이블은 만들지 않았다.

이미 끝난 관련 시험은 E1 31개와 연결 시험 24개, 합계 55개 통과다. 이후 범위 축소에 따른 화면·공개 실행 차단은 단순 마무리 변경이며 사용자 지시대로 새 시험을 실행하지 않았다. Part2 일반 회귀 네 묶음은 실행하지 않았다.

## 전체 감시 재생의 기존 수치

**전체 감시 기준이며 백테스트 시간 아님.** 아래 평균은 입력 읽기·디코드·선택·엔진을 포함한 경과 시간을 묶음 수로 나눈 값이다. 엔진 전용 평균은 따로 표시한다. 메모리는 Windows worker peak working set이다.

| 완료된 진단 | 묶음 | 경과 초 | 입력 포함 ms/묶음 | 엔진 ms/묶음 | 최대 MiB |
|---|---:|---:|---:|---:|---:|
| 하루 BAR 전체 감시 | 1,377 | 258.22 | 187.520 | 171.824 | 236.53 |
| 하루 TIMER→BAR 전체 감시 | 1,377 | 632.98 | 459.677 | 168.822 | 236.55 |

하루 틱 재생의 중단 직전 기록: **6,891묶음**, **1019.19초**, 입력 포함 **147.902ms/묶음**, 최대 **159.09MiB**. 엔진 전용 중간 누적 시간이 파일에 없으므로 그 값이나 부분 p99를 만들어내지 않았다. 마지막 진행 기록 이후 강제 종료까지의 짧은 구간은 이 수치에 포함되지 않는다.

앞선 첫 틱 측정은 약 2,631초에서 Windows 진행률 JSON 교체 잠금으로 실패했다. 진행률 기록을 best-effort로 바꾼 뒤 다시 실행했고, 위 수치는 그 재시작 구간의 중단 기록이다. 실패 시도와 중단 시도를 성공한 하루 전체 결과로 합치지 않았다. 이미 끝난 BAR 두 결과는 반복하지 않았다. 분기/1년 재생·단일 코어 1년 환산·주별 병렬 비교 결과는 없다.

## 녹화·창고 사용법

1. `Part2/START_BACKTEST.cmd`를 열면 **MSP3 녹화 창고** 화면이 열린다. 런처는 이 컴퓨터의 Python 3.12/3.13 64비트를 사용하고 이동된 가상환경을 필요하면 재구성한다.
2. **창고 선택**으로 이 컴퓨터에서 연결된 외장하드의 창고 루트를 지정한다. 기본은 프로젝트들의 상위 폴더 옆 `개피곤_warehouse`다. 루트 바인딩은 컴퓨터별 설정/화면 값이며 DuckDB 목록에 저장하지 않는다.
3. 종목, UTC 시작일·종료일(미포함), BAR/TIMER를 고른다. 기본 날짜는 최근 완료된 12개월이다. TIMER는 STAFF_TIMER_MS 관측 간격이며 기본 1000ms다. BAR는 장기 녹화, TIMER는 짧은 관측 구간용이다.
4. **누락 조각 확인**으로 보유/빈 구간을 보고 **녹화 준비**로 빈 조각만 추가한다. 녹화는 선택된 MT5를 정상 종료하고 테스터 전용으로 실행한 뒤 원래 파일·일반 터미널을 복원한다. 모든 조각이 이미 있으면 MT5를 건드리지 않고 재사용한다.
5. 완료된 달은 월 조각, 진행 중인 달은 일 조각으로 보관한다. 이미 있는 일 조각과 새 월 조각이 중복되지 않게 커버리지를 선택한다. 파일 해시가 다르거나 완료 표시가 없으면 정상 재사용 대상으로 삼지 않는다.

**이어 붙이기:** 같은 창고·종목·EA 빌드·BAR 설정으로 기간을 `2026-02-01~2026-09-01`로 지정하고 **녹화 준비**를 누르면 없는 2~8월 조각만 추가한다(앞 겹침에 필요한 1월은 재사용).

CLI는 Part2 폴더에서 `python -B -m event_backtest missing --symbol XAUUSD+ --start 2026-02-01 --end 2026-09-01 --mode BAR`, 이어서 같은 인수의 `prepare`를 사용한다. `--warehouse`로 이 컴퓨터의 루트를 지정한다. 설정은 `Part2/event_backtest.json`이다. `run`은 현재 차단되어 있으며 대상 전략 선택 실행은 다음 작업이다.

창고는 `captures/<조각 ID>`, `builds/<소스 해시>`, `runs/<진단 실행 ID>`, `event_backtest.duckdb`로 구성된다. 목록·메타데이터·설정 안의 데이터 경로는 루트 기준 상대 경로만 사용하고 절대 경로·드라이브·루트 밖 `..`를 거부한다. 기존 개발 중 절대 경로가 들어간 DB는 상대 경로만 가진 새 DB로 재작성했다. 컴퓨터 전용 MT5 실행 경로·임시 설정은 창고에서 분리한다. 서로 다른 프로그램이 같은 DuckDB에 동시에 쓰는 운용은 지원하지 않는다.

현재 녹화 종료는 이미 실행 중이던 옛 작업이 중단 신호를 지원하지 않아, 해당 월의 CAPTURE_COMPLETE 등록 후 녹화 프로세스만 종료하고 설치 백업을 명시적으로 복원했다. 진행 중인 월의 파일을 중간 결과로 채택하지 않았다. 종료 근거는 `recording_stopped_at_boundary.json`이다.
