## 1. 이번 정정의 결론

공용 프로필 선택지만 지운 뒤 SPECIAL5 전용 코드에서 레짐 올존 후보를 다시 판정하던 구현을 제거했습니다. 기존 전략 결과를 유지하기 위한 별도 레짐밴드 조건, 지표군별 후보 필터, 독립 B0/소비 상태, 추가 이벤트 발행을 남기지 않았습니다. 새 환경조건 구조로 옮긴 구현도 없습니다.

SPECIAL5 전체를 삭제하지는 않았습니다. 수정본48에 이미 존재하던 **일반 BREAKER 발생 + 해당 상위 프레임의 마지막 확정봉 EMA50/200 방향 일치** 경로만 남겼습니다. 레짐 경로 제거에 따른 SPECIAL5 결과 변화는 허용하며, 이를 보상하는 조건은 추가하지 않았습니다. 자식 감시의 기존 만료·교체·해제 규칙은 유지합니다.

이 문서는 정정본의 루트 `수정내역48.md`를 대체합니다. 이전 문서의 “상위 레짐밴드 대체 조건으로 기존 동작을 보존한다”는 설명은 이번 배포에 적용되지 않습니다.

### Part3

현재 사용자 안내서, 스키마 설명, SPECIAL 설명표와 참조 HTML의 SPECIAL5 설명·소스를 함께 정리했습니다. `Part3/reference/`의 역사 자료와 기존 `Part3/generated/` 사용자 생성물은 원본대로 보존했으며 자동 복원용 대체 소스로 사용하지 않았습니다.

## 4. 유지하는 OZ 프로필과 판정

| 표시 이름 | validation_mode | trigger_mode |
|---|---|---|
| 올존 | NORMAL | OZ |
| 무지성 올존 | BLIND | OZ |
| 브레이커 올존 | NORMAL | BREAKER |
| 무지성 브레이커 올존 | BLIND | BREAKER |

`DIVERGENCE` 단독 값은 기존 의미를 그대로 갖는 `BREAKER`의 읽기 호환 별칭입니다. 기존 엄격한 TRUE B0 돌파, OUT→IN, HMA 교차, 후보 추적과 누적 완료 판정을 다른 조건으로 대체하지 않았습니다. 실제 지표 다이버전스 계산을 추가하지 않았습니다.

공용 NORMAL/BLIND 및 OZ/BREAKER의 기존 평가 순서, 선택 의존성 최적화는 유지합니다. 삭제한 레짐 전용 평가가 끼어들던 부분만 제거했습니다. 브레이커 경계·기본 후보 유지·트리거 누적 등 23개 선정 함수의 AST를 원본48과 대조해 동일함을 확인했습니다. 삭제한 후보 필터 분기 자체를 “변경 없음”으로 주장하는 것은 아닙니다.

## 6. 저장 설정과 과거 감시 상태의 안전 처리

### 정상 별칭과 제거된 프로필 구분

- `DIVERGENCE` 단독: BREAKER로 정규화합니다. 지원되는 후보 체크포인트의 상태도 유지할 수 있습니다.
- `REGIME`, `SUPER` 및 해당 조합: 일반 올존 또는 BREAKER로 자동 변경하지 않습니다. 현재 설정/생성 진입점에서 명시적으로 거부합니다.
- `UPPER_REGIME_BAND` 등 폐기된 SPECIAL5 출처: 정상 자식 OZ 프로필이 함께 있어도 통과시키지 않습니다. 출처 메타데이터와 구형 감시 ID를 모두 검사합니다.

기존 Watch/Composer 복원은 제거된 감시의 원값·ID·사유를 `rejected_watches` 기록에 남기고 활성 목록에서 제외합니다. SPECIAL5에 이미 남아 있는 제거된 부모/자식 감시는 해제하며 BREAKER 감시로 이관하지 않습니다. 해제된 자식의 지연 도착 최종 이벤트도 발송하지 않습니다.

엔진 시작 시 `special5_source_band_` 후보 상태와 제거된 프로필 헤더를 가진 `oz_observed_` 상태는 활성 메모리에서 제외하고 원문과 이유를 `oz_rejected_profile_checkpoints.json`에 보관합니다. 이 코드는 저장 상태를 폐기 경로로 분류하는 코드이며 레짐 후보를 재평가하거나 대체 상태를 만드는 코드가 아닙니다.

## 7. SPECIAL5 결과 변화 — 보상하지 않음

원본48과 정정48을 각각 별도 프로세스에서 동일한 합성 시세·후보 상태로 실행했습니다. 양쪽 모두 실제 네트워크를 차단했으며, 아래 각 사례에서 LIVE/BACKTEST 결과가 서로 일치했습니다. 원본 결과는 차이 보고용이지 복원해야 할 정답으로 사용하지 않았습니다.

표의 수치는 **내부 부모 OZ 이벤트 수 / 활성 자식 감시 수**입니다.

| 입력 사례 | 원본48 | 정정48 | 의미 |
|---|---:|---:|---|
| EMA 조건만 충족 | 1 / 3 | 1 / 3 | 남기는 BREAKER+EMA 경로 |
| 레짐밴드 조건만 충족 | 2 / 3 | 1 / 0 | 별도 레짐 이벤트와 그 자식 생성 제거. 일반 BREAKER 이벤트는 EMA에서 차단 |
| 두 조건 모두 충족 | 2 / 3 | 1 / 3 | 별도 레짐 이벤트 및 그에 의한 중복 생성/교체 제거 |
| 둘 다 불충족 | 1 / 0 | 1 / 0 | 부모 일반 이벤트 이후 전략 조건에서 차단 |
| 레짐 지표군 필터가 별도 B0를 남기던 사례 | 1 / 3 | 0 / 0 | 레짐 전용 후보/B0 평가 삭제 |

두 조건이 모두 충족되던 경우도 전용 이벤트가 없어지므로 부모 이벤트 식별자·자식 그룹 선택·교체 횟수가 달라질 수 있습니다. 기존 레짐 경로가 만들던 이후 최종 알림은 더 이상 만들어지지 않을 수 있으며, 이 결과 변화는 의도한 삭제 영향입니다.

위 비교는 부모 단계 시험으로 외부 최종 알림 수는 모두 0입니다. 이를 실제 시장의 최종 알림 감소량으로 해석하지 않습니다. 자식 최종 이벤트 전달과 해제는 별도 오프라인 시험에서 확인했습니다.

증거: `special5_before_results.json`, `special5_after_results.json`.
