# 백테스트 화면과 안전 정지 — 수정본33

수정본32를 복사한 수정본33에서 작업했다. 이전 검증결과는 복사하지 않았으며 이번 증거는 `검증결과/stop_virtual_parallel/`에 저장했다. 실제 텔레그램 전송·MT5 실행은 하지 않았다. 전략 판정식, EA, Wire 스키마, 녹화 형식, 사용자 config는 변경하지 않았다.

## 화면

- 종목·재생 모드 Combobox의 화살표만 제거했다. 기존 선택 기능은 유지한다.
- SPECIAL/WATCH는 두 칸, 결과 옵션은 **알림 온리 / 가상 진입 / 데이터 구축** 세 칸의 Canvas 전환 버튼이다.
- WATCH 수신자 입력을 없애고 내부 기본값 `BACKTEST`를 사용한다. 감시 명령 입력은 두 줄이다.
- 스프레드는 가상 진입에서만 표시한다. 데이터 구축에서는 `초기화 후 녹화`를 표시한다. 숨겼다가 다시 선택해도 입력값과 체크값을 유지한다.
- 데이터 구축은 구축만 수행한다. 다른 두 모드는 기존처럼 빠진 데이터를 구축한 뒤 백테스트한다.
- 실행 버튼 옆에 정지 버튼을 추가했다. 정지 요청 이후에는 부분 결과 저장이 끝날 때까지 기다린다.

실제 Tk 창을 실행해 `part2_alert.png`, `part2_watch_virtual.png`, `part2_build.png`를 생성했다. 화면 검증은 `gui_checks.json`에 남겼다.

## 정지와 부분 결과

실행 폴더의 `stop.request`를 GUI·CLI·구축 코드·worker·가상 진입 계산기가 공유한다. 프로세스 강제 종료 대신 현재 처리 경계에서 멈춘다. 백테스트 worker는 진행 중인 엔진 이벤트 처리를 마친 뒤 CSV를 닫고 합친다. 가상 진입은 현재까지 관측한 거래와 손익비별 결과를 저장한다.

`result.json`에는 `status=CANCELLED`, `status_label=중단됨(부분 결과)`와 실제 처리 구간 `processed_periods`를 기록한다. 병렬 처리에서 떨어져 있는 구간을 하나의 연속 구간처럼 합치지 않는다. 워밍업 구간도 실제 결과 처리 구간에 넣지 않는다. 가상 진입의 계산 범위는 알림별로 별도 기록한다.

결과 보기에서 상태·실제 처리 구간·부분 알림/가상 진입 표를 볼 수 있다. 백테스트 단계에서 멈춰 가상 진입을 시작하지 못한 경우에는 알림 표와 `가상 진입 시작 전`을 표시한다. 부분 결과를 최종 성과와 혼동하지 않도록 미계산 알림은 가상 진입 성과에서 제외한다.

구축에서는 차분 변환·복원 검증 중인 후보를 고유한 `.partial_...` 폴더에 둔다. 검증 성공 후 최종 경로로 옮기며, 중단·예외 시 해당 후보만 제거한다. 기존 완성 조각과 이미 완료된 새 조각은 보존한다. gzip 작성기를 먼저 닫은 뒤 파일을 닫아 중단 시 리소스 오류도 막았다. MT5 종료 확인과 원래 파일·터미널 복원에는 취소를 전달하지 않는다. 정지는 즉시 강제 종료가 아니므로 현재 입력 복원과 터미널 정상 종료를 기다릴 수 있다.

초기 실패 XML은 삭제하지 않았다. 예전 GUI 체크박스/버튼 구조를 전제로 하던 시험은 새 전환 버튼의 동일 기능 확인으로 바꾸었다. Tk 창을 같은 pytest 프로세스에 반복 생성할 때의 환경 오류는 각 GUI 시험을 별도 프로세스로 실행해 확인했다. 최신 판정 근거는 위의 49+4건이며, 초기 이력 집계 `test_summary.json`은 최종 판정용이 아니다.
