# 수정본52 — localhost 통합 UI의 WebView2 전용 창

수정본51을 복사하되 이전 `검증결과`는 제외했다. 기존 엔진, 웹 API, Part1/Part2 파일, 전략 판정은 바꾸지 않았다.

## 변경

- `START_MOSES.pyw`: 기본 브라우저 대신 전용 창 진입점을 호출한다. 시작 오류는 기존 파일과 Windows 메시지로 알린다.
- `Part3/lab/desktop_window.py`: 기존 `LabServer`를 `127.0.0.1`에서 시작하고, 기존 일회용 토큰 주소를 WebView2에 표시한다. 창이 닫히거나 생성에 실패하면 이 UI 서버를 닫는다. 기본 포트가 점유되면 기존처럼 빈 포트를 쓴다. `edgechromium`을 강제해 구형 렌더러로 바뀌지 않게 한다.
- `Part3/requirements-desktop.txt`: 전용 창에 필요한 `pywebview` 버전을 고정했다.
- `Part3/tests/test_desktop_window52.py`: 실제 localhost 응답, WebView2 지정, 브라우저 미실행, 서버 종료, 의존성 부재, 시작 파일 연결을 시험한다.
- `README_MOSES_DESKTOP.md`: 설치·실행 방법을 기록했다.

`Part3/run.py`의 브라우저 방식은 별도 실행용으로 유지했다. 기존 Tk GUI 파일도 삭제하지 않았다.

## 확인

- Part3 테스트 전체 50개 통과. 결과는 `검증결과/part3_unittest.txt`.
- Python 3.13 및 pywebview 6.2.1에서 실제 EdgeChromium 창을 띄워 페이지 로드와 종료를 확인했다.
- 테스트에서는 텔레그램 전송, MT5 실행, 백테스트 수행을 하지 않았다.

## 통합 화면 분리 (같은 수정본52에서 후속 작업)

- `Part3/web/index.html`: 라이브 감시를 메인·전략 설정·모듈 로그 화면으로, 백테스트를 설정·진행·결과 화면으로 분리했다. 기존 입력·출력 요소의 ID와 API 연결은 유지했다.
- `Part3/web/unified.js`: 화면 안에서 전환하도록 연결했다. 메인에는 `이벤트 엔진 연결 대기`처럼 사용자가 이해할 수 있는 상태만 표시하고, `[WinError 2]` 같은 원문 오류는 모듈 로그 화면에서만 확인하게 했다. 실행이 끝나면 결과 화면으로 이동하며 설정·진행 화면도 다시 열 수 있다.
- `Part3/web/style.css`: 분리한 화면의 카드·간격과 로그·결과 영역 크기를 조정했다.
- `Part3/tests/test_unified_web.py`: 기존 컨트롤이 각 화면에 남아 있고 상세 화면이 처음에는 숨겨지는지 회귀 검사한다.
- `검증결과/ui_navigation_smoke.py`: 실제 WebView2에서 라이브 메인·전략 설정·로그, 백테스트 설정·진행·결과 전환을 확인하는 수동 시험이다.

검증: JavaScript 구문 검사 통과, Part3 전체 51개 테스트 통과. WebView2 화면 전환 7개 확인 항목 통과. Part1·Part2 파일, 엔진·백엔드 API, 텔레그램 전송, MT5 실행, 백테스트 계산은 변경하거나 실행하지 않았다.

## 상단 이동 메뉴와 뒤로 가기 (같은 수정본52에서 후속 작업)

- 상단 메뉴를 `라이브 감시`·`백테스트`·`전략 생성` 3개 큰 배너로 만들고, `설정`은 오른쪽 작은 톱니바퀴 버튼으로 바꿨다.
- 눈에 띄는 `← 뒤로` 버튼을 상단에 추가했다. 라이브 설정·로그에서는 라이브 메인으로, 백테스트 결과에서는 진행 기록으로, 진행에서는 설정으로, 최상위 화면에서는 직전 메뉴로 돌아간다.
- 결과에서 진행 기록으로 돌아갔을 때 상태 갱신이 다시 결과 화면으로 밀어내던 UI 전환도 막았다. 백테스트 실행·결과 데이터는 변경하지 않았다.
- 헤더와 좁은 창 배치를 확인했다. 기존 Part1·Part2·Part3 엔진 및 웹 API는 변경하지 않았다.

검증: JavaScript 구문 검사 통과, Part3 전체 52개 테스트 통과. 실제 localhost 화면에서 전략 설정→뒤로, 백테스트→뒤로, 설정 톱니바퀴 진입과 상단 배너 배치를 확인했다. 테스트 중 라이브 시작, MT5, 백테스트 실행, 텔레그램 전송은 하지 않았다.

## 라이브 화면을 Part1 시스템 컨트롤 형태로 정렬 (같은 수정본52에서 후속 작업)

- 상단의 `← 뒤로` 문자 버튼을 제거하고, 하위 화면에서만 보이는 왼쪽 가운데 `◀` 삼각형 버튼으로 바꿨다. 기존 화면 복귀 동작은 유지했다.
- 웹 라이브 메인을 현재 Part1 시스템 컨트롤의 구성에 맞췄다: 브랜드 헤더 → 동일한 비율의 시작·종료·전략 설정 버튼 3개 → 2열×4행 모듈 카드 → 하단 상태바. Part1의 색상·간격·카드 높이와 유사하게 조정했다.
- 모듈 카드에 아이콘 박스, 모듈명, 상태 점·문구, 작은 꺾쇠를 배치했다. 전체 카드 클릭과 기존 로그 API는 유지했다.
- 통합 상단 메뉴는 별도 셸로 남겨 라이브·백테스트·전략 생성·설정 전환을 유지했다. 라이브 화면에서는 브랜드가 두 번 보이지 않게 셸 브랜드만 숨겼다.

검증: JavaScript 구문 검사 통과, Part3 전체 53개 테스트 통과. 실제 localhost 화면 1280×800에서 Part1 형태의 2열×4행, 하단 상태바, 왼쪽 가운데 삼각형 표시와 복귀 동작을 확인했다. Part1·Part2 소스 및 실행 로직은 수정하지 않았다.

## 백테스트·전략 생성 배경색 수정 (같은 수정본52에서 후속 작업)

라이브 화면의 중복 브랜드를 피하려고 `body`에 현재 메뉴 표시를 추가했는데, 메뉴 강조 코드의 선택 범위가 넓어 `body`까지 `primary` 버튼 스타일을 받았다. 라이브 화면은 자체 배경이 있어 드러나지 않았으나, 백테스트와 전략 생성 화면은 파란색 페이지 배경으로 보였다.

- 메뉴 선택·클릭 대상은 상단 메뉴의 버튼으로만 제한했다.
- 페이지 공통 배경은 라이브 화면과 같은 어두운 네이비 그라데이션으로 맞췄다.
- Part1·Part2·Part3 엔진, 백테스트 데이터·설정·콜백은 변경하지 않았다.

검증: 실제 localhost 화면에서 백테스트와 전략 생성 모두 `body.primary`가 붙지 않고 네이비 배경으로 보이는 것을 확인했다. Part3 전체 54개 테스트와 JavaScript 구문 검사가 통과했다.

## 백테스트 화면을 Part2 GUI 구성으로 정렬 (같은 수정본52에서 후속 작업)

- 웹 백테스트 설정을 현재 Part2 GUI의 정보 순서에 맞췄다: 종목·기간·재생 모드의 가로 입력 카드, 데이터 연결 줄, SPECIAL/WATCH 대상 카드와 결과 옵션 카드의 좌우 배치, 파란 실행 버튼. SPECIAL별 선택·트리거·거래시간은 별도 하위 화면에서 편집해 메인 화면의 밀도를 줄였다.
- 진행 화면은 데이터 확인 카드, 단계 상태바, 구축·재생 게이지, 주의 사항·실행 로그·결과 요약 3열 카드로 정리했다. 결과 화면은 그대로 유지했다. 모든 기존 백테스트 입력 ID와 요청 데이터 구조, 실행·정지·결과 API는 유지했다.
- Part1 팔레트의 네이비 배경·카드·입력·파란 버튼을 통합 웹 UI에 적용했다. 왼쪽 중간 `◀` 버튼은 둥근 형태로 다듬고, 네 개 상단 메뉴는 각각 최상위 화면으로 열리게 했다. 뒤로 가기는 라이브/백테스트 하위 화면에서만 나타난다.
- 수정 파일: `Part3/web/index.html`, `Part3/web/style.css`, `Part3/web/unified.js`, `Part3/tests/test_unified_web.py`. Part1·Part2 파일과 백엔드 계산 코드는 변경하지 않았다.

검증: 실제 localhost 화면 1280×800에서 백테스트 설정 카드·SPECIAL 설정·WATCH·가상 진입 전환, 전략 생성 화면의 네이비 색상, 최상위 메뉴에서 뒤로 가기 버튼 숨김을 확인했다. Part3 테스트 55개와 JavaScript 구문 검사가 통과했다. 시험 중 백테스트·MT5·텔레그램은 실행하지 않았다. `검증결과/백테스트_웹UI_검증.txt`에 확인 항목을 남겼다.
