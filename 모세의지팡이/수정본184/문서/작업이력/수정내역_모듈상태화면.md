# 모듈 상태 화면 연결

## 공용 로그 버튼 제거

`모듈 상태 / 추적 로그` 공용 버튼과 `클릭하면 추적 로그` 안내 문구를 제거했다. 제목은 `모듈 연결 상태`로 남겼다. 8개 모듈 상태 버튼은 선택한 로그를 계속 연다. 실제 Tk 화면 시험에서 두 문구가 사라지고 OZ 버튼의 로그 연결이 유지됨을 확인했다. 무결성 체인 `54-direct-module-logs`에 등록했다.

## 표시 이름 후속 변경

메인 버튼과 해당 로그창 제목의 표시 이름을 `MT5 연결 → STAFF`, `EVENT ENGINE → EVENT`, `OZ MONITOR → OZ`로 줄였다. 아래의 초기 구현 기록에 나오는 옛 이름은 당시 상태를 설명한다. 내부 모듈 키와 상태 수집은 변경하지 않았다. `모듈 상태 / 추적 로그` 공용 버튼의 존치 여부는 이번 표시 이름 변경 범위에서 결정하지 않았다. 관련 Tk 화면 시험을 다시 통과했고, 무결성 체인 `53-module-display-names`에 등록했다.

## 상단 중복 표시 정리

메인 화면 맨 위에 있던 `EVENT ENGINE 실행 중 · PID` 행을 제거했다. 같은 대상을 아래의 `[EVENT ENGINE]` 상태 버튼에서 확인한다. 옛 행을 갱신하던 5초 프로세스 조사와 `상태 새로고침` 버튼도 함께 제거했다. 아래 모듈 상태는 1초 주기로 자동 갱신된다. 전체 시작·종료 동작과 각 작업의 완료 안내는 유지했다. 실제 Tk 시험에서 상단 별도 행이 없고 아래 상태 버튼이 남아 있음을 확인했으며, 관련 UI 시험 18건도 통과했다. 이 후속 편집은 무결성 체인 `52-system-control-dedup`에 등록했다.

수정본30에서 직접 수정했다. 새 수정본 폴더를 만들지 않았고 이전 수정본은 변경하지 않았다. 전략 판정·알림 문구·전송 경로는 변경하지 않았다.

## 화면

- 시스템 컨트롤 본창에 공용 모듈 8개를 2열 상태 버튼으로 표시한다: MT5 연결, EVENT ENGINE, OZ MONITOR, SWEEP, FVG, INDICATOR, WATCH, 김비서. SPECIAL1~7은 이 목록과 공용 로그창 목록에서 제외한다.
- 상태 버튼을 누르면 선택 모듈이 지정된 추적 로그창을 연다. 창 제목과 로그 제목에 `[OZ MONITOR]`, `[김비서]`처럼 표시 이름을 넣는다. 내부 진단 키(STAFF, ENGINE, OZ, KIM)는 그대로 사용한다.
- 전략 설정에서는 SPECIAL1~7 각 행에 현재 상태·마지막 처리 시각과 `추적 로그` 버튼을 표시한다. 이 버튼은 해당 SPECIAL의 로그만 보여준다. 백테스트 전략 설정 화면은 변경하지 않았다.
- 두 화면은 별도 작업 스레드에서 읽기 전용 진단 IPC를 1초마다 조회한다. 엔진 스레드는 화면을 직접 호출하지 않는다. 연결 전에는 회색, 정상은 초록, 지연은 황색, 오류·끊김은 적색으로 표시한다.
- `MT5 연결`은 시장 휴장 여부가 아니라 실제 Named Pipe 연결 여부를 사용한다. 처음 연결 전은 `연결 대기`, 연결 후 끊어지면 `끊김`이며, 연결 중에는 기존 피드 상태의 정상·지연·오류를 표시한다. 상태 수집에 필드만 추가했고 SOURCE_HEALTH 의미와 파이프 데이터 형식은 변경하지 않았다.

실제 추적 내용은 기존 모듈별 링버퍼를 읽는다. 예시 문장을 화면에 만들어 넣지 않았다. 로그가 없는 모듈은 빈 로그로 표시하고, 진단 서버가 실행되지 않으면 연결 대기로 표시한다.

## 검증

새 Tk 화면 시험 1건 통과: 메인 8개와 SPECIAL 제외, 표시 명칭, 상태 버튼 이동, `[OZ MONITOR]`/`[김비서]` 제목, 이전 로그 제거, 실제 파이프 연결/끊김 표시, 전략 설정의 SPECIAL 전용 버튼 7개와 상태, 선택한 SPECIAL 로그만 표시. 기존 `test_ui_slots.py` 18건과 `test_module_diagnostics.py` 6건도 각기 통과했다. 시험에서 실제 텔레그램 전송·네트워크 연결은 하지 않았다.

옛 `Part1/audit/test_oz_trigger_profiles.py::ControlTriggerSlots` 3건은 격리 시험 폴더에 필요한 `event_host.py` 등을 복사하지 않는 기존 시험 구성 때문에 실패한다. 수정본29에서도 동일한 3건 실패를 확인했다. 이번 화면의 실제 Tk 검증은 새 시험으로 수행했다. 그 기존 시험 파일은 수정본29과 SHA256이 같다.

Part1 무결성 체인 `51-module-status-navigation`에 5개 소스 변경을 등록하고 `build/part1_immutable_sha256.json`을 재생성했다. 새로운 무결성 오류 0건이며 이전 6건은 `검증결과/module_status_navigation/integrity.json`에 보존했다.
