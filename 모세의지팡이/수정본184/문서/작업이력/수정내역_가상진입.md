# B — Part2 가상 진입·진행 화면·데이터 구축 전용

A 로그 복원 후 같은 수정본30에서 구현했다. 수정본29 소스·설정 216개 보존 해시가 모두 같다. 실제 텔레그램 전송과 신규 MT5 녹화는 하지 않았다. EA·지표·Wire·스키마는 변경하지 않았다. 사용자 확인값 XAUUSD+ point=0.01만 수정본30의 `Part1/program/config.txt`에 `POINT_XAUUSD+=0.01`로 추가했다. 기존 전략 판정식·문구·임계값은 변경하지 않았다.

## 사용법

기존 BACKTEST CONTROL을 열고 종목·기간·전략을 선택한다. **알림 온리**가 기본값이며 기존 알림만 생성한다. **가상 진입**을 선택하면 같은 알림을 만든 뒤 녹화 OHLC/HMA와 알림의 OZ B0 메타데이터로 성과를 사후 계산한다. 스프레드는 MT5 포인트 단위이며 종목별 마지막 입력값을 보관한다. 결과 보기에서 전략·손익비별 표, 알림 CSV·성과 CSV·거래별 CSV를 연다.

**데이터 구축**을 체크하면 구축만 하고 백테스트를 실행하지 않는다. 기본은 없는 조각만 구축한다. 하위 **기존 데이터도 다시 녹화(검증 후 교체)**를 켜면 전체 기간을 재녹화하되 기존 파일은 새 조각 검증 성공까지 보존한다. 데이터 구축 체크를 끄면 없는 조각을 자동 구축한 다음 백테스트한다. 새 녹화는 월 조각 안내·예상 시간·용량 확인을 거친다. WATCH 거래시간 버튼 비활성화 규칙도 유지했다.

CLI는 Part2에서 다음처럼 실행한다. 날짜는 UTC이며 종료일 미포함이다. 새 녹화가 필요한 경우 계획을 확인하고 `--yes`를 추가한다.

```text
python -m event_backtest run --symbol XAUUSD+ --start 2025-09-01 --end 2025-09-08 --mode BAR --strategies SPECIAL1 --result-mode VIRTUAL_ENTRY --spread-points 0
python -m event_backtest run --symbol XAUUSD+ --start 2025-09-01 --end 2025-10-01 --mode BAR --build-only
```

두 번째 명령에 `--rebuild --yes`를 추가하면 승인한 기간을 다시 구축한다. 기존 조각을 재사용하는 경우 MT5가 실행되지 않는다. 결과는 공용 창고의 `runs/<실행 ID>/result.json`과 CSV에 저장한다. 경로는 창고 루트 기준 상대 경로다.

## 가상 진입 규칙과 데이터 흐름

알림 CSV → 기존 CaptureInputs/STAFF 녹화 복원 → VirtualEntry 사후 계산 → 같은 run의 CSV/result.json 순서다. 전략을 다시 평가하거나 HMA/B0를 재계산하지 않는다. OZ가 이미 판단한 `true_b0_price/time`을 출력 메타데이터와 CSV의 `b0_price/b0_time`으로 전달했다. 기존 DuckDB alerts에 이 두 메타데이터 열을 추가했다.

- 알림 이후 새 TF 봉에서 매수 시가>HMA6, 매도 시가<HMA6일 때 진입한다. 같은 시각에 이미 시작한 봉에는 소급 진입하지 않는다. 조건이 안 맞으면 대기한다.
- 진입 전 HMA6/17 역크로스가 나면 패스한다. 같은 봉에서 역크로스와 진입 조건이 함께 맞으면 역크로스 패스가 우선이다.
- 기존 OZ의 방향별 B0 가격을 손절가로 사용한다. 손절 폭은 절댓값이며 0이면 패스한다.
- 손익비 1.0~5.0을 0.5 간격으로 각각 독립 계산한다. 진입 봉부터 확정된 1분봉 고저를 사용하며 같은 1분봉의 손절·익절 동시 도달은 손절이다.
- 매수 스프레드는 진입가에 더하고 매도 스프레드는 판정용 1분봉 고저에 더한다. 수수료는 제외한다.
- 미청산 진입은 승률·평균 R·합계 R의 청산 표본에서 제외하고 별도 집계한다. 기간 끝까지 진입 조건이 없었던 알림은 `waiting`으로 별도 표시한다.
- M1 기반 청산 시각은 도달한 **1분봉의 시작 시각**이다. 실제 틱 도달 시각을 추정하지 않는다. 확정되지 않은 마지막 M1 고저는 사용하지 않는다.
- 동일 신호가 여러 수신자에게 전달된 경우 가상 거래는 signal_id·전략·종목·TF당 한 번 계산한다. 방향/TF가 없는 등록·상태 안내는 진입 대상에서 제외하고 건수를 기록한다.
- point는 녹화 메타데이터 우선, 없으면 config 종목별 값이다. point·HMA6/17·OZ B0가 없으면 명시 오류로 중단한다. 다른 종목의 point는 추정하지 않았다. result.json에 사용한 point·출처·스프레드 포인트/가격을 기록한다.

## 진행 화면과 MT5 수명주기

상단 한글 단계, 구축 조각 게이지와 현재 단계(MT5 추출→차분 변환→복원 검증), 백테스트 게이지를 분리했다. 구축할 조각이 없으면 구축 게이지는 100%다. 구축 전용 완료 시 백테스트 게이지도 100%이며 실제 백테스트는 실행하지 않는다. 재생은 진행률 기반 남은 시간을 표시하고 추정 불가능한 단계는 경과 시간을 표시한다.

화면 로그에는 단계 변경·경고·오류의 한글 요약만 표시한다. 생성 틱 등 경고는 별도 영역에 남긴다. 원시 진행 이벤트는 `runs/<실행 ID>/progress.jsonl`, GUI 프로세스 출력은 같은 실행 폴더의 `console.log`에 보관하며 상세 로그 버튼으로 연다. 결과 화면에는 구축 조각별 새로 구축/기존/실패 상태도 표시한다.

다음 조각 실행 전에 같은 MT5 실행 파일의 프로세스 종료를 기다린다. `NATIVE_TESTER_DID_NOT_START`에 한해 종료 확인 후 1회 재시도한다. 계속 실패하거나 기존 프로세스가 종료되지 않으면 열린 MT5 확인 안내를 내고 완료 조각을 보존한다. 이번에는 이 분기를 모의 실행으로 검증했으며, 실제 MT5 재녹화·재시도 실측으로 주장하지 않는다.
