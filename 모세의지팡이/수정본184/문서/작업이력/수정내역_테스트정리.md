수정본46을 복사해 수정본47을 만들었다. 이전 `검증결과`는 복사하지 않았다. 엔진·전략·EA 동작·Wire 형식·웹 기능은 바꾸지 않았다. 현재 구조에서 실행할 수 없는 과거 검증만 기본 pytest 대상에서 빼고 원본 테스트 파일은 보존했다. 다음 수정본은 이 `pytest.ini`를 그대로 이어받는다.

## 기본 실행

수정본47 루트에서 `python -m pytest`를 실행하면 `tests`와 `Part3/tests`를 수집한다. Part1의 옛 `audit`와 Part2의 일반 회귀 4묶음은 현재 실행 경로의 기본 게이트에서 제외한다. `pytest.ini`가 세 레거시 디렉터리를 추가로 무시하고 내부 구조를 고정한 시험 6개만 개별 제외한다. 특정 파일을 명시해 실행하면 진단용으로 다시 사용할 수 있다. 테스트 파일은 삭제하지 않았다.

## 제외하지 않은 실패와 시험 보수

`tests/test_data_selection.py::test_public_runner_final_export_stays_in_run_directory`는 아직 유효한 결과 위치 검사다. 시험용 `run_chunk` 가짜 반환값에 현재 worker 계약의 `task_start`, `task_end`, `warmup_bundles`, `elapsed_seconds`, 처리 구간 필드를 채웠다. **원래의 결과 위치·CSV 내용 검사는 줄이지 않았고**, 개별 재실행에서 통과했다.

EA 빌드 해시 시험은 제외하지 않았다. 처음에는 `STAFF_Wire_Schema.mqh`의 기록값 `b184c669…`과 현재 MT5 `.mq5/.mqh` 소스 해시 `238f50f0…`이 달라 실패했다. 사용자가 BTCUSD를 기본 대상에서 뺀 것은 의도한 설정임을 확인해 주었다. 이에 생성 헤더의 **빌드 해시 한 줄만** 현재 소스 해시로 갱신했다. EA의 `InpSymbols`와 다른 소스, 열 목록, schema_id `0x379D2170`은 유지했다. 생성기의 출력과 대조해 헤더의 차이가 해시 한 줄뿐임을 확인했다. 이번 작업에서 `.ex5`를 컴파일하거나 MT5 설치 파일을 바꾸지는 않았다. 다음 Part2 녹화는 기존 자동화가 현재 소스를 동기화하고 컴파일한다.

Part1 무결성 체인에 `74-ea-build-hash-sync`를 등록하고 `build/part1_immutable_sha256.json`의 해당 헤더 및 변경 이력 항목을 갱신했다. 체인 진단은 수정본46과 같이 기존 8건이며, 이번 헤더에 관한 새 진단은 0건이다. 수정본46 대비 Part1 `program`의 소스·설정 109개 중 변경은 이 헤더 1개뿐이다.
