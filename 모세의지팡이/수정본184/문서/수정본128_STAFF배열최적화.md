# 수정본128 최적화 1 — STAFF 시간봉 배열 내보내기

수정본127을 그대로 복사해(검증결과 제외) 수정본128을 만들었습니다. 수정본127 측정에서 가장 큰 병목이던 STAFF의 시간봉 배열 내보내기(`Part1/program/THE STAFF OF MOSES.py` `_publish_arrays`)를 줄였습니다. LIVE와 백테스트가 같이 쓰는 코드이며, 내보내는 값은 그대로입니다.

## 결과

|---|---|

실행 전체 시간은 같은 컴퓨터에서도 실행마다 크게 흔들려서(127 이틀치가 17초~32초), 고친 부분을 번갈아 재는 방식으로 효과를 확인했습니다. 수정본127 측정의 자료 읽기 시간(묶음당 약 11ms) 기준으로 약 15~20%가 줄어든 셈입니다.

## 바뀐 것

1분봉 갱신의 약 80%는 마지막 줄만 바뀌는 ROW 갱신입니다. 이전에는 ROW 갱신마다 시간봉 배열 전체에서 MT5 빈값(EMPTY_VALUE·무한대)을 찾고, 새 줄에 빈값이 있으면 배열 전체를 복사해 고친 뒤, 불변 배열로 만들려고 한 번 더 통째로 복사했습니다.

| 위치 | 변경 |
|---|---|
| `_SnapshotEntry` | "정리된 값" 표시(`clean`) 추가. 내보내기 함수가 만든 스냅샷만 표시. 저장된 상태에서 복원한 스냅샷은 표시하지 않음 |
| ROW 갱신 (`_receive_v2`) | 표시가 있으면 새 줄만 정리하고 이어 붙임. 이전 줄은 이미 정리된 값이라 배열 전체를 정리한 것과 결과가 같음. 표시가 없으면(복원 직후) 지금처럼 전체를 정리 |
| `_publish_arrays` | 정리를 `_clean_values` 하나로 모음. 이미 정리된 배열은 다시 검사·복사하지 않음 |
| 지표 유효 표시 | 마지막 줄의 유한 여부를 한 번에 계산한 뒤 지표마다 열을 확인. 규칙(필요한 열이 하나라도 없거나 유한하지 않으면 무효)은 같음 |
| HEARTBEAT | 값이 그대로이므로 표시도 그대로 이어감 |

묶음이 거부되어 되돌릴 때는 스냅샷 객체가 통째로 되돌아가므로 표시도 함께 되돌아갑니다.

## 시험

새 시험 `tests/test_staff_row_clean128.py`:

- 새 줄에 MT5 빈값·무한대·정상값·NaN이 들어와도 결과가 배열 전체를 정리한 것과 바이트 단위로 같음, 유효 표시가 원래 규칙과 같고 순서도 같음, 배열은 불변
- 빈값이 남은 상태(예: 예전 복원 지점)에서 복원하면 다음 ROW 갱신 때 전체를 정리하고, 그다음부터 빠른 길
- HEARTBEAT는 표시와 배열을 그대로 둠
- 거부된 묶음은 표시까지 되돌림
- 무작위로 빈 열을 넣은 마지막 줄에서 유효 표시가 원래 규칙과 같음
