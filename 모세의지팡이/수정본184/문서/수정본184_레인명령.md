## 레인 계산 방식

- 함께 쓰는 것(읽기 전용): 녹화 읽기, STAFF 스냅샷.
- 실행마다 따로: 엔진 판단, 가상진입, 결과 기록(`runs/<실행 ID>/`).
- 그래서 각 조합의 결과는 그 조합을 혼자 돌린 결과와 같다(161·171 레인 그대로, 시험으로 확인).
- 설치본 안내(6장)와 제미나이 지시문에 같은 내용을 적었다.
- 보고 규칙: 트리거만 레인으로 묶고 전략은 하나씩 돌렸다면 그렇게 적는다.

## Part2: 시나리오 `lanes`

```json
{"lanes": [{"strategy": "SPECIAL2", "trigger": "무지성 올존"}, {"strategy": "SPECIAL5"}],
 "virtual_entries": {"SPECIAL2": {...}}}
```

- 레인 하나가 실행 하나다.
  - 그 전략 하나를 혼자 돌린 시나리오와 같다: 트리거, 그 전략의 가상진입, 그 전략의 거래시간.
  - 트리거를 빼면 전략 자신의 트리거다.
  - `virtual_entries`에 없는 전략은 레시피 가상진입 값을 쓴다.
- 첫 레인이 이 요청 자신의 실행이다. `strategies`는 비우거나 첫 전략만 둔다.
- 거절하는 것(메시지에 할 일을 적음)
  - 목록이 아님 / 칸이 틀림 / 없는 전략 / ALL·WATCH
  - OZ 트리거가 없는 전략에 트리거 / 없는 트리거 / 같은 조합 두 번
  - 데이터 구축·WATCH 명령과 함께 / `virtual_bases`·`trigger_variants`와 함께 / 전략 조건을 고친 시험
  - lanes에 없는 전략의 정책 / 알림만에서 정책 / 정책 하나를 모든 레인에
- **자동 나누기**
  - 한 번에 함께 재생하는 실행 수는 `max_lanes`다(설정 기본 36, 1~200). 명령줄 `--max-lanes`로도 준다.
  - 그보다 많으면 묶음으로 나눠 차례로 돈다. 묶음마다 녹화를 다시 읽는다.
  - 진행에 "묶음 2/4"가 나온다(`LANE_GROUP` 사건). 진행 화면 단계도 "백테스트 중 (묶음 2/4)"다.
  - 정지하면 돌던 묶음에서 멈추고 다음 묶음은 시작하지 않는다.
- **기록**
  - 첫 실행 폴더의 `lanes.json`: 묶음 수, 묶음마다 시작·끝 시각, 실행마다 전략·트리거·묶음·상태.
  - 다른 실행 폴더의 `lane.json`: 첫 실행을 가리킨다.
  - 모든 실행의 `tested_with`: 같은 요청의 다른 실행 전부(묶음이 달라도).
- 알림 재생 공유(154)도 레인마다 그대로다. 혼자 돌린 실행과 재생 키가 같다.

## Part3: `cli.py lanes plan|run|status|stop|report 계획.json`

| 동작 | 하는 일 |
|---|---|
| `plan` | 실행·묶음 수, 쓰는 녹화 구간, 빠지는 구간. 아무것도 실행하지 않는다 |
| `run` | 끝나지 않은 실행만 요청 하나로 시작. 녹화 승인은 하지 않는다(터미널이면 사용자에게 묻고, 아니면 기다린다) |
| `status` | 몇 번째 묶음인지, 첫 묶음이 끝난 뒤 남은 시간 |
| `stop` | 돌고 있는 요청을 멈춤 |
| `report` | 결과 표(아래), `<계획>.report.md`에도 저장 |

- **계획 파일 칸**
  - 필수: `symbol`, `start`, `end`, `mode`, `result_mode`, `strategies`
  - 선택: `triggers`, `spread_points`, `available_only`(기본 true), `virtual_entries`, `max_lanes`, `cores`, `special_settings`
  - 모르는 칸·빠진 칸·잘못된 값은 고칠 방법과 함께 거절한다.
  - 실행 수 = 전략 × 트리거.
  - 시험 전략(Test_SPECIAL)과 스페셜·내 전략은 한 계획에 섞지 않는다.
- **다시 돌리기**
  - 계획 파일 옆 `<계획>.lanes.json`에 요청(실행 ID)을 남긴다.
  - 같은 계획으로 `run`을 다시 하면 끝난 실행은 건너뛴다. 계획을 고치면 새 계획이다.
  - 돌고 있으면 거절한다.
  - 사용자가 지운 요청은 막지 않는다.
- **생성 전략 여러 개**
  - 작업 명령이 파일마다 해시를 실어 보낸다.
  - `Part3/backtest.py`가 모두 등록한다. 실행 코드 해시에 모든 파일이 들어간다.
- **결과 표**
  - 조합×RR마다: 거래 수, 평균 R(스프레드 뺀 값), t, 승률, 기간 앞 70% → 뒤 30% 평균 R, 비용 2배.
  - 표 세 개: 평균 R 상위 10, 꾸준한 조합 10(거래 30건 이상, 앞·뒤 모두 플러스, t 순), 실행마다 가장 나은 RR.
  - 스프레드 0이면 경고를 낸다.

## 제미나이 (Part3 AI)

- **새 명령 칸**
  - `triggers`: 비교할 올존 트리거 목록
  - `filenames`: 생성 전략 여러 개
  - 새 동작 `REPORT`: 결과 표
- **레인이 되는 요청**: START 하나가 아래 경우면 레인 계획 하나가 된다.
  - 트리거 목록이 있다.
  - 가상진입에 전략이 여러 개다.
  - 생성 파일이 여러 개다.
  - 트리거 없이 알림만으로 여러 SPECIAL을 고르면 전처럼 한 엔진이다.
- **스페셜 설정**
  - 각 스페셜은 화면 저장 설정을 그대로 쓴다: 트리거 목록이 없을 때의 트리거, 거래시간.
  - 그래서 레인 하나는 그 전략을 화면에서 혼자 돌린 것과 같다.
- **가상진입**
  - 여러 전략이면 전략마다 레시피 값을 쓴다.
  - 진입·손절·기준 프레임 변경은 전략 하나일 때만 된다. 기준 프레임은 그 트리거 실행 모두에 적용된다.
- **계획 보관과 미리보기**
  - 계획은 창고 `runs/lanes/<16자>.json`에 둔다. 같은 요청을 다시 하면 끝난 실행을 건너뛴다.
  - 미리보기에 "함께 돌릴 실행: N개"와 실행마다 전략·트리거가 나온다.
  - 모두 끝난 요청을 시작하면 "결과 표를 요청하세요"라고 답한다.
- **REPORT**
  - 대상은 고른 작업, 없으면 가장 최근에 끝난 작업이다.
  - 제미나이가 시작한 요청은 계획 전체의 표를 보여 준다.
  - 다른 레인 요청은 그 요청의 실행들, 보통 실행은 그 하나의 표다.
  - 연구 대화에서도 바로 보여 준다.
- **지시문**: 같은 규칙을 네 곳에 적었다.
  - `common_ai/security.py`(외부 모델이 실제로 받는 규칙), `backtest_commands.py`, `research_backtest.py`
  - `research_interpreter.py`에는 한 줄
  - 작업 목록의 `source`("레인 N개: …")도 모델에게 보낸다.
- **순차 작업**(`backtest_sequences`): 레인 요청의 생성 파일을 모두 확인한다.

## 결과가 달라지는 것

- 엔진 결과는 그대로다. 레인 실행 결과는 혼자 돌린 결과와 같다(시험).
- **제미나이 가상진입 여러 전략**
  - 전에는 "전략 1개만 실행할 수 있습니다"라고 물었다.
  - 이제 전략마다 레시피 가상진입으로 함께 돌린다.
  - 그 질문을 고정하던 `tests/test_virtual_ai113.py` 시험을 새 동작으로 바꿨다.
- 결과 화면 데이터의 비교 실행 행에 `strategy`가, 결과에 `strategy`가 붙었다.
- 작업 상태에 `lanes`가 붙었다. 레인 요청의 `source`는 "레인 N개: 전략…"이다.
- 진행 단계 이름은 묶음이 둘 이상일 때만 "(묶음 2/4)"가 붙는다.
