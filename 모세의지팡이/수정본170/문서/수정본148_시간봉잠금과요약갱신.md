# 수정본148: 칸별 시간봉 잠금과 AI 초안 요약 갱신

사용자 요청: 수정본147 검토에서 확인한 세 문제를 다음 수정본에서 수정한다.
수정본147을 복사해 시작했으며 이전 검증결과와 캐시는 복사하지 않았다.

## 수정한 동작

1. 기존 진입 제한의 조건 종류를 바꿔도 그 칸의 시간봉은 유지된다.
   - SPECIAL9 기준 2분의 20분 추세 제한을 이평 정배열로 바꾸면, 20분 이평 정배열로 정상 실행한다.
   - 이평 종류·기간·배수·봉 기준은 계속 편집할 수 있다.
2. 같은 종류의 다른 칸에서 시간봉을 가져올 수 없다.
   - SPECIAL6의 HMA 정배열 칸에 다른 EMA 칸의 환경 프레임을 넣으면 화면 외 요청·AI·시나리오·저장값 복원에서 거부한다.
   - 새로 추가한 조건·제한은 전략 시간봉(SIGNAL)을 쓴다.
   - 기준 프레임 변경은 기존과 같이 전략과 진입의 모든 값을 해당 기준의 레시피 값으로 다시 채운다.
3. AI 연구 초안의 핵심 요약이 최신 검증 결과를 따른다.
   - 편집 즉시 이전 시간봉 숫자를 숨기고 검증 중 상태를 표시한다.
   - 저장·검증에 성공한 최신 응답만 실제 시간봉을 갱신한다.
   - 이전 편집의 늦은 응답·검증 실패·통신 오류가 이전 숫자를 복원하지 않는다.
   - 여러 전략 시간봉·환경 프레임 목록과 알 수 없는 생성 파일의 예비 표시를 유지한다.

## 구현과 데이터 흐름

- `Part2/event_backtest/virtual_defaults.py`
  - 채워진 정책의 조건·제한 행에 원래 레시피 위치인 `recipe_index`를 부여한다. 레시피 파일에는 쓰지 않는다.
  - 종류별 시간봉 집합 검사인 `_frame_fields`를 제거하고, 각 원래 칸의 시간봉을 정확히 비교한다.
  - 기존 칸은 조건 종류를 바꿔도 같은 번호와 시간봉을 유지한다. 삭제하면 번호도 없어지고, 새 행은 번호 없이 SIGNAL만 쓴다.
  - 중복·범위 초과·순서가 바뀐 칸 번호를 거부한다. 손절·ATR은 각각의 레시피 시간봉과 정확히 비교한다.
- `Part2/event_backtest/virtual_contract.py`
  - 공통 정규화와 JSON schema에서 선택적 정수 `recipe_index`를 보존한다. 조건 판정 자체의 필드는 그대로다.
  - 입력 사본에서 번호를 분리하고 정규화 후 다시 붙인다. 호출자의 입력은 수정하지 않는다.
- `Part2/event_backtest/ui_model.py`
  - 예전 저장값에 칸 번호가 없으면, 같은 목록 위치·종류·시간봉을 확인할 수 있는 행만 복원한다.
  - 대응이 모호하거나 개별 시간봉을 바꾼 예전 정책은 복원하지 않고 레시피 값으로 시작한다.
  - 이 복원은 저장값을 읽는 경로에만 있다. API·AI 입력의 새 행을 기존 칸으로 추측하지 않는다.
- AI 안내문 세 곳
  - 기존 행의 번호·시간봉 보존과 새 행의 SIGNAL 규칙을 전달한다.
- `Part3/lab/ai/research_editor.py`, `research.py`
  - 기존 공통 시간봉 계산을 재사용해 검증된 초안의 시간봉을 저장 응답에 전달한다.
- `Part3/web/ai_editor.js`, `ai_chat.js`
  - 현재 편집 버전에 해당하는 응답만 요약을 갱신한다. 브라우저에 전략 시간봉 판정 계산을 새로 만들지 않았다.

Part1·레시피 파일·settings는 변경하지 않았다. 실제 전략 조건과 확정봉·진행봉 판정은 변경하지 않았다.
제거했던 143의 칸 기억, 145의 표시 보정, 개별 시간봉 선택 UI도 다시 넣지 않았다.
매뉴얼의 기존 시간봉 선택 규칙은 그대로여서 PDF는 다시 제작하지 않았다.
