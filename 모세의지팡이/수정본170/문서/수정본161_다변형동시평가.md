## 방식: 녹화 읽기·STAFF는 한 번, 엔진은 기준 프레임마다

처음에는 변형을 서로 다른 이름으로 한 엔진에 올리는 방식을 생각했다. 하지만 버렸다.
- 전략 이름(namespace)이 감시 ID·신호 ID에 들어가서, 신호 ID가 혼자 돌린 결과와 달라진다.
- OZ·SWEEP 같은 공용 상태 처리기를 변형들이 함께 써서, 서로 영향이 없다는 것을 따로 증명해야 한다.

대신 재생 조각 하나가 "레인" 여러 개를 돌린다.

| | 함께 씀 | 레인(실행)마다 따로 |
|---|---|---|
| 녹화 읽기 | ○ | |
| STAFF 수신·검사·게시 | ○ (레인들이 쓰는 시간봉의 합집합을 게시) | |
| 엔진(처리기·전략·사실) | | ○ 혼자 돌릴 때와 같은 이름·같은 구성 |
| 입력 선별(select_inputs) | | ○ 혼자 돌릴 때와 같은 8개 묶음 단위, 레인마다 자기 직전 스냅숏 |
| 알림 기록·결과 폴더·실행 기록 | | ○ 실행 ID·알림·가상진입·결과가 각자 하나의 완전한 실행 |

결과가 같다는 근거는 셋이다.
- STAFF는 시간봉마다 따로 처리한다. 게시하는 시간봉을 합집합으로 넓혀도 각 시간봉의 스냅숏 내용은 같다.
- 게시 시간봉 제한은 원래부터 "제한해도 모든 시간봉을 게시한 결과와 같아야 하고, 아니면 전체 게시로 다시 돈다"는 원칙이다(131). 그래서 합집합은 그 사이에 있다.
- 묶음 선별은 레인마다 혼자 돌릴 때와 똑같이 한다.

## 바꾼 것

### Part2

- `runner.py`
  - `_run_lanes`: 재생 조각 하나가 레인 여러 개를 돌린다. 레인 1개는 지금까지의 단일 실행과 같다(공통 경로). TICK은 지금처럼 입력을 하나씩 넘긴다.
  - `run_chunk`·`_run_chunk`: 레인이 없으면 지금처럼 결과 사전 하나를 돌려주고, 레인이 있으면 레인별 결과 목록을 돌려준다.
  - `run_many`: 여러 실행을 함께 재생한다. `run(s)`는 `run_many([s])`의 첫 결과다.
    - 실행마다 기록·재생 키·154 재사용을 따로 정한다. 이미 끝난 재생이 있는 실행은 다시 재생하지 않는다.
    - 실패하면 모든 실행을 실패로 기록한다.
    - 대표가 아닌 실행 폴더에는 대표 실행을 가리키는 `lane.json`을 남긴다.
  - 함께 재생하려면 종목·기간·재생 방식·명령 등 재생을 정하는 칸(`SHARED_REPLAY`)이 같아야 한다.
- `settings.py`
  - 시나리오에 `virtual_bases`(비교할 기준 프레임 목록, 기본 `[]`)를 둔다. 가상진입에서만, 명령 없이만 받는다.
  - `variant_scenarios(s)`: 기준 프레임마다 "그 기준 하나로 가상진입한 시나리오"로 펼친다. 첫 실행이 요청의 실행 ID를 갖는다.
- `virtual_defaults.py`
  - `target_bases`: 고를 수 있는 기준 중 서로 다른 둘 이상인지 검사하고 작은 시간봉부터 정렬한다.
  - `base_variants`: 기준마다 레시피의 진입 설정·전략 조건을 그 기준으로 옮긴 값을 만든다. 144 규칙대로, 기준 프레임을 바꾸면 손으로 고친 칸은 버리고 레시피 값으로 다시 채운다.
- `workflow.py`: 기준 프레임이 여러 개면 `run_many`, 아니면 지금처럼 `run`. 끝난 실행마다 결과 분석을 한다.
- `ui_model.py`: 화면 요청의 `virtual_bases`를 시나리오로 넘긴다.
- `system.py`: 쓰기 제한(`restrict_writes`)이 실행 폴더 여러 개를 받는다.

## 검증

### 실제 녹화: 따로 실행 vs 함께 실행 (금 2026-09 한 달 BAR, 가상진입, 14코어)

같은 녹화를 임시 창고 두 곳에 복사했다. 한 곳에서는 기준 프레임마다 따로 실행하고, 다른 곳에서는 함께 실행했다. 같은 창고에서는 154 재사용 때문에 따로 실행이 재생되지 않으므로 창고를 나눴다. 기준마다 알림 행(실행 ID 제외), 가상진입 성과 요약, 거래 목록 전체를 해시로 비교했다.

| 전략 | 기준 프레임 | 알림 | 거래 | 알림·요약·거래 | 따로 | 함께 |
|---|---|---|---|---|---|---|
| SPECIAL9 | 1·2·3·5분 | 147·67·58·31 | 1323·603·522·279 | 모두 같음 | 192초 | **88초 (2.2배)** |
| SPECIAL7 (OZ) | 1·2·5분 | 0·14·6 | 0·126·54 | 모두 같음 | 160초 | **87초 (1.8배)** |

시간은 재생과 가상진입 계산, 결과 분석 전까지를 모두 포함한 요청 전체다.

## 남은 것·주의

- SPECIAL1~6은 기준 프레임을 바꿀 수 없어 이 비교를 쓸 수 없다. SPECIAL2 같은 전략의 변형(예: 터치 시간봉 하나씩)은 새 규칙이 필요하다.
- 함께 비교할 때는 기준마다 레시피 값으로 시험한다. 가상진입 칸에서 손으로 고친 값은 적용되지 않는다(144 규칙).
- 함께 도는 실행이 처리 중 실패하면 그 폴더에는 결과 파일 없이 `lane.json`만 남는다. 실행 목록에는 나오지 않고, 대표 실행에 오류가 표시된다.
