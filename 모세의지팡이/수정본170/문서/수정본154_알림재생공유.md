# 수정본154: 가상진입 설정만 바꾼 실행은 알림 재생을 다시 하지 않기

수정본153을 별도 폴더로 복사해 작업했다. 이전 검증결과는 복사하지 않았다.

## 요청

남은 최적화 1번이다. 진입·손절·ATR만 바꿔 가며 보는 시험이 재생을 한 번만 하게 한다. 사용자는 주로 70개월 전체로 돌린다.

## 동작

`runner.run`이 재생 조각을 만든 뒤 "재생 입력"으로 키를 계산한다. 결과 DB에 같은 키로 끝난 실행이 있으면 재생을 건너뛴다. 그 실행의 알림을 새 실행 번호로 복사하고 가상진입만 계산한다. 같은 키의 실행이 없으면 지금처럼 재생한다.

재사용하는 실행의 조건:
- 상태가 완료(COMPLETE)다. 중단·실패한 실행은 쓰지 않는다.
- 코드 해시와 설정(`config.txt`) 해시가 같다.
- 실행 폴더가 남아 있다. 화면 목록에서 지운 실행은 쓰지 않는다. 화면의 삭제는 폴더만 지우고 DB 행은 남기기 때문에 폴더로 확인한다.
- 결과 DB에 그 실행이 내보낸 알림 행이 모두 있다.
- 같은 키 실행이 여럿이면 가장 늦게 끝난 것을 쓴다. 키가 같으면 알림이 같다.

### 재생 입력 (키)

키에는 코드 해시, 설정 해시, 재생 조각마다의 기간·준비 시작·녹화 목록·전송 방식, 시나리오가 들어간다. 시나리오에서는 재생이 읽지 않는 칸만 뺀다.

| 빼는 칸 (`runner.AFTER_REPLAY`) | 이유 |
|---|---|
| `virtual_entry` | 진입 방식·조건·진입 제한·손절·ATR. 재생 코드(`runner._run_chunk`, `base_frames.engine_plugins`, Part1 엔진)는 읽지 않는다 |
| `spread_points` | 가상진입 가격에만 쓴다 |
| `result_mode` | 알림 온리 ↔ 가상진입. 재생은 같다 |
| `_run_id` | 실행 자신의 번호 |

- 기준 프레임은 `base_frames`, 전략 조건 편집은 `virtual_strategy` 칸으로 따로 들어간다. 그래서 이 둘을 바꾸면 다시 재생한다.
- 나중에 시나리오에 새 칸이 생기면 기본은 "다시 재생"이다.
- 코어 수가 바뀌면 조각 나누기가 달라지므로 다시 재생한다.
- 코드 해시는 프로그램 전체 파일이다. 그래서 수정본이 바뀌면 이전 기록은 쓰지 않는다. 레시피 파일 안의 가상진입 칸을 직접 고쳐도 다시 재생한다.

### 결과와 화면

- 결과에 `replay_reused_from`(출처 실행 번호), `replay_key`, `alert_rows`, `completed_at`을 넣었다.
- 재사용한 실행의 `chunks`·`alert_statistics`·`processed_periods`는 출처의 재생 결과다.
- 경고 목록에 한 줄을 넣는다: "알림 재생: 같은 조건으로 끝난 실행의 결과를 썼습니다."
- 진행 화면에도 한 줄을 띄운다: "같은 조건으로 끝난 실행의 알림 재생 결과를 씁니다".
- 결과 DB 표 구조는 바꾸지 않았다. 배포본 136이 같은 DB에 열 이름 없이 넣기 때문이다. 키는 기존 metadata JSON에 들어간다.

## 검증

### 로직 시험 (`tests/test_replay_reuse154.py`, 12개 통과)

실제 DuckDB 결과 DB를 쓰고, 재생 작업자는 호출을 기록하는 가짜로 바꿨다.

| 확인 | 내용 |
|---|---|
| 진입 설정만 바꿈 | 손절 배수·ATR 기간·스프레드를 바꾼 실행은 재생 0회, 알림 CSV·행 수·통계·처리 구간이 출처와 같음, 가상진입은 바꾼 설정으로 계산 |
| 알림 온리 ↔ 가상진입 | 같은 전략의 알림 온리 실행도 재사용, 가장 최근 실행을 출처로 씀 |
| 다시 재생해야 하는 경우 8가지 | 기준 프레임, 전략 조건 편집, 거래 시간 필터, 기간, OZ 평가 범위, 코어 수, 설정 파일, 코드. 모두 재생함 |
| 쓰면 안 되는 출처 | 중단된 실행, 목록에서 지운 실행, 알림 행이 빠진 실행 |
| 키 | 시나리오의 모든 칸 중 위 4칸만 키를 바꾸지 않음. 조각의 기간·준비 시작·녹화·전송은 키를 바꾸고, 실행 번호·폴더·창고 위치는 바꾸지 않음 |

기존 `tests/test_worker39.py`의 가짜 결과 DB에 "재사용할 실행 없음"(`finished_replay`)을 추가했다. 시험 내용은 그대로다.

### 실제 녹화 (금 2026-09-07 ~ 10-01, SPECIAL8, 14코어)

| 실행 | 설정 | 재생 | 전체 |
|---|---|---|---|
| A (창고1) | 레시피 진입 | 25.8초 | 30.3초 |
| B (창고1) | 손절 ATR 2배, 스프레드 3 | **재사용(A)** | **4.5초** |
| C (창고2, 새 창고) | B와 같은 설정 | 26.0초 | 30.5초 |
| D (창고1) | 기준 프레임 1시간 | 26.6초 (다시 재생) | 30.4초 |

- B와 C는 알림(725행), 거래(6,525행), 요약 CSV가 모두 같았다.
- A와 B는 알림은 같고, 손절이 바뀌어서 거래가 다르다.
- C는 다른 창고에서도 A·B와 키가 같았다. 키에 경로가 들어가지 않는다는 뜻이다.
- 70개월은 직접 재지 않았다. 재사용하면 재생(10~20분 추정)이 빠지고 녹화 검증·준비와 가상진입(30초 안팎)만 남는다.

기록: `검증결과/revision154/measurement/real/`, 도구 `검증결과/revision154/measurement/tools/`
