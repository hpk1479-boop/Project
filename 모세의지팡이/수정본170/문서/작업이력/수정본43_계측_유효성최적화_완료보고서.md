## 2. ④ 계측 래퍼

기존에는 소비자 호출마다 `processor.setdefault(name, {'ns': 0, 'calls': 0})`의 기본 딕셔너리를 생성하고 누산 항목을 조회했습니다. 새 래퍼는 **첫 호출의 `finally`에서 한 번 확보한 누산 객체를 이후 호출에서 재사용**합니다.

시간 측정은 끄지 않았습니다. 매 호출의 시작·종료 시계 조회, `ns`·`calls` 누산, 예외가 발생한 호출의 계측을 유지합니다. 소비자를 만들기만 하고 호출하지 않은 경우 통계 행을 생성하지 않으며, 통계 행의 최초 등록 순서도 유지합니다. 같은 이름의 기존 누산 항목이 있으면 그 항목에 더하고 실행별 딕셔너리는 분리됩니다.

4인자 소비자의 출력은 기존처럼 **`writer.note_emission()` → 엔진 `emit()` 순서**로 전달합니다. 알림 B0 가격·시각·등급·프로필·트리거·수신자 수집, Signal·TimerRequest 전달, 반환값, 원래 예외를 보존하는 검사를 추가했습니다. 타이머·알림 기능을 없애거나 계측하지 않은 통계를 0으로 위장하는 변경은 없습니다.

## 3. ⑤ 배열 검사 결과 공유

기존 `Board._frame_cache`의 입력 묶음 수명을 사용합니다. 새로운 전역 캐시나 영구 캐시는 만들지 않았습니다.

`('numpy_finite', symbol, tf, columns)` 키에 `(snapshot 객체, 검사 결과)`를 보관합니다. 동일한 스냅샷 객체인지도 확인합니다. `columns=None`은 **모든 행의 OHLC 네 열**, 열 번호 튜플은 **요구 지표의 마지막 행만** 검사합니다. 정상·비정상 결과 모두 재사용할 수 있어 반복되는 NaN 거부 검사도 줄어듭니다. 캐시가 없는 경량 Board 대역은 매번 전체 검사를 수행합니다.

건드리지 않은 판정은 다음과 같습니다.

- 피드 존재 여부, `STALE`·`UNAVAILABLE`·`RECONNECT`, 관측 후 30초 경과 여부는 호출할 때마다 확인합니다. 30,000ms는 허용하고 30,001ms는 거부하는 경계를 유지합니다.
- OZ는 최소 3행, 일반 시장 뷰는 비어 있지 않은 입력이라는 기존 조건을 유지합니다. 이 조건을 OHLC 캐시의 일부로 합치지 않습니다.
- 과거 봉의 OHLC 오류도 계속 거부하고 요청하지 않은 지표의 오류는 해당 요청을 막지 않습니다. 요구 지표 검사는 여전히 마지막 행만 봅니다.
- `Board.commit()`·health 변경·restore의 기존 캐시 폐기 동작을 이용합니다. 같은 Snapshot을 재전달하거나 다른 심볼이 갱신돼도 새 입력 묶음으로 넘기지 않습니다.

첫 성능 시도에서 빈 요구 지표 목록을 튜플 생성식으로 만드는 비용이 발견됐습니다. **두 번째 시도에서 기존 목록 생성식을 유지하고, 요구 열이 있을 때만 캐시 키용 튜플을 만들도록 수정했습니다.** 느려졌던 첫 구현은 포함하지 않았습니다. 첫 측정과 수정 후 측정을 별도 JSON으로 남겼습니다.

## 6. 구간 성능

650행 합성 입력, 각 경로 사전 실행 후 입력 수정본·새 수정본 순서를 AB/BA로 바꾸며 **7회 측정한 중앙값**입니다. 프로파일러는 사용하지 않았고, 별도 검사용 배열 호출 횟수 집계는 시간 측정과 분리했습니다.

| 측정 구간 | 수정본42 | 수정본43 | 시간 감소 |
|---|---:|---:|---:|
| 3인자 처리기 계측 래퍼 200,000회 | 0.096986초 | 0.076204초 | 21.43% |

OHLC 단독 조회의 작은 차이는 짧은 구간의 실행 변동 영향을 받습니다. 이 경로는 큰 개선보다 첫 시도의 추가 비용을 제거한 점이 중요합니다.

반복 조회 합성 묶음 하나에서 실제 `isfinite` 호출은 **28회 → 3회**였습니다. OHLC 전체 검사는 **11회 → 1회**, 요구 지표 행 검사는 **17회 → 2회**입니다. 이는 일반 뷰·원비 뷰·OZ 준비 판정과 EMA/원비 요청을 8회 반복한 특정 입력 흐름의 수치이며 모든 백테스트에서 같은 횟수가 줄어든다는 의미가 아닙니다.

**위 수치는 전체 백테스트 단축률이 아닙니다.** 실제 녹화 파일, 프로세스 시작·워밍업·디스크 읽기·SQL 저장을 포함한 전체 실행 시간은 측정하지 않았습니다. 이전 Fact42 개선율과 합산하거나 곱하지 않습니다.

검증 환경: Linux / Python 3.13.5 / NumPy 2.3.5 / pandas 2.2.3. 프로젝트가 지정한 pandas 3.0.1 환경과 다르며 의존성 파일은 변경하지 않았습니다. Windows·MT5·실제 DuckDB·실제 시장 녹화 입력에서의 전체 실행 검증은 미완료 항목입니다.

## 7. 변경 범위와 자료
