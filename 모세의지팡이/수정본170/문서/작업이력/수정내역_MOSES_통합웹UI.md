# MOSES 통합 웹 UI 1차 작업 — 수정본46

## 사용법과 범위

`START_MOSES.pyw`를 실행하면 로컬 브라우저에 통합 화면이 열린다. 메뉴는 **라이브 감시 / 백테스트 / 전략 생성 / 설정**이다. 화면을 여는 것만으로 Part1 라이브 엔진이나 Part2 백테스트는 시작되지 않는다. 각각 필요한 메뉴에서 독립적으로 시작한다. 기존 Part1·Part2 데스크톱 UI와 Part3 전략 생성 기능은 삭제하지 않았다.

이번 변경은 웹 화면과 연결 계층에 한정했다. Part1 엔진·전략·텔레그램 로직, Part2 계산·녹화 로직, Part3 Recipe·compiler·storage 계약은 변경하지 않았다. 수익곡선·MDD·전략 비교, 외부 접속, 패키징은 포함하지 않았다.

## 구조

| 화면 | 연결 방식 | 기존 계약 |
|---|---|---|
| 라이브 감시 | `Part3/lab/unified_live.py`가 현재 Part1 시스템 컨트롤의 시작·종료·SPECIAL 설정 함수를 호출하고 진단 IPC를 읽음 | `event_host.py` 시작·종료, 모듈 상태·Watch 상태·핵심/상세 로그 |
| 백테스트 | `Part3/lab/unified_backtest.py`가 현재 Part2의 `ui_model.make_scenario`·설정·CLI `plan/run`·`ProgressView`를 사용 | 기존 구축 확인, 진행·안전 정지·결과 파일. 브라우저는 결과를 읽기만 함 |
| 전략 생성 | 기존 Part3 화면·API를 같은 페이지의 메뉴 안에 유지 | AI·Recipe·preview·SPECIAL 생성·기존 검증 그대로 |
| 설정 | `Part3/lab/unified_settings.py`가 실제 Part1 `config.txt`, Part2 `event_backtest.json`, 기존 Part3 컴퓨터별 연결·AI 설정을 읽고 검증 후 저장 | 기존 키만 편집; 비밀값은 조회 응답에서 마스킹, 빈 입력은 기존 값 유지 |

서버는 기존 Part3 `lab/server.py`를 확장했고 `127.0.0.1`에만 바인딩한다. 정적 화면은 로컬 파일이며 인터넷 없이 열린다. 기존 세션 토큰·Origin 검사를 새 API에도 적용했다. 브라우저 JavaScript에 Bot Token/API Key를 넣지 않는다. 설정 저장은 현재 파일의 키와 허용값을 검증하고 임시 파일 교체로 반영한다. Part1 설정 저장 시 재시작 안내를 표시한다. 창고·Python 실행 파일 경로는 기존 컴퓨터별 연결 설정에만 둔다.

## 검증

- Part1 252개, Part2 251개 소스·설정 파일을 수정본45와 SHA-256으로 대조: 추가·삭제·변경 **0**. 증거: `검증결과/통합웹UI/source_integrity.json`.
- Part3 기존+신규 테스트 **43개 통과**. 신규 테스트는 비밀값 마스킹, 값 검증, 실제 Part2 시나리오 계약 일치, 구축 승인·정지 요청 경로, Part1 기존 시작·종료 함수 위임, 웹 네 메뉴와 인증 API를 확인했다. 증거: `검증결과/통합웹UI/unittest_part3.log`.
- `unified.js` 구문 검사 통과. 새 Python 모듈 구문 검사 통과. 기존 Part3의 백테스트 대화상자와 새 통합 백테스트의 DOM ID 충돌을 제거했다.
- 로컬 브라우저에서 네 메뉴를 직접 열어 입력·상태·전략 생성 기존 화면·마스킹된 설정을 확인했다. XAU 2025-09-01~08 계획 조회에서 기존 창고 조각 2개를 재사용 대상으로 판정했다. 실제 라이브 시작, 텔레그램 전송, MT5 재녹화, 장기 백테스트는 실행하지 않았다.
- 루트 테스트 전체 수집에는 현재 소스에 없는 `live_replay.runtime`을 참조하는 레거시 12개 파일의 수집 오류가 있다. 해당 묶음을 제외한 실행은 임시 폴더 권한을 작업 공간으로 돌린 뒤 **879 통과, 10 실패**였다. 이 중 1개는 위의 오래된 Part3 부재 검사였고, 계약 수정 후 해당 파일은 **7 통과·하위 시험 3 통과**했다. 남은 9개는 변경하지 않은 Part1/Part2와 기존 Tk 환경·옛 내부 구조를 고정한 시험에서 재현된다. 목록과 원문은 `검증결과/통합웹UI/pytest_retest.log`에 남겼다. 따라서 **기존 테스트 전체 통과 조건은 충족하지 못했다**. 이 실패를 엔진 변경이나 시험 삭제로 숨기지 않았다.

Part2의 백테스트 계산 파일이 비트 단위로 그대로이고 웹에서 만드는 시나리오가 기존 `ui_model` 시나리오와 같은 것은 확인했다. 실제 기간을 두 경로로 완주해 결과 CSV를 비교하는 종단 검증은 수행하지 않았으므로, 결과 동일성의 실측 증거는 아직 없다.

## 남은 확인

운영 전 실제 백테스트 한 구간을 기존 UI와 통합 UI 양쪽에서 실행해 결과를 비교하고, 라이브 운영 환경에서 Part1 제어·진단 연결을 확인해야 한다. 이때 테스트에서는 실제 텔레그램 전송을 차단한다. 루트 레거시 테스트의 현재 소스와 맞지 않는 계약 및 Tk 설치 문제는 별도로 정리해야 전체 녹색 실행을 얻을 수 있다.
