# 수정본130 최적화 3 — 엔진으로 스냅샷 넘기기

수정본129를 그대로 복사해(검증결과 제외) 수정본130을 만들었습니다. 효과는 작습니다(자료 읽기의 약 2%). 대신 이번 측정으로 자료 읽기에서 더 줄일 곳이 거의 남지 않았다는 것을 확인했습니다.

## 결과

| | 내용 |
|---|---|
| 엔진 입력 동일성 (129와 130을 따로 돌려 입력마다 지문 비교) | 9월 한 달 28,786개 입력 — **차이 0**, 전체 지문 같음 (시간봉 배열 바이트, 순번, 유효 표시와 순서, 간격·상태 입력 포함) |

## 바뀐 것

| 위치 | 변경 |

## 확인한 것: 처음 예상과 다른 점

- 수정본127 문서의 "같은 묶음을 재생기와 STAFF가 두 번 해석" 추정은 틀렸습니다. 해석은 한 번만 하고 결과를 다시 씁니다.
- 프로파일러는 이번에 고친 부분처럼 작은 파이썬 함수가 많이 불리는 곳을 실제보다 크게 보여 줍니다(이 부분이 프로파일에서는 11%, 실제로는 약 3%). 그래서 효과는 번갈아 측정한 값으로 판단했습니다.
