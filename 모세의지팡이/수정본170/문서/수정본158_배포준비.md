## 2-1. 깨진 SPECIAL 파일은 그 파일만 빼고 시작

### 전

`Part1/program/SPECIAL` 안의 파일 하나라도 읽기·검사에 실패하면 전략 목록 전체가 예외로 끝났다. 라이브 시작, 전략 설정 화면, 백테스트 목록이 모두 막혔다.

### 후 (합의한 동작)

- 깨진 파일 하나만 빼고 나머지 전략으로 정상 시작한다.
- 어떤 파일이 왜 빠졌는지 화면과 텔레그램에 한 줄로 알린다.

| 경우 | 처리 | 알림 문구 예 |
|---|---|---|
| JSON 문법 오류 | 그 파일만 제외 | `SPECIAL8.recipe.json 제외 · JSON 형식 오류 1행 18열` |
| 파이썬 문법 오류 | 그 파일만 제외 | `SPECIAL8.py 제외 · 파이썬 문법 오류 2행` |
| PART3_RECIPE가 없거나 literal이 아님 | 그 파일만 제외(소스는 실행하지 않음) | `… 제외 · 스페셜 파일에 PART3_RECIPE 선언이 하나 필요합니다` |
| UTF-8 아님, 읽기 실패 | 그 파일만 제외 | `… 제외 · UTF-8 파일이 아닙니다` |
| 파일명 형식(SPECIAL0, SPECIALX) | 그 파일만 제외 | `… 제외 · 스페셜 파일명은 SPECIAL1~SPECIAL999 형식이어야 합니다` |
| 파일 안 ID가 파일명과 다름 | 그 파일만 제외(다른 전략을 덮어쓰지 않음) | `… 제외 · 스페셜 파일의 이름·중복·Recipe 형식을 확인하세요` |
| 레시피 검사 실패 | 그 파일만 제외 | `… 제외 · 최종 행동은 OZ/NOTIFY/DEFINE입니다.` |
| 같은 번호 파일 둘(`SPECIAL1.py`와 `SPECIAL1.recipe.json`) | **둘 다 제외**. 어느 쪽이 맞는지 알 수 없으므로 추측하지 않음 | `… 제외 · 같은 전략 번호 파일 중복 …` |
| SPECIAL 폴더 자체 문제(연결 폴더, 수정본 밖) | 지금처럼 예외 | |

알림 문구에는 PC 경로가 들어가지 않는다.

알리는 곳:

| 곳 | 내용 |
|---|---|
| 라이브 시작·재시작 결과 | 기존 주의 문구 자리(`주의 사항은 모듈 로그를 확인해 주세요`)와 ENGINE 로그 줄에 파일별 한 줄. 독립 실행(CLI) 결과 문구에도 붙음 |
| 엔진 로그 | 엔진이 시작할 때 파일별 한 줄(INFO). 모듈 상태를 '지연'으로 바꾸지 않음 |
| 텔레그램 | 엔진 시작마다 한 번, `[라이브 시작] SPECIAL3.py 제외 · …`. 전략 알림이 아니라 LIVE 기록에는 `HOST_NOTICE`로 남음 |
| 전략 설정 창(라이브·백테스트) | 창 아래 안내 줄 맨 앞(기존 테스트 전략 오류 안내 자리) |

함께 고친 것:

- **저장된 설정 때문에 라이브가 막히지 않게**: 빠진 전략의 이름이 `special_settings.json`에 남아 있어도 "미등록 항목"으로 막지 않는다. 그 전략의 트리거·거래시간은 엔진에 넘기지 않는다. 빠진 파일이 아닌 미등록 이름은 지금처럼 막는다.
- **빠진 전략의 설정 보존**: 파일을 고치기 전에 전략 설정을 저장해도 빠진 전략의 기존 설정(켜짐/꺼짐·트리거·거래시간)을 지우지 않는다. 고치면 예전 설정 그대로 돌아온다. 저장된 트리거를 읽지 못한 상태였다면 추측하지 않고 꺼 둔다. 설정 파일 자체가 손상된 복구 저장은 지금처럼 제출한 전략만 쓴다.
- 백테스트(Part2)도 같은 목록을 쓰므로 같은 파일이 빠진다. LIVE와 재생의 전략 구성이 같다.

## 2. 라이브 배포 준비

배포본은 158(최신)로 만든다. MT5 EA 소스는 152에서 마지막으로 바뀌었고 153~158은 파이썬만 고쳤다. 152 EA는 650봉 APPEND를 보내므로 136 배포본 프로그램으로는 읽을 수 없다. 그래서 EA와 프로그램을 함께 바꿔야 한다.

### 배포 EA와 기존 녹화의 연결

문제는 이랬다.

- 배포 도구는 EA에 만료 검사를 넣고 다시 컴파일한다. 그러면 EA 빌드 해시가 개발용(`76440d6e…`)과 달라진다.
- 창고 녹화는 152 재구축 때 모두 개발용 EA(`76440d6e…`)로 만들었다.
- 호환 목록에는 152 이전 소스용 연결만 있었다. 그래서 그대로 배포하면 배포본 백테스트가 창고 녹화를 못 쓰고 새로 녹화하려 했다.
- 개발본(158) 백테스트와 라이브 알림은 이 문제와 상관이 없다.

사용자가 고른 방법은 "배포 EA로 하루치 녹화 → 같으면 호환 목록 등록"이다.

1. 배포 빌더와 같은 함수(`releasekit/mt5.py`의 `build_mt5`)로 시험용 배포 EA 5개를 만들었다.
   - 만료는 2026-10-10 0시로 짧게 잡았다. 그래서 실제 배포 EA와 해시가 겹치지 않는다.
   - 시험용 EA 해시는 `fca68ace…`다.
2. 시험용 EA로 금 2026-09 BAR 한 달을 임시 창고에 녹화했다(녹화 단위가 월이라 한 달).
   - 녹화 도구가 MT5를 잠시 종료하고 시험용 EX5와 그 소스를 넣었다. 테스터가 다시 컴파일해도 배포용 코드로 돈다.
   - 끝난 뒤 원래 파일(136 배포 EA·지표·옛 소스)로 되돌리고 MT5를 다시 켰다. 되돌린 해시도 확인했다.
3. 실제 창고의 같은 달 녹화(개발 EA)와 비교했다.

| 비교 | 개발 EA `76440d6e…` | 시험 배포 EA `fca68ace…` |
|---|---|---|
| 묶음 수 | 30,164 | 30,164 |
| 전체 묶음 해시 | `c70ff1ff…` | `c70ff1ff…` (같음) |
| 거래일 | 22일 | 22일, 날짜별 묶음 수·해시 모두 같음 |
| 틱 | 실제 틱 | 실제 틱 |
| 스키마·타이머·테스터 모델·테스터 종목 | | 모두 같음 |

같았으므로 `Part2/ea_build_compatibility.json`에 묶음 하나를 더했다. 기존 묶음은 그대로 두었다.

- 해시: [`76440d6e…`, `fca68ace…`]
- 고정점(`source_anchor`): 개발 EA `76440d6e…` + 현재 MQL 소스 지문 `8dfd82e2…`
- 근거: `문서/EA_녹화호환_152소스검증.json`. `문서/`는 다음 수정본으로 복사되므로 검증결과가 없어도 근거가 남는다.

배포 빌더는 소스 지문과 개발 EA가 고정점과 같을 때, 새로 만드는 배포 EA를 이 묶음에 자동으로 붙인다. 소스나 개발 EA가 바뀌면 붙이지 않는다. 임시 폴더에서 빌더의 호환 단계를 모의로 돌려 확인했다(서명 키는 복사하지 않음).

| 확인 | 결과 |
|---|---|
| 첫 배포 EA → 개발 EA 녹화 사용 | 예 |
| 기간만 바꾼 다음 배포 EA → 개발 EA 녹화·첫 배포 EA 사용 | 예 |
| 152 이전 소스 묶음(4개) | 그대로 |
| 관계없는 해시 | 거부 |

개발본에서는 호환 집합이 {`76440d6e…`, `fca68ace…`}가 된다. 실제 창고에 `fca68ace…` 녹화는 없으므로 개발본 백테스트는 바뀌지 않는다. 시험 녹화는 임시 창고에만 두었다가 지웠다.

기록: `검증결과/revision158/ea_compat/`
- `day_comparison.json`: 날짜별 비교
- `licensed_test_build.json`: 시험 EA 해시·소스 지문
- `licensed_recording_events.json`: 녹화 주요 이벤트
- `release_bridge_simulation.json`: 빌더 모의 결과

### 남은 배포 단계 (사용자 결정·조작 필요)

1. 통합설치 EXE 만들기
   - `모세의지팡이 배포.cmd` 창에서 배포 버전, 프로그램 만료일, 설치파일 유효시간을 정한다.
   - 빌드 도구와 WebView2 오프라인 설치파일을 내려받고, MetaEditor로 5개를 컴파일하고, 배포 EXE 검사까지 거친다.
2. 모세(배포본)와 MT5를 종료하고 통합설치 **업데이트**로 `모세트레이딩시스템`을 갱신한다. MT5 데이터 폴더를 고르면 EA·지표도 교체된다.
3. MT5를 켜서 차트의 EA를 새 EA로 다시 붙이고 라이브를 시작한다.
