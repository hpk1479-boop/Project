# 수정본151 백테스트 반복 처리 최적화

수정본150을 별도 수정본151로 복사하여 승인한 **1·2·3번만** 작업했다. 이전 수정본의 검증결과·캐시는 복사하지 않았다. 이번 증거는 모두 `검증결과/revision151`에서 새로 만들었다. 150의 나스닥 스프레드 0 / point 누락 허용 수정과 올라마 시험 격리 수정도 복사 시점에 포함되어 있고 그대로 유지됐다.

실제 금 녹화의 짧은 시험에서 재생 시간이 약 **4~6%** 줄었다. 이번 범위만으로 큰 폭의 개선을 확인한 것은 아니다. 사용자가 전달한 70개월·14코어 실행의 가상진입 8.7분/약 30%는 중요한 장기 병목으로 본다. 2일 시험에서 가상진입 시간이 짧다는 이유로 장기 실행의 우선순위를 낮게 판단하지 않는다.

## 바꾼 내용

1. **STAFF ROW 반복 검사:** 정상 FULL에서 검증한 불변 과거 봉은 같은 창의 ROW 갱신마다 다시 전부 검사하지 않는다. 새로 받은 마지막 행의 OHLC와 지표 유효성은 계속 검사한다. FULL·일반 복원·보관 봉 수 변경·비정상 시간 배열은 전체 검사를 유지한다. 연결 복구·순서 누락·오류 처리와 bundle 전체 취소 규칙도 유지한다. Part1과 Part2가 함께 쓰는 수신부이므로 양쪽 경로를 함께 시험했다.
2. **복원 중간 복사:** Delta FULL의 기존 행을 최종 배열에 직접 채우고, 연속 메모리를 바이트 조립에 전달한다. 전체 시간봉과 열을 계속 복원한다. 녹화 시작점 복구에서는 canonical STAFF가 FULL을 검증한 배열을 유지하고 이어 읽기용 메타데이터만 적용한다. 배열→목록→배열의 왕복 복사를 제거했다.
3. **확정봉 수치 재사용:** 같은 확정봉 원본이면 가변 MA 수치를 재사용한다. 전체 계산과 같은 입력 창·초기값을 쓰며 판정에 쓰는 값이 전체 계산과 같아야 한다. 진행봉은 기존 경로로 계산한다. MT5가 이미 계산한 native MA도 그대로 읽는다. 과거 정정·창 이동·기간 변경·재연결은 반영한다. 알림 발생 상태, 조건 대기 상태, 교차 경계, 중복 방지와 시간 처리는 매 관측마다 기존대로 수행한다.

숫자 비교 결과까지 저장하는 후보는 반복 입력에서도 이득이 없고 값이 바뀌면 CPU가 약 2.2배 필요해 철회했다. 최종 제품에는 그 비교 캐시와 연결 코드가 남아 있지 않다. 당시 후보 측정은 `closed_tests/compare_bench151.json`에 참고 증거로 보존했다. 그 탐색 스크립트는 최종 제품의 재현 명령이 아니다.

제품 변경 파일은 다음 5개다.

- `Part1/program/THE STAFF OF MOSES.py`
- `Part1/program/watch_array_facts.py`
- `Part1/program/strategy_recipe/port.py`
- `Part2/event_backtest/delta.py`
- `Part2/event_backtest/bridge.py`

Part1 전략 설정·전략 조건과 레시피 파일, 기준프레임/내부 시간봉 매핑, EA, 가상진입 판단, CRC·SHA 검사 방식은 변경하지 않았다. 650봉 창과 준비 3일도 유지한다. 필요한 시간봉만 먼저 복원하는 4번, 장기 가상진입/분할의 5번, 녹화 검증 표시를 믿고 CRC·SHA를 생략하는 일은 구현하지 않았다.

## 로직 검증

관련 **531개 통과**: `final_integrated.log`에서 530개, `final_windows.log`에서 1개. 기존 중단 저장 시험은 샌드박스 안에서 Windows strict 경로 조회가 WinError 5로 막혔다. 150 폴더·151 폴더·새 임시 폴더 모두 같은 현상을 보였고, 샌드박스 밖에서 최종 제품의 그 시험 1개를 다시 실행해 통과했다. 실패 로그는 보존하고 환경 원인을 `windows_environment.json`에 기록했다. 실패를 합격으로 바꾸거나 제품/기존 시험을 고치지 않았다.

새 회귀 5파일과 기존 관련 시험은 아래를 확인했다.

- FULL·ROW·heartbeat, 확정봉/진행봉 경계, 재연결, 과거 정정, 봉 이동과 가변 기간 변경.
- 잘못된 ROW·손상 CRC·잘린 Delta·잘못된 행/셀 매핑의 거부, 실패 bundle의 원자적 취소, 이전 Snapshot 불변성.
- 확정봉 MA의 판정값과 전체 계산 값 일치. 준비 부족/NaN일 때 미발생, 실제 교차·터치일 때 발생, 취소·미충족 입력일 때 미발생.
- 실제 SPECIAL8 엔진에 같은 합성 Wire를 LIVE 수신과 Delta 재생으로 넣어 동일한 알림 시간·방향·시간봉·가격을 확인. native HMA와 가변 SMA 모두 시험.
- keyframe 시작점 복구와 처음부터 읽기의 이어 읽기 상태·지표 유효성·시간·배열 일치, LIVE/재생 양쪽 확인.

이전 결과 자체를 정답으로 삼지 않았다. 예상 발생/미발생 입력과 전체 수치 계산, 같은 입력의 LIVE/재생 일치를 로직 합격 기준으로 사용했다. 실제 녹화의 전후 CSV 비교는 변화 확인용이다.

예외 처리의 작은 차이 1개는 별도로 기록한다. 보관 봉이 3개보다 적은 오류 경로의 `len(slice)`가 잘못된 TypeError를 내던 부분을 수정했다. 이제 의도한 RuntimeError로 같은 입력을 거부한다. 정상 신호 판단 변화는 아니다. 잘린 Delta 변경 값도 적용 전에 명시적으로 거부한다.

## 실제 녹화 측정

금 `XAUUSD+`, BAR 녹화, 시험 기간 2025-09-08부터 09-10 직전까지, 준비 시작 09-03. 휴장일을 제외한 준비 3일이며 한 실행당 **6,889묶음**을 처리했다. 생산 supervisor/job·MT5·실제 알림 서비스를 실행하지 않고 분리된 측정 워커로 읽었다. `process_priority.full_speed()`를 먼저 호출했다. 같은 입력으로 150→151와 151→150 순서를 뒤집어 실행하고 wall 시간과 CPU 시간을 함께 기록했다. 사용한 150 소스 snapshot은 151 복사 시점의 파일 해시와 일치했다.

아래는 **재생 단계만**의 시간이다. SPECIAL8 기본 1분/1시간은 교대 2쌍의 중앙값, 나머지는 1쌍이다.

| 시험 | 150 wall → 151 wall | 감소 | CPU 감소 | 알림 수 |
|---|---:|---:|---:|---:|
| SPECIAL8 기준 1분 | 18.50초 → 17.57초 | 5.0% | 4.4% | 86 |
| SPECIAL8 기준 1시간 | 18.71초 → 17.57초 | 6.1% | 5.7% | 2 |
| SPECIAL8 기준 1시간, HMA18/51 | 19.76초 → 19.04초 | 3.7% | 4.1% | 2 |
| SPECIAL1 다중 프레임 | 36.90초 → 35.13초 | 4.8% | 4.8% | 0 |

HMA18/51 시험은 기존 HMA17/50을 전략과 해당 진입 값에서 바꾼 측정용 설정이다. 제품 설정 파일은 수정하지 않았다. SPECIAL1의 알림 0건은 이번 구간의 속도 측정이며 발생 사례 검증을 대신하지 않는다.

6쌍 모두 알림 CSV, 가상진입 거래 CSV, 요약 CSV가 실행 식별자 `run_id`를 제외하고 동일했다. 다른 값은 보고 대상이나 이번 실제 녹화 시험에서는 없었다. 시간봉 전체 재생으로 돌아가는 fallback도 없었다. 상세 원시 기록과 제품 소스 해시는 `performance/cases`, 집계는 `performance/final_paired.json`에 있다.

가상진입은 그대로이며 이 짧은 표본에서는 약 0.5~0.8초였다. 장기 가상진입을 최적화한 수치로 해석하지 않는다. 70개월 전체·14코어 완료 시험은 이번에 실행하지 않았으며 그 총 시간 개선율을 추정하지 않는다. 단일 프레임을 1시간으로 바꿔도 분 단위 입력·진입/손절 처리와 모든 feed 복원은 남아 있어 1분 대비 크게 빨라지는 구조를 이번 작업에서 바꾸지는 않았다.

## 다시 확인하는 도구

151 루트에서 `verification/run_regression151.py`에 새 실행 이름과 명시적인 시험 파일을 주면 이전 증거를 덮어쓰지 않고 실행한다. 새 회귀는 `tests/test_staff_row_validation151.py`, `test_delta_materialization151.py`, `test_closed_facts151.py`, `test_bootstrap_metadata151.py`, `test_live_replay151.py`이며 공식 검증 목록에도 등록했다.

`verification/measure_revision151.py`는 상대 경로로 저장된 녹화 메타데이터와 분리된 150 snapshot을 사용한다. 새 `--run-label`로 각 측정을 실행하고 `verification/summarize_revision151.py`에 그 쌍을 지정해 집계한다. 당시 최종 제품과 현재 제품 해시가 달라지면 최종 집계로 인정하지 않는다. `verification/audit_scope151.py`는 제품 변경 범위와 150의 명시된 수정 보존을 확인한다. 필요한 Python 의존성은 실행 환경에서 제공하며 설치 경로를 저장하지 않는다.

이번 문서는 이번에 실행한 Part1·Part2 관련 검증만 설명한다. Part3 prototype/Lab 및 전체 프로젝트 검증은 실행하지 않았다. 과거 전체 검증 문서의 PASS를 151의 새 증거로 사용하지 않았다.
