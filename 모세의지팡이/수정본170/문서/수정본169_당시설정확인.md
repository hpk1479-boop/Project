# 수정본169: 백테스트 당시 설정 확인

수정본168을 복사해 만들었고, 168의 검증결과 폴더는 복사하지 않았습니다. 실시간(Part1) 코드와 재생 로직은 바꾸지 않았습니다. 백테스트를 시작할 때 기록을 하나 더 남기고, 연구소의 백테스트 목록에서 그 기록을 보여 줍니다. 배포는 하지 않았습니다.

## 사용자 요청
- "백테스트 목록에서 당시 설정 확인 — 각 백테스트에 사용한 전략·기준프레임·내부 설정값을 저장하고 표시합니다. 이후 설정을 바꿔도 당시 시험한 값을 확인할 수 있어야 합니다."
- 전략 주고받기(내보내기·가져오기)는 만들지 않습니다. 사용자 말로는 "그냥 파일로 주고 받으면 되는건데"입니다. 번호가 겹칠 때 바꾸는 절차는 170 규칙에 넣습니다.

## 무엇을 남기나 (`Part2/event_backtest/tested_settings.py`)
실행을 시작할 때(재생 전) 실행 폴더에 `tested_settings.json`을 씁니다. 같은 내용은 결과(`result.json`과 창고 목록)의 `tested_settings`에도 들어갑니다.

| 항목 | 내용 |
|---|---|
| 전략 조건 | 엔진이 실제로 돌린 계획입니다(`base_frames.engine_plugins`와 같은 값). 그때의 레시피를 시험한 기준 프레임으로 옮기고, 고른 OZ 트리거와 거래 시간을 적용한 것입니다. 가상진입에서 조건을 고쳤으면 고친 조건입니다. |
| 트리거·거래 시간 | 실제로 적용한 값입니다. 고르지 않았으면 레시피 기본값이고, 사용자 지정인지 기본값인지도 남깁니다. |
| 기준 프레임·시간봉 | 기준 프레임(여러 시간봉을 쓰는 전략은 없음), 전략 시간봉, 환경 시간봉 |
| 제목·파일 위치 | 레시피 이름과 상대 경로 폴더입니다. 개발본은 `Part1/program/SPECIAL`, 설치본은 `스페셜/기본`·`스페셜/내 전략`, 생성 전략은 `Part3/TEST_SPECIAL`입니다. |
| 레시피 지문 | 레시피 항목의 sha256입니다. 나중에 레시피가 바뀌었는지 판단할 때 씁니다. |
| 가상진입 | 이 실행의 가상진입 설정입니다. 기준 프레임 여러 개를 한 번에 시험하면 실행마다 다릅니다. |
| 설정값 | config.txt 가운데 판단에 쓰는 값입니다: 원비 밴드 배수, 세션 시간 9개, 종목 1포인트 가격. |

- 기간·종목·재생 모드·스프레드·앞 구간 겹쳐 읽기·올존 확인 시간봉은 원래부터 시나리오에 저장되므로 그대로 씁니다.
- 레시피가 없는 실행(WATCH 명령, 데이터 구축)은 전략 칸이 비고 설정값만 남습니다. ALL은 실제로 도는 전략을 모두 남깁니다.
- 레시피 원문 대신 엔진 계획을 남기는 이유가 있습니다. 원문을 남기면, 예를 들어 SPECIAL2를 "무지성 브레이커 올존"으로 돌린 실행의 조건 설명이 "일반 올존"으로 나옵니다.
- 기록 때문에 실행이 달라지지 않습니다. 엔진이 준비할 수 없는 입력(종목 없음 등)이면 기록만 비웁니다. 재생은 원래대로 같은 오류를 보고하고 실패로 남습니다.
- 경로는 상대 경로만 남기고, 창고에 저장하기 전에 경로 검사(`portable.validate`)를 통과합니다. 비밀값(텔레그램 토큰 등)은 남기지 않습니다.

## 화면 (연구소 → 백테스트 → 백테스트 목록)
- 줄마다 "▶ 당시 설정"이 있습니다. 누르면 그 줄 아래에 펼쳐지고, 처음 펼칠 때 한 번 읽어 옵니다.
- 보이는 것:
  - 전략 이름·제목·파일 위치
  - 기준 프레임, OZ 트리거, 거래 시간
  - 조건 설명(AI 해석 화면과 같은 설명)
  - 가상진입 설정과 스프레드
  - 재생 모드, 올존 확인 시간봉, 앞 구간 겹쳐 읽기
  - 설정값
- 실행 뒤에 레시피 파일이 바뀌었으면 "지금 레시피와 다름"이 붙고, 지워졌으면 "지금은 없는 전략"이 붙습니다.
- 진행 중인 실행도 실행 폴더의 기록으로 보입니다. 데이터 구축 작업에는 이 항목이 없습니다.
- 169 이전 실행은 그때 남긴 것만 보입니다: 요청, 적용한 트리거·거래 시간, 원비 배수, 세션 시간, 가상진입에서 고친 조건. 레시피 조건은 "기록 없음"으로 나옵니다. 옛 형식(schema 1)의 가상진입은 저장된 값을 그대로 보여 줍니다.
- 조건 설명을 만들지 못하는 조건(예: 설명 함수가 모르는 형식)은 그 칸만 저장된 값 그대로 보여 주고, 나머지 칸은 평소대로 나옵니다. 지금 SPECIAL1~9의 계획은 모두 설명이 정상으로 나옵니다.
- 기존 "진행 / 결과 보기" 버튼은 그대로입니다. 줄마다 버튼은 여전히 하나입니다(펼침 항목은 버튼이 아님).
- 넓은 화면에서는 이름표와 값이 두 칸으로 맞춰지고, 좁은 화면에서는 위아래로 쌓입니다. 가로 넘침은 없습니다.
