# 단계별 검증·성능 규칙 — 최종 결정

사용자의 최종 지시를 적용한다. 이 문서가 기존 설계서의 매 단계 +5% 성능 게이트보다 우선한다.

## 단계별 적용

- S1–S4, S6–S7: 합성·실제 MT5 골든 동일성, 240초 3-way 1회, 전체 테스트 1회, 새 실패 0. 성능은 1회 참고 기록이며 판정하지 않는다.
- S5 종료, S8 종료: 위 동일성 검증과 함께 아래 동결 성능 규칙을 적용한다.
- 골든은 파일 SHA256을 먼저 비교한다. 동일하면 이미 검증된 동결 원본과 바이트가 같으므로 개별 DataFrame을 다시 풀지 않는다. 해시가 다르면 기존 정확 비교로 차이를 확인한다. `build/compare_staff_golden.py`를 사용한다.
- 개발 중에는 영향 파일의 관련 테스트만 실행한다. 단계 완료 후 전체 게이트는 1회, 실패 원인 해결에 필요한 항목만 재실행한다. S0 골든 생성은 재실행하지 않는다.

## S0 측정 근거

CPU 비고정 5회는 최대 편차 약 47%여서 실패했다. 원시 자료는 `검증결과/staff_s1/performance_protocol_unpinned`에 보존한다.

동일 논리 CPU에 고정한 S0 5회도 임시 공통 10% 상한으로는 실패했다. 그 기록을 PASS로 바꾸지 않았다. 사용자가 현재 측정 결과로 규칙을 확정하도록 지시한 뒤, 후보를 추가 측정하지 않고 **작업별** 허용치를 정했다. 전체 CPU 최대 편차는 2.528%, 가장 짧은 요청은 7.407%다.

| 작업 | 5회 CPU 범위(초) | 중앙값 | 최대 편차 | 허용 비율 |
|---|---:|---:|---:|---:|
| parser 650행 × 1000 | 2.000000–2.093750 | 2.046875 | 2.290% | 1.05 |
| request_0 × 250 | 0.390625–0.437500 | 0.421875 | 7.407% | 1.15 |
| request_1 × 250 | 2.609375–2.796875 | 2.718750 | 4.023% | 1.09 |
| request_2 × 250 | 3.234375–3.406250 | 3.328125 | 2.817% | 1.06 |
| request_3 × 250 | 3.718750–4.000000 | 3.890625 | 4.418% | 1.09 |
| OZ/FVG LIVE 240초 전체 | 73.812500–76.046875 | 74.171875 | 2.528% | 1.06 |

각 작업의 중앙값 대비 최대 절대 편차를 d라 할 때 `ceil(100 * (1 + max(0.05, 2*d))) / 100`이다. 관측 변동의 두 배에 여유를 주고 1% 단위로 올림했다. 짧은 요청의 15%를 다른 작업에 일괄 적용하지 않는다.

## S5·S8 고정 실행 방법

`build/staff_performance_policy.json`이 최종 정책이다. 같은 수치·방법을 S8까지 유지하며 단계마다 다시 보정하지 않는다.

- BEFORE는 수정본6 Part1/program 전체 동결본이며 파일 해시를 확인한다.
- worker만 허용된 가장 낮은 논리 CPU에 고정한다. 다른 앱·MT5·전원 설정·우선순위는 바꾸지 않는다.
- 같은 세션에서 S0 → 후보 순으로 각 5회, 총 10개 독립 worker를 순차 실행한다. 다른 테스트와 겹치지 않는다.
- 각 작업의 후보 CPU 중앙값 / 같은 세션 S0 CPU 중앙값을 표의 고정 비율과 비교한다. 6개 작업 모두 만족해야 한다.
- 측정 중 S0 CPU 중앙값이 보정 중앙값의 같은 허용 범위를 벗어나면 환경 변동으로 실패한다.
- 초기 publish 10회, 요청 종류별 warmup 5회, STAFF 배치 전 gc.collect. GC는 켜 둔다.
- wall/p50/p95는 별도로 보존한다. 표본 제외·최솟값 선택·자동 재시도·결과 덮어쓰기는 하지 않는다.

실행: `python -X utf8 -B build/run_staff_performance_stage.py --stage S5 --out <새 결과 폴더>` (S8에서는 S8).
기존 14개 회귀 검증의 성능 항목에는 `STAFF_STAGE` 및 `STAFF_PERFORMANCE_RESULTS`를 해당 단계로 지정한다. 다른 단계는 1회 기록만 수행하며 속도 assertion은 적용하지 않는다. Fact 재사용 assertion은 모든 단계에서 유지한다.

S1에서는 추가 후보 반복 측정을 하지 않았다. 단발 wall 117.3468초 → 118.8382초와 초기 STAFF 측정을 참고 자료로 남긴다. 초기 성능 실패와 보정 실패 기록도 삭제하지 않는다.
