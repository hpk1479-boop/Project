# 수정본167: 동시 작업 수 최적화 · 백테스트 우선순위 자동 · 내 전략 실시간 체크 해제

수정본166을 복사해 만들었고, 166의 검증결과 폴더는 복사하지 않았습니다. 백테스트 재생·가상진입이 내는 알림과 거래는 그대로입니다. 바뀌는 것은 동시에 돌리는 작업 수, CPU 우선순위, 그리고 `내 전략`에 새로 들어온 전략의 실시간 기본값입니다. 경계 정확 이어 붙이기 (다)는 168에서 합니다. 배포는 하지 않았습니다.

## 사용자와 정한 것
- 동시 작업 수는 숫자를 박아 두지 않고 PC마다 실제로 재서 정합니다.
  - 설정 → 백테스트 → "동시 작업 수" 옆의 [최적화] 버튼을 누를 때만 잽니다.
  - 누르면 먼저 "다른 프로그램을 모두 닫은 뒤 측정하세요" 확인 창을 띄웁니다.
  - 결과는 배포본을 업데이트해도 남습니다.
- 백테스트 우선순위는 실시간이 돌면 '낮음', 아니면 '보통'입니다.
  - 실시간 엔진이 켜져 있는 동안 '켜짐' 표시를 들고 있고, 백테스트는 그 표시만 봅니다. 사용자가 고른 방식입니다.
- `내 전략`(설치 뒤 생긴 전략)에 새로 들어온 전략은 실시간 전략 설정에 체크가 꺼진 채 나옵니다.
- 경계 정확 이어 붙이기 (다)는 167을 마무리한 뒤 168에서 합니다.

## 측정 근거: 이 PC(i5-14500, 빠른 코어 6 + 느린 코어 8, 20스레드)
같은 SPECIAL2 하루치(2,758묶음)를 실제 백테스트 작업자와 같은 방식으로 동시에 돌렸습니다(임시 창고, 두 번째는 순서를 바꿔 재측정).

| 동시 작업 수 | 우선순위 | 묶음당 시간 | 초당 처리 묶음(두 번 평균) | 지금 대비 |
|---|---|---|---|---|
| 1 | 낮음 | 11.4~11.9ms | 86 | — |
| 14(이전 기본값) | 낮음 | 21.1~21.8ms | 653 | 기준 |
| 14 | 보통 | 19.9~20.5ms | 693 | +6% |

모든 경우 알림은 똑같이 4건이었습니다. 동시 작업 수와 우선순위는 결과에 영향을 주지 않습니다.

## 1. 최적화 버튼
- **측정 후보:** 그 PC의 물리 코어 수, 논리 프로세서 수, 그 가운데 값입니다(이 PC: 14·17·20).
- **측정 방법:**
  - 백테스트 화면에서 골라 둔 전략으로 최근 녹화 하루치를 후보 수만큼 동시에 돌립니다. 고른 전략이 없으면 SPECIAL2를 씁니다.
  - 실제 백테스트와 같은 재생 함수와 작업자 초기화를 쓰고, 측정은 '보통' 우선순위로 합니다.
  - 측정용 임시 재생은 창고의 `.tuning` 아래에 만들고 끝나면 지웁니다.
- **고르는 규칙:** 처리량이 가장 큰 값의 97% 안에 드는 수 가운데 가장 작은 수입니다.
- **메모리:** 측정 때 잰 작업자당 메모리로, 시작할 때 비어 있던 메모리의 80% 안에 들어가지 않는 후보는 재지 않습니다.
- **막는 경우:** 실시간이 켜져 있거나 백테스트가 돌고 있으면 측정하지 않고 한 줄로 알려 줍니다.
- **저장:**
  - `Part2/event_backtest.json`의 `worker_profiles`에 PC 식별값(처리기 이름, 코어·스레드 수, 메모리 크기의 해시)별로 저장합니다. 경로나 사용자 이름은 기록하지 않습니다.
  - 다른 PC로 옮기면 그 PC 식별값이 없으므로 물리 코어 수로 돌고, 설정 화면에 "이 PC는 최적화 전"이 나옵니다.
  - 이 파일은 설치 프로그램이 업데이트 때 원래부터 보존합니다. 시험을 추가해 확인했습니다.
- **동시 작업 수를 정하는 순서:** 칸에 직접 넣은 값 → 이 PC 측정값 → 물리 코어 수.
- **실행 방식:** 측정은 백테스트처럼 별도 프로세스(`python -m event_backtest tune`)로 돕니다. 화면 프로세스에서 작업자를 만들면 Windows가 화면 시작 파일을 다시 불러오기 때문입니다.

실제 측정 경로 확인(임시 창고, SPECIAL8 하루치, 32초): 14개 5,812 · 17개 6,096 · 20개 6,443묶음/초로 20개를 골랐고, 임시 재생 폴더는 남지 않았습니다.

## 2. 백테스트 우선순위 자동
- 실시간 엔진은 시작할 때 이름 붙은 잠금(`Global\MOSES_LIVE_ENGINE_RUNNING_v1`)을 만들고 끝날 때까지 쥡니다. 실시간이 비정상 종료돼도 Windows가 자동으로 없앱니다.
- 백테스트는 시작할 때와 실행 중 2초마다 그 잠금이 있는지만 확인합니다(시스템 호출 한 번). 바뀌면 자신과 작업자 전부의 우선순위를 '낮음'(실시간 켜짐)이나 '보통'(꺼짐)으로 바꿉니다. 가상진입 계산 단계도 같습니다.
- 예전의 실행 중 엔진 찾기(파워셸 프로세스 조회, 1~2초)는 반복 확인에 쓰지 않습니다.
- 실시간이 켜져 있을 때 '낮음'을 지키는 이유: 실시간 엔진은 '높음'이지만 시세를 보내는 MT5는 '보통'이라, 백테스트가 '보통'으로 CPU를 다 쓰면 MT5가 밀립니다.

## 3. 내 전략 새 전략은 실시간 체크 해제
- `내 전략`의 전략은 저장된 실시간 설정에 이름이 없으면 꺼진 채 시작합니다. 체크하고 저장해야 실시간 알림이 나갑니다.
- `기본` 전략과 개발본(스페셜 폴더가 없는 프로젝트)은 지금처럼 켜진 채입니다. 백테스트는 모든 전략을 그대로 씁니다.
- 같은 규칙(`registry.user_strategies`)을 네 곳이 씁니다.
  - 실시간 시작과 상태(`live_control`)
  - 엔진 시작(`event_startup.load_startup`)
  - 전략 설정 화면(`unified_live.specials`)
  - 테스트 전략 승급이 설정 파일을 처음 만들 때(`user_catalog.promote_selected`)
- 166의 `스페셜/안내.md` 원본 문구도 이 규칙에 맞게 고쳤습니다.
