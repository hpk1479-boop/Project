# 수정본114 작업완료

상세 설명은 `수정본114_공통수명기능.md`(기능·SPECIAL3 대조·SPECIAL4 검증), 앞 단계의 외부유동성 위치 표시는 `수정본114_외부유동성위치.md`에 있습니다. 증거는 `검증결과/revision114/`에 있습니다.

## 완료한 작업

| 항목 | 한 일 | 확인 |
|---|---|---|
| 1. 외부유동성 연결 | 터치 `capture` + 최종 OZ `level_gate`(ATR 기간·배수·연결 대상을 전략이 지정). 최종 OZ 감시가 선택된 터치에 연결되고, 판정은 OZ 엔진의 기존 Gate가 함. SPECIAL2에 실제 연결(ATR 14, 1.5) | 허용 거리 안은 통과, 밖은 탈락(경계 ±0.01~0.05 포함), 전략이 지정한 배수가 경계를 바꿈. 실제 엔진에서 LIVE=백테스트 |
| 2. 대기시간 | `within_sec`(조건끼리)와 `final_window_sec`(최종 대기) 구분, `final_window_from`으로 처음 조건부터/모두 모인 뒤부터 선택 | 마지막 순간 포함/제외, 시작 전에 이미 끝난 경우, 두 시간 독립. SPECIAL3 대조표 작성 |
| 3. 봉 수 만료 | SPECIAL5의 `bars: 1` 고정을 `bars_setting: MAX_BARS_AFTER_B0`(기본 10)로 교체. 하위 프레임별 계산·부모/하위 반대 교차 취소 유지 | 한도, 한도+1 경계, 1m·3m 각자 계산, 설정 없음/0/음수/문자 처리, 실제 엔진 LIVE=백테스트 |
| 4. 선행 조건 검사 | `lifecycle.precondition_check`: `WHILE_ACTIVE`(기본) / `AT_START` | 두 방식 모두 통과·차단·취소·미준비 값. SPECIAL1·5·6·7·8은 선언 없이 기본 |
| 5. SPECIAL4 검증 | 30분 마감 시작, 스냅샷, 6분 만료, ATR 1배 선행이동 경계 | 실제 문제 3건 발견·수정(아래 표) |
| 6. 알림 표시 | `TREND`를 공통 위치 표시에 추가: `• 위치: 15분봉 추세` | 실제 Composer 출력 경로, 조건·트리거·등급 줄 없음 |
| 7. 계약·AI·배포 | 계약 검증, AI JSON 스키마(같은 상수 사용), AI 설명 라벨·문서 갱신, 코드 번들 | 소스 없는 배포본 = 이동본 = 개발 폴더 결과 동일 |
| 레시피 단일 원본 | `Part1/program/SPECIAL/`만 수정. `settings/strategy_registry.json`은 손대지 않음. AI 조회 도구의 출처 표기도 SPECIAL 폴더로 정정 | 배포본 레지스트리 = SPECIAL 폴더(시험) |

## 찾아서 고친 결함

| 결함 | 증상 | 수정 |
|---|---|---|
| 재시작 사건을 "지난 사건"으로 버림 | 새 30분봉을 0.3초만 늦게 봐도 SPECIAL4 setup이 시작되지 않음 | 재시작을 일으킨 사건의 시각을 새 활성화 기준으로 사용 |
| 선행이동 창·6분 만료가 폴링 시각 기준 | 경계 봉의 극값이 빠지고, 지연만큼 6분이 늘어남 | 창은 경계 봉부터, 6분은 SPECIAL4에 `final_window_from: FIRST_CONDITION` 선언 |
| 부모 TF 반대 교차가 첫 자식만 취소 | SPECIAL5에서 2분·3분 자식이 살아남음 | SOURCE/FINAL에 묶인 조건의 기준값을 머신별로 보관 |

## 미완료·한계

- 실제 시장 데이터의 LIVE 알림과 장기 백테스트는 돌리지 않았습니다(합성 입력, 실제 엔진 LIVE·백테스트 두 모드 비교).
- SPECIAL3의 대기시간 설정은 적용하지 않았습니다(`final_window_sec 1800` + `FIRST_CONDITION`이 수정본50과 같은 설정).
- 웹 화면(`ai_display.js`, `ai_editor.js`)은 요청대로 바꾸지 않아 새 필드가 AI 요약·편집 화면에 나오지 않습니다.
- ATR 선행이동 검사는 활성화한 폴링의 다음 평가부터입니다(최종 OZ 이벤트는 자기 폴링을 먼저 하므로 그 사이 알림 없음).
- OZ 게이트는 터치한 시간봉(`SOURCE`)의 OZ에서만 동작하며 계약이 다른 시간봉을 거부합니다.
