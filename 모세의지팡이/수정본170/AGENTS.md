## 절대 규칙

원본 폴더는 수정하지 말고 별도의 수정본 폴더에서 작업을 이어간다

\- 새 수정본을 만들 때 이전 수정본의 검증결과 폴더는 복사하지 않는다.

\- 새로운 수정본에 검증결과 폴더에는 그 수정본에서 새로 만든 증거만 둔다.



## Part1 규칙 (실시간 라이브감시)

순수 매매용 실시간 알림으로 백테스팅과 카피시스템과는 별개로 독립 운용이 가능해야한다
사용자가 명시적으로 요청하지 않은 기존 로직을 변경하지 않는다.

이전 버전의 구현을 추측하거나 복원하지 않는다.



## Part2 규칙 (백테스팅)

Part1의 실시간 알림과 99.999% 동일해야 한다 (환경상 100%일수는 없을지라도 최대한 동일해야한다는 의미)
만약 어제 Part1 실시간 알림이 3번 왔다면
백테스팅으로 어제자 동일한 조건을 돌리면 똑같이 같은 시간에 3번 알림이 와야한다



## Part3 규칙 (전략연구소)

Part3는 Part1·Part2 데이터를 참고할수 있다

Part1·Part2는 Part3를 호출하지 않는다.



## 공통규칙

용자가 명시적으로 요청하지 않은 기존 로직을 변경하지 않는다.
이전 버전의 구현을 추측하거나 복원하지 않는다.
큰 변경 전에 영향을 받는 파일과 기존 데이터 흐름을 먼저 확인한다.
변경 후 로직 검증(아래 검증 원칙)을 통과하지 못하면 완료로 간주하지 않는다.
새 동작을 추가할 경우 해당 동작의 regression test를 추가한다.
사용자가 요청한 범위만 수정한다.
기존 전략 조건을 임의로 개선하거나 단순화하지 않는다.



## 검증 원칙

1. 기준본 개념은 없다. 이전 수정본·폴링판·과거 알림 결과는 참고 자료일 뿐이며, 새 코드가 맞춰야 할 정답이 아니다.
2. 검증 기준은 두 가지뿐이다.

   * 사용자가 넣은 로직이 의도대로 작동하는가: 조건마다 발생해야 하는 입력에서는 발생하고, 발생하면 안 되는 입력(확정봉/진행봉 경계 포함)에서는 발생하지 않는지 시험한다.
   * 같은 입력이면 LIVE와 백테스트(재생)가 같은 결과를 내는가.
3. 구조 변경·성능 최적화는 로직의 의미(조건, 확정봉/진행봉 사용)를 유지하면 된다. 기존 결과와 알림이 달라지면 목록으로 보고하고, 로직상 어느 쪽이 맞는지 판단을 적는다. 이전 결과와의 일치 자체를 합격 기준으로 쓰지 않는다.
4. 계산을 줄이는 최적화(끝부분만 계산, 봉 확정 시에만 계산, 캐시)는 판정에 쓰는 봉에서 전체 계산과 같은 값을 내는지로 확인한다.
5. 내부 구현(바이트, DataFrame 모양, 객체 구조, 호출 순서)을 고정하는 기존 테스트는 진단용이다. 로직 검증을 대신하지 않는다.
6. 검증은 필요한 만큼만 한다. 기준선·골든 생성, 비트 단위 비교, 매 단계 성능 게이트, 실시간 대기 비교를 기본으로 넣지 않는다.

## 역할 분리 (이벤트 엔진 기준)

|계층|하는 일|하면 안 되는 일|
|-|-|-|
|MT5 EA|OHLC, 고정 지표(퍼센타일 밴드·레짐·원비·HMA·EMA) 계산, Wire 전송|전략 판단|
|STAFF|수신·검증·불변 Snapshot 보관·전달|지표 계산, 판단|
|Pure Fact (indicator\_facts)|파이썬 계산 지표(가변 기간 MA, ATR14, 전일 고저 등), 입력이 같으면 결과가 같음|상태 보관, 알림|
|Stateful Processor|순서에 따라 변하는 공용 상태(OZ 후보, FVG, SWEEP)|알림 전송|
|Strategy (Consumer)|전광판을 읽고 판단해 신호를 냄|지표 직접 계산, 파일·네트워크·시계 직접 접근|
|김매니저 (Output)|문구·수신자·중복 방지·텔레그램 전송|판단|

* 같은 지표를 두 곳에서 계산하지 않는다.
* 여러 전략이 쓰는 지표는 공용 Fact로 등록한다. 한 전략 전용 계산은 그 전략 내부 Fact로 이름을 붙여 등록한다. 전략 안에서 이름 없이 지표를 새로 계산하지 않는다.
* 여러 전략이 쓰는 상태는 Stateful Processor로 둔다. 전략끼리 상태를 직접 공유하지 않는다.
* 새 지표 배치: 고정·무거운 지표는 MT5, 가변·가벼운 지표는 Fact, 상태가 있으면 Processor.
* 확정봉 기준 값은 봉 확정 시에만 계산하고, 매 묶음에는 필요한 비교만 한다.

## 경로 규칙

* 프로젝트와 창고는 외장하드로 여러 컴퓨터에 옮겨 쓴다.
* 코드·설정·DuckDB·목록·보고서에는 해당 루트(프로젝트 루트 또는 창고 루트) 기준 상대 경로만 저장한다.
* 절대 경로, 드라이브 문자, 사용자 이름, 루트 위쪽 경로(../ 로 루트 밖으로 나가는 경로)를 하드코딩하거나 기록하지 않는다.
* 루트 위치는 컴퓨터마다 설정 파일이나 화면에서 지정한다.
* 경로를 다루는 기능을 만들면, 폴더를 다른 위치로 옮긴 뒤에도 그대로 동작하는지 시험한다.





## 클로드 코드와 작업 폴더 분리

* 클로드 코드가 작업 중인 수정본 폴더나 패치 폴더는 수정하지 않는다. 동시에 같은 폴더를 쓰지 않는다.
* 클로드 코드가 만든 별도 패치 폴더(예: 개피곤\\SPECIAL\_거래시간슬롯)를 합칠 때는 폴더 안 README를 먼저 읽고, 대상 파일이 패치의 기준 버전과 같은지 확인한다. 다르면 멈추고 보고한다.
* 클로드 코드가 남긴 수정내역 문서를 읽고 이어서 작업한다.
