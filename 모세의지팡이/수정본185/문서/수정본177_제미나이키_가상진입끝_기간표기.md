# 수정본177 — 제미나이 키 칸, 가상진입 기간 마지막 봉, 기간 표기

수정본176(아스트라가 175 점검 6건을 고친 수정본)을 복사해 만들었다. 176의 검증결과, 검증 임시 폴더, 캐시는 복사하지 않았다. 배포(EXE 빌드·업데이트)는 하지 않았다.

## 요청

사용자(10/09):
- "이거 동일하게 봇토큰 방식으로 동일하게 수정해 그리고 1번으로 하고 시작일 종료일로만 표기해 다음 수정본 만들어서 작업 시작해"
- "봇토큰 방식" = 설정 화면의 Gemini API 키 칸을 봇 토큰 칸과 같은 모양·동작으로.
- "1번" = 176 점검에서 고른 가상진입 처리. 기간이 끝난 뒤 처음 들어온 데이터로 기간 안 마지막 1분봉의 손절·익절을 판정한다.
- "시작일 종료일로만 표기" = 백테스트 기간에 붙은 "UTC"를 뺀다. 기간을 자르는 기준(브로커 서버 날짜 = 일봉 날짜)은 그대로다.

176을 확인할 때 찾은 것(문서 근거):
- 176의 4번 수정은 "기간 끝 시각과 똑같은 관측"이 있을 때만 마지막 봉을 판정했다. 실제 녹화는 관측 시각이 분 정각에 맞는 경우가 0~1%이고, 기간 끝(서버 자정)은 장 휴식 시간이라 관측이 없다. 그래서 실제 결과는 175와 같았다.
- 176의 6번 수정은 배포본 AI 규칙만 고쳤다. 화면·매뉴얼·간단사용서에는 "UTC"가 남아 있었다.

## 2. 가상진입 기간 마지막 1분봉 (1번 방식)

| 파일 | 바뀐 것 |
|---|---|
| `Part2/event_backtest/runner.py` | `following_capture`: 실행 녹화가 기간 끝을 넘지 않으면, 기간 끝 날짜 이후 첫 녹화 하나를 찾는다(녹화 카탈로그가 열려 있는 `run_many`에서). 가상진입에만 넘긴다. 녹화 고르는 조건은 `usable_captures`로 묶어 `resolve_captures`와 같은 것을 쓴다. |
| `Part2/event_backtest/virtual_source.py`, `virtual_msd.py` | `past_end`: 기간 끝 뒤 첫 관측 하나까지 읽고 멈춘다. 다음 녹화에서도 읽는다. 기본값은 예전과 같다. |
| `Part2/event_backtest/virtual_entry.py` | 그 관측으로 `observe`를 한 번 하고 끝낸다. `observe`는 원래대로 기간 안에서 열린 봉만, 닫힌 봉만 판정한다. 새 봉(기간 밖) 가격과 기간 밖 확인 진입은 쓰지 않는다. 다음 녹화의 브로커 시계가 실행 녹화와 다르면 읽지 않는다(새 오류를 만들지 않음). |

- 실제 녹화 확인(임시 창고의 나스닥 2026-07·08 녹화, `검증결과/revision177/real_recording/last_candle_probe.txt`):
  - 7월 기간 끝(한국 8/1 06:00)의 마지막 1분봉(05:59)은 7월 녹화 안에서 닫히지 않는다. 기간 안 마지막 관측은 05:59:00.020, 다음 관측은 주말 뒤 8/3 07:00:39(8월 녹화)다.
  - 이 봉 시가에 매도 진입을 만들어 보면, 다음 녹화 없이는 RR 1~5 모두 미청산, 다음 녹화를 붙이면 이 봉 안에서 닿은 RR1·RR1.5는 WIN, 닿지 않은 RR2~5는 미청산이다.
- 같은 판정 규칙: 진입 시각이 봉 중간이면 그 봉은 기존 규칙대로 "순서 미확정"이다.

## 3. 기간 표기 (UTC 빼기)

| 위치 | 전 | 후 |
|---|---|---|
| 백테스트 설정 날짜 칸 (`Part3/web/index.html`) | 시작일 UTC / 종료일 UTC (미포함) | 시작일 / 종료일 (미포함) |
| 백테스트 목록 (`backtest_jobs.js`) | 2026-09-01 ~ 2026-10-01 UTC (종료일 미포함) | 2026-09-01 ~ 2026-10-01 (종료일 미포함) |
| AI 편집기 실행 계획 (`ai_editor.js`) | 종목 · UTC 시작 ~ 끝 (종료일 미포함) | 종목 · 시작 ~ 끝 (종료일 미포함) |
| 백테스트 명령 AI 미리보기 (`Part3/lab/ai/backtest_commands.py`) | 기간 (UTC): … | 기간: … |
| 사용자 매뉴얼 | 7장 "시작일·종료일(UTC)", "날짜는 모두 UTC예요", "UTC 기준 끝난 날짜", 10장 용어 "데이터 창고 / UTC" | 모두 뺌 |
| 간단사용서 | "날짜는 UTC이고 종료일은…" | "종료일은 포함되지 않아요…" |

- 그대로 둔 것: 결과의 "원본 파일 · 경로 · 실행 기록" 안 "실제 처리 구간 (UTC)"는 엔진의 실제 시각을 UTC로 적은 것이라 표기가 맞다. 대시보드가 없을 때만 쓰는 옛 결과 표시(`unified.js` 알림 시각 UTC)도 그대로다. 브로커 서버 시간 설정의 "UTC+2" 같은 선택지는 시차 설정이라 그대로다.
- 배포본 AI 규칙(176에서 아스트라가 고친 "브로커 서버 날짜" 설명)은 AI가 기간을 정확히 이해하는 데 쓰여 그대로 뒀다.
