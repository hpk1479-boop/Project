# 조각 크기 측정 — XAU 1주, 수정본33

사용자 축소 지시에 따라 **2025-09-01~09-08 UTC, 종료일 미포함**만 측정했다. 한 달의 월 1조각/주 단위 재측정은 하지 않았다. 기본 분할 규칙과 worker 기본값은 변경하지 않았다.

## 방법

보존 XAUUSD+ BAR 녹화를 SPECIAL1 단독으로 재생했다. 1주 한 작업, 3일 단위, 1일 단위를 순서대로 각각 한 번 실행했다. 각 작업에는 기존 3거래일 워밍업을 적용했고 워밍업 알림을 제외했다. 최대 worker 12개 안에서 작업 수만큼 사용했다. 녹화 조각을 새로 만들거나 저장 형식을 바꾼 것이 아니라 재생 작업 범위만 나눈 진단이다.

경과 시간은 프로세스 풀 시작·종료를 포함한다. 총 CPU는 부모 프로세스의 측정 구간 CPU와 각 worker가 마지막 작업을 마친 시점의 누적 process CPU 합이다. worker의 최종 종료 정리 CPU는 포함하지 않아 아주 작은 차이는 있을 수 있다. CPU 고정·성능 게이트는 적용하지 않았다.

## 제안 — 승인 전 미적용

| 요청 기간 | 제안 | 근거/제한 |
|---|---|---|
| 1~2일 | 일 단위, 작업 수 이상의 worker를 만들지 않음 | 매우 짧은 구간은 워밍업이 본 처리보다 클 수 있음 |
| 3~7일 | 완료 속도 우선이면 1일, CPU 절약이면 3일 | 이번 1주 실측 근거 |
| 8~14일 | 우선 3일 단위 후보 | 이번 구간에서의 균형을 바탕으로 한 추정, 미실측 |
| 15일 이상 | 먼저 주 단위, 작업이 충분하면 최대 2주 | 워밍업 중복을 줄이는 제안, 한 달 재측정은 생략 |

조각 단위의 상한은 사용자 요청대로 2주를 제안한다. 특정 날짜 수만으로 무조건 쪼개기보다 실행 가능한 worker 수와 워밍업/본 처리 비율도 함께 판단하는 편이 낫다. 위 기준은 제안이며 운영 기본값을 변경하지 않았다.

## 증거와 실행 이력

- `검증결과/live_daily_partition_virtual/partition_timings.json`
- `week_single/`, `week_3day/`, `week_daily/`의 작업별 result.json, progress.json, alerts.csv
- 도구: `build/measure_live_followup33.py`

이미 실행 중이던 측정 부모에는 원래 월 작업 목록이 들어 있었다. 범위 축소 후 worker 진입에 제한을 적용해 월 작업이 재생을 호출하기 전에 `USER_SCOPE_END`로 종료되도록 했다. `month_single`의 빈 준비 폴더는 있을 수 있지만 시장 입력·알림·시간 측정 결과는 없다. 세 주간 방식의 완료 결과는 모두 보존했다.

측정 도중 별도 LIVE 기록 모듈을 개발해 전체 코드 해시가 달라졌으나, 이 진단이 사용하는 Part2 재생·분할·전략 처리 코드에는 변경이 없었다. LIVE 기록기는 생산 LIVE 호스트에만 연결되며 이 측정에서 생성되지 않았다. GUI 시험 및 가상 진입 프로파일은 조각 비교 완료 후 실행했다. 실측은 기기와 디스크 캐시 상태에 영향을 받는 참고값이다.
