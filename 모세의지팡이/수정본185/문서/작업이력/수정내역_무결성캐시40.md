# 수정본40 — 녹화 무결성 캐시 결함 수정

## 문제와 수정

수정본39의 `Part2/event_backtest/warehouse.py`는 녹화 파일의 SHA-256을 경로·크기·수정 시각으로 캐시했다. 같은 프로세스에서 이미 검증한 파일의 내용을 **같은 크기로 바꾸고 수정 시각을 복원**하면 이전 해시가 재사용되어 `find_capture()`가 변경된 파일을 정상으로 승인했다. 임시 파일에서 이 실패를 재현했다. 실제 운영 창고의 손상 여부를 뜻하지 않는다.

수정본40은 이 캐시를 제거했다. `find_capture(verify=True)`의 매 요청은 파일 내용을 다시 SHA-256으로 읽으며, 해싱 전후 크기·수정 시각 비교는 유지한다. 녹화 형식·EA·Wire·전략·알림 계산은 바꾸지 않았다. 반복 검증 시 파일을 다시 읽으므로 큰 녹화에서는 준비 단계 I/O 비용이 증가할 수 있다. 캐시의 성능상 이점보다 검증의 정확성을 우선했다.

## 변경 파일

- `Part2/event_backtest/warehouse.py`: 메타데이터 기반 해시 캐시 제거.
- `tests/test_part2_optimization37.py`: 기존 검증 항목을 유지하면서 매 요청 재검사 기대값으로 수정하고, 크기·수정 시각을 보존한 내용 교체 회귀시험을 추가.

수정본39 대비 Part1·Part2·tests 소스 차이는 위 두 파일뿐이다. Part1 불변 목록 265개는 모두 일치한다. 이전 수정본의 `검증결과`는 복사하지 않았다.

## 검증

| 검사 | 결과 |
|---|---|
| `find_capture` 집중 시험 | 7개 통과. 동일 크기·동일 수정 시각의 파일 교체를 거부함. |
| 관련 회귀시험 | 299개 통과, 기존 실패 4개 제외. 제외 항목은 아래와 같음. |
| 실제 XAU BAR 재생 | 2025-09-01 이상, 2025-09-02 미만. 수정본39↔40의 SPECIAL1 알림 2건, ALL 알림 8건. 실행 ID 외 CSV 내용·순서, 사용 녹화·설정·청크 범위가 일치함. |

관련 회귀에서 제외한 4개는 수정본39에서도 실패했다: Part3 폴더가 없다고 가정하는 구형 검사, 자식 테스트 프로세스의 DuckDB 경로 누락, 새 결과 정렬 필드가 없는 가짜 워커, 옛 수정본23을 형제 폴더에서 찾는 경로 검사. 이 제외를 통과로 기록하지 않는다.

실제 재생은 보존 XAU 녹화와 임시 창고를 사용했고, 실제 MT5나 텔레그램을 실행하지 않았다. `overlap_trading_days=0`인 하루 진단 구간이며 운영 기본값은 변경하지 않았다. 첫 비교는 수정본39 폴더가 실행 중 이동해 중단됐고, 현재 경로에서 재실행한 결과만 `검증결과/무결성캐시40/actual_xau_comparison.json`에 보관했다.

단일 실행 경과시간은 SPECIAL1 19.60→26.61초, ALL 58.76→68.67초였다. 반복 측정이 아니므로 성능 회귀율로 판정하지 않는다. 반복 해시 계산의 I/O 비용은 장기 녹화에서 별도 측정이 필요하다.
