# 수정본65 — Part1·Part2 GUI를 통합 웹 UI로 정리

수정본64를 별도의 수정본65로 복사한 뒤 작업했다. 이전 검증결과와 캐시는 복사하지 않았다. 원본과 수정본64는 그대로 보존했다.

## 현재 실행

- 프로젝트 루트의 `START_MOSES.pyw`: 라이브 감시·백테스트·전략 생성을 같은 웹 화면으로 제공한다. WebView2 창은 이 웹 화면을 담는 실행 방식이다.
- `Part3/START_PART3.pyw` 또는 `python Part3/run.py --idle-exit 180`: 같은 화면을 기본 브라우저에서 연다. 마지막 탭 종료 후 약 25초, 브라우저 강제 종료 후 마지막 접속부터 3분 뒤 라이브 엔진과 서버를 정리한다. 종료 실패 시 서버를 유지하며 재시도한다.
- `python -m Part1 start|status|stop`: 저장된 전략 선택·OZ 트리거·거래시간으로 Part1을 독립 실행·조회·종료한다. 이 stop 명령은 해당 수정본만 대상으로 한다.
- `Part2/START_BACKTEST.cmd`: 환경 준비와 독립 CLI 유틸리티. `--backtest --help` 등으로 기존 `event_backtest` CLI에 인자를 전달한다. 세부 사용법은 `Part2/START_BACKTEST_KO.md`에 있다.

## 웹으로 옮긴 기능과 API

- 연결 설정의 **LIVE 기록 폴더**: 기존 `machine_roots.load_live_root/save_live_root`를 사용한다. 프로젝트 밖의 존재하는 폴더만 허용하고 컴퓨터별 설정에 저장한다. 프로젝트 연결 JSON에는 이 절대 경로를 넣지 않는다. 폴더 이동 후에도 같은 컴퓨터별 위치를 읽는 검사를 통과했다.
- 라이브 모듈 로그: 일시정지와 자동 스크롤 추가. 일시정지 중에도 모듈 상태는 갱신한다. 기존 상세 로그 설정은 유지한다.
- WATCH 모드: 수신자 ID 입력을 기존 `ui_model.make_scenario`의 `watch.chat_id`에 전달한다. 비워 두면 기존 BACKTEST 값을 사용한다. 백테스트 알림은 결과 파일로 기록한다.
- 백테스트 진행의 **상세 기록**: `GET /api/mo/backtest/log?id=...` 추가. 해당 웹 세션의 console.log를 읽고, 없으면 기존 progress.jsonl을 읽는다. 파일이 없거나 비어 있어도 안내한다. 숨긴 상태에서는 조회하지 않으며 중복 요청과 이전 실행 응답의 화면 덮어쓰기를 막는다.
- 상세 로그는 CLI의 기존 stdout/stderr를 보관한다. 이벤트 파싱에는 원문을 전달하고 저장 시 프로젝트/창고 루트만 표시용 문구로 치환한다. 한글 경로의 JSON 두 인코딩 형식도 검사했다.
- 공통 `log_tail.read_tail`로 최근 40KB만 읽는다. 생성 전략 백테스트의 기존 process.log 조회도 이 읽기 함수로 연결했다.
- Part1 공개 제어 API `start_live/stop_live/live_status` 추가. 웹과 CLI가 같은 선택·트리거·시간 전달을 사용한다. 기존 프로세스 시작/종료 정책을 유지한다.
- Part2 환경 준비의 Tk 의존과 GUI 실행 `--launch`를 제거했다. `--backtest`는 기존 독립 CLI와 종료코드를 사용한다.

라이브 전략 설정, 모듈 진단, 기존 백테스트 결과 대시보드 및 CSV/JSON 원본 다운로드를 유지했다. 웹 화면을 담는 창과 브라우저 실행을 모두 제공하지만 화면 코드는 하나다.

## 계산과 전략 계약

Part1 계산 코드, Part2 event_backtest 계산 엔진, Part3 canonical schema/Recipe v2/validator/execution_plan/compiler/AI provider 및 기존 생성 전략은 수정하지 않았다. Part1·Part2 엔진은 Part3/Tk/webview 없이 독립 CLI 도움말을 실행할 수 있다. 새 기능은 UI·연결·로그 전송에 한정한다.

코드 변경 범위와 제거 목록: `검증결과/ui65/change_scope.json`. protected 계산 변경은 0건이다. GUI의 내부 소스 모양을 고정하던 단정은 현재 공개 API의 동작 검사로 이관했다. 순수 상태·설정·계산 검사는 유지했으며 폐기된 Tk 창 전용 검사만 제외 이유를 갱신했다.

별도 Edge 검사: 기존 폴링 16건·한글 설정 13건 통과. 기본 검사에서는 이 선택적 브라우저 검사들이 제외되며, 위 PASS 숫자에는 중복 합산하지 않는다. 새 실제 JS를 Node VM에서 실행해 로그 일시정지/스크롤/상세기록/수신자 전달·비동기 응답도 공식 검사했다.
