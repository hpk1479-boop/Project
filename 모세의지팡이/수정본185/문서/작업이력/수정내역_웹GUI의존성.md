# 수정본51 — 통합 웹 경로의 기존 GUI 의존성 분리

수정본50을 복사한 수정본51에서 작업했다. 이전 수정본의 `검증결과`는 복사하지 않았다. 이 단계는 기존 Tk 화면을 삭제하기 전, 통합 웹 UI가 해당 화면을 가져오거나 실행하지 않도록 분리한 작업이다.

## 변경

- `Part1/live_control.py`에 기존 시스템 컨트롤의 라이브 시작·종료, SPECIAL 설정 함수들을 GUI 없이 분리했다. 시작 시 필요한 로그·캐시 폴더만 생성한다.
- `Part1/program/module_status_state.py`에 웹 상태 표시가 사용하는 이름·상태 판정 함수를 GUI 없이 분리했다.
- `Part3/lab/unified_live.py`는 두 GUI 독립 모듈을 사용한다.
- 사용처가 없는 옛 `/api/launch` 경로와 Part1/Part2 Tk 창 실행 함수를 제거했다. 웹의 현재 시작·종료·백테스트 API는 유지했다.
- `START_MOSES.pyw`의 시작 오류 안내에서 Tk 메시지 박스 의존성을 제거했다.
- `Part3/tests/test_web_headless51.py`에 Tk import 차단 상태의 웹 계약 및 모의 라이브 시작·종료 시험을 추가했다.

기존 Part1/Part2 데스크톱 GUI 파일은 이번 단계에서 삭제하지 않았다. `START_MOSES.pyw`도 아직 기본 브라우저를 여는 방식이며, 주소창 없는 WebView2 창은 다음 단계다.

## 검증

- Part3 테스트 전체: 46개 통과 (`검증결과/part3_web_headless_unittest.txt`).
- 수정본50 대비 Part2 파일 SHA256 변경 0건. 기존 Part1 GUI 파일 변경 0건.
- 수정본50 대비 코드 변경 파일 4개, 신규 코드·시험 파일 3개, 누락 파일 0개였다. 이 보고서는 별도 신규 파일이다.
- Tk import 차단 상태에서 웹 라이브 제어·상태 표시와 Part2 웹 옵션 계약을 확인했다.
- 실제 MT5, 텔레그램 전송, 라이브 엔진 실행은 하지 않았다. 프로세스 제어 시험은 모의 객체로 수행했다.

GUI 삭제 단계에서는 기존 화면 파일을 지우기 전에 남은 직접 실행 진입점과 동일한 상태 표시 규칙의 중복을 다시 확인해야 한다.
