# 결과 분석기 — 수정본53

수정본52 전체를 복사하고 이전 `검증결과`는 제외했다. 백테스트 엔진의 재생·전략 신호·가상 진입/청산·녹화 포맷·최적화 코드는 변경하지 않았다.

## 변경 파일

| 구분 | 파일 | 내용 |
| --- | --- | --- |
| 추가 | `Part2/event_backtest/analytics.py` | 완료된 가상 진입 CSV의 RR별 독립 분석, JSON 반환·저장 |
| 수정 | `Part2/event_backtest/workflow.py` | `runner.run()`이 완료된 뒤 분석 호출. 분석 실패 시 기존 백테스트 결과는 유지하고 `ANALYTICS_ERROR` 기록 |
| 추가 | `tests/test_result_analytics53.py` | 경계값·RR 분리·집계·경로·파일 불변·후처리 순서 시험 |

Part1과 Part3 파일은 수정하지 않았다. Part2에서 수정본52 대비 달라진 파일은 위의 분석 모듈과 workflow뿐이다. `runner.py`, `virtual_entry.py`, `virtual_source.py`, `warehouse.py`, `settings.py`의 SHA256은 수정본52와 같다.

## 입력과 산식

입력은 기존 `virtual_trades.csv`다. 실제 헤더는 `run_id, signal_id, strategy, symbol, tf, alert_time, direction, entry_time, entry_price, stop_price, rr, result, exit_time, r, target`이다. 분석기는 이 중 기록된 시각·전략·종목·TF·방향·RR·결과·R만 읽는다. 가격을 재계산하지 않는다. 빈 CSV는 기존 생성기의 축약 헤더여도 9개 RR에 빈 통계를 반환한다.

알림 하나가 RR 1.0~5.0의 9행으로 저장되므로 `rr_results`의 각 RR을 별도 실험으로 계산한다. 서로 다른 RR의 거래 수·손익·곡선을 합치지 않는다. `total_trades`는 실제 진입 수이며 미청산 진입을 포함한다. 승률·평균 R·Expectancy는 청산된 거래만 분모로 사용한다. Expectancy는 관측된 R의 평균으로 평균 R과 같다. 손실이 0건인 Profit Factor, Max Drawdown이 0인 Recovery Factor, 청산이 없는 평균·승률은 `null`로 둔다. 총 손실 R은 음수로 표시한다.

누적 R과 Drawdown은 **청산 시각 순**으로 계산하며 시작 누적 R과 이전 최고점을 0으로 둔다. 동시 청산은 알림 시각과 `signal_id`로 순서를 고정한다. 최대 연속 승·패도 같은 청산 순서다. 보유시간은 진입·청산 시각이 모두 있는 거래만 사용한다. 월·요일·시간 집계는 원본 `alert_time`의 **UTC** 기준이다. 미청산·패스도 알림 당시의 집계군에 포함된다. 진입률은 해당 RR에서 `진입 수 / 알림 수`다. 기록되지 않은 수익금, 자본, 수수료, 체결 정보는 추정하지 않는다.

반환 구조는 `analyze_rows()` 또는 `analyze_csv()`의 JSON 직렬화 가능한 dict다. `rr_results["1.0"]` 등 RR별로 `summary`, `drawdown`, `streaks`, `by_direction`, `by_symbol`, `by_timeframe`, `by_strategy`, `monthly`, `weekday`, `hourly`, `equity_r_curve`, `drawdown_curve`를 제공한다. 완료된 가상 진입 실행은 러너가 `result.json`과 거래 CSV를 저장해 반환한 **뒤에만** 분석한다. 분석 결과는 같은 실행 폴더의 `analytics.json`에 저장하고, `result.json`에는 창고 루트 기준 상대 `analytics_path`만 추가한다. 알림 온리·데이터 구축만·중단된 실행은 분석하지 않는다.

향후 UI는 `result.json`의 `analytics_path`를 창고 루트에 결합해 `analytics.json`을 읽으면 된다. 이번에는 UI와 Part3 결과 API를 변경하지 않았다.

## 검증

- 분석 전후 거래 CSV 바이트 해시 동일(합성 결과). 저장 경로가 상대 경로이며 창고 위치를 복사해 옮긴 뒤에도 읽히는지 확인.
- 빈 결과, 거래 1건, 전승, 전패, 미청산·역크로스·손절 폭 패스, RR 분리, 손실 0인 Profit Factor, 누적 R의 2R 최대 낙폭, 연속 승패, 방향·종목·TF·전략·월·요일·시간 집계 합계: 신규 테스트 7개 통과.
- 보존된 실제 `virtual_trades.csv` 2개를 읽어 기존 `virtual_summary.csv`의 RR·전략별 알림·진입·승·패·미청산·총 R과 대조: 불일치 0건.
- `workflow.py`에서 `runner.run()` 반환 후에만 분석기를 호출하며, 러너·가상 진입 계산 파일은 SHA256 동일. 따라서 본 실행의 중간 계측·판정 경로에 분석 비용이 추가되지 않는다. 전체 실행 후에는 별도의 분석 시간이 추가된다.
- Python 구문 검사 통과.
- 기존 Part2 pytest 전체 실행은 현재 번들 Python에 `pytest`와 `duckdb`가 없어 수행하지 못했다. 임시 시험 의존성 설치도 네트워크 차단으로 실패했다. 이 제한은 `검증결과/결과분석기_검증.txt`에 기록했다. 기존 엔진 결과를 실제로 재실행해 전후 실행 시간을 비교한 시험은 수행하지 않았다.
