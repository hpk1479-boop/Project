수정본88 — 외부 AI 요청 문맥 축소와 오류 원인 구분

문제와 변경
짧은 사용자 문장에도 전체 응답 schema, 중복 vocabulary와 계약 설명이 함께 전송됐다.
schema의 동일 정의를 공유하는 것만으로는 작은 문맥 모델의 한도를 해결하지 못했다.
Groq/Gemini가 공통 외부 요청 준비 계층을 사용하도록 정리했다.
전체 schema는 로컬에 보존하고, 모델에는 출력 구조·지원 조건 목록·공통 의미 규칙을 보낸다.
현재 요청 및 직전 canonical에 관련된 조건의 상세 형식과 예제만 추가한다.
원래 schema에 대한 parse_reply 검증과 후속 intent 검증은 그대로 수행한다.
번호별 실행 분기·원문 정답 매칭·자동 모델 전환·검증 우회는 추가하지 않았다.

공통 Reference Pack
common_ai/reference_pack.json:
- version: 공개 언어 자료의 버전
- core_rules: 조건·순서·봉 기준·방향·객체 참조·수명·확인 규칙
- examples: 확정 예제 100개의 입력과 의미 설명
- condition_terms: 관련 조건 설명을 검색하기 위한 공개 용어 목록
교육 예제의 과거 pseudo JSON이나 소스코드를 전송하지 않는다.
예제 번호는 자료 ID일 뿐 실행 판단에 사용하지 않는다.
현재 사용자가 정정한 부모 OZ의 활성 수명과 SAME_FVG의 OZ 발생/시작점 의미를 보존한다.

재사용 방식
공통 AI Service 시작 시 immutable Pack을 메모리에 읽는다.
요청마다 파일을 다시 읽지 않고 관련 예제 최대 2개를 전체 예제 단위로 선별한다.
예제 전송 텍스트는 최대 900자로 제한한다. 무관한 요청에는 예제를 붙이지 않는다.
Groq/Gemini 모두 동일한 Pack과 schema에서 생성한 공통 출력 설명을 사용한다.
고정 system prefix와 사용자별 선택 정보/현재 intent/관련 예제를 분리했다.
지원 서비스·모델의 자동 prompt cache가 활용할 수 있는 구조이며, cache hit를 보장하지 않는다.
Gemini 별도 explicit context cache를 생성하지 않았다. cache가 문맥 한도 문제의 해결책은 아니다.
모델/Provider 변경 시 기존 공통 설정 변경·generation 무효화 경로를 유지한다.
WATCH/BACKTEST/전략 연구의 기존 schema와 역할을 유지하고 사전 AI 분류 호출을 추가하지 않았다.

보안과 오류
전송 준비 전에 기존 external_payload 허용 목록을 다시 적용한다.
현재 intent·Recipe·안전한 vocabulary/registry 정보만 허용하며 코드/파일/로그/인증정보를 전송하지 않는다.
키는 기존 인증 헤더로만 사용하고 API 오류 원문·실패 생성문을 UI에 그대로 표시하지 않는다.
공통 오류 분류: 키/권한, 모델 형식·미지원·종료, 입력 문맥, 요청 크기,
응답 길이, JSON 옵션/schema 지원, JSON 생성, 사용량/요청 속도, 연결/대기시간, 서버 오류.
모델 응답의 JSON 문법 실패와 MOSES 원래 schema 검증 실패도 구분한다.

전송량 확인
동일한 짧은 사용자 요청과 현재 공개 계약으로 외부 호출 없이 비교했다.
이전 전체 schema 텍스트 전송 구조를 재구성한 요청: 33,572 bytes.
현재 공통 준비 계층의 요청: 10,144 bytes. 69.8% 감소.
두 측정 모두 합성 모델 ID를 사용했고 실제 키나 전체 payload를 증거 파일에 저장하지 않았다.
전송 크기는 요청·현재 intent·도구 결과·선택 모델에 따라 달라지며 모든 모델의 한도를 보장하지 않는다.

실호출 확인의 한계
사용자가 선택한 Groq allam-2-7b로 같은 짧은 요청을 확인했다.
최종 요청 10,081 bytes는 입력 문맥 초과 대신 JSON 생성 실패로 반환됐다(HTTP 400).
입력 한도 문제는 해소됐지만 이 실모델의 유효한 전체 intent 생성은 완료되지 않았다.
다른 모델로 자동 변경하거나 실패한 JSON을 적용하지 않았다.
Gemini의 실제 추론 성공은 이번 작업에서 확인하지 않았다. Gemini 전송/검증은 합성 응답으로 검사했다.

적용
실행 중인 MOSES 창을 정상 종료하고 START_MOSES.pyw를 다시 실행한다.
선택 모델과 저장한 키는 유지된다. 유효한 JSON과 사용자 확인 전에는 전략을 적용하지 않는다.
