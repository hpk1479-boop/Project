## 1. "EMA21은 EMA20으로" 예외 삭제

예전 표기 호환 때문에 EMA21을 EMA20으로 바꿔 읽는 규칙이 네 곳에 있었고, 레시피 실행기는 이를 피하려고 21만 따로 계산하는 우회로를 두고 있었습니다.

| 위치 | 변경 |
|---|---|
| `Part1/program/watch_ma.py` | MA 이름 해석의 "EMA21이면 20" 규칙 삭제 |
| `Part1/program/watch_orchestrator.py` | 시간연쇄 크로스의 "21이면 20" 규칙 삭제 |
| `Part1/program/command_interpreter.py`, `moses_language/language.json` | 명령 문장 정리의 "EMA21/21EMA → EMA20/20EMA" 바꾸기 2개 삭제 |
| `Part1/program/strategy_recipe/port.py` | EMA21 전용 우회 계산과 그 캐시 삭제 → 공통 MA 저장소 사용 |

## 2. 짧은 크로스 명령도 공통 경로로

"골드 1분 EMA20 50 골크", 시간연쇄 "…EMA50 200 골크나면" 같은 짧은 크로스 명령은 EA가 보내는 길이(EMA 20·50·200, HMA 6·17·50·168)만 받고, EA가 보낸 열을 직접 읽어 판정했습니다.

| 위치 | 변경 |
|---|---|
| `Part1/program/watch_orchestrator.py` | 허용 길이 목록(`GENERIC_MA_PERIODS`) 삭제. 길이 규칙은 공통 MA 이름 문법(양의 정수) 하나 |
| `Part1/program/event_engine/watch_runtime.py` | 두 선의 값을 비교식 명령과 같은 공통 MA 저장소(`WatchMAStore`)에서 받음. EA가 보내는 길이는 저장소가 EA 값을 그대로 돌려주므로 기존 명령의 판정은 그대로 |
| `Part3/lab/catalog.py` | 쓰이지 않던 `MA_PERIODS`(허용 목록 사본) 삭제 |
| `통합설치/releasekit/tests/test_runtime_bundle.py` | 설치본 확인 값 `catalog.MA_PERIODS` → 같은 성격의 `catalog.OZ_TFS` |

## 바뀌는 동작

| 명령 | 수정본120 | 수정본121 |
|---|---|---|
| `골드 1분 EMA21 > EMA50 알려줘` 등 비교식 | EMA20으로 계산 | **EMA21로 계산** |
| `골드 1분 EMA21 50 골크 알려줘` | EMA20/50 크로스 | **EMA21/50 크로스** |
| `골드 1분 EMA22 50 데크 알려줘`, `HMA18 30 골크` | 거부 | **받아서 공통 경로로 계산** |
| 시간연쇄 `…EMA21 50 골크나면…` | EMA20/50 | **EMA21/50** |
| AI 레시피의 EMA21 | 우회로로 21 계산 | 공통 경로로 21 계산 (값은 같은 공식) |
| EA 길이(EMA20·50·200, HMA6·17·50·168) 명령 | EA 값 | EA 값 (변화 없음, 실제 백테스트 162건 동일) |

- 이미 "EMA21"로 걸어 둔 감시가 있다면 앞으로 EMA20이 아니라 진짜 EMA21로 판정합니다. 예전에 EMA21로 등록해 EMA20으로 저장된 시간연쇄는 저장값이 20이라 그대로 EMA20입니다.
- 명령 문장 정리 결과에서 `EMA21`은 다른 길이(`ema22`)처럼 소문자 `ema21`로 나옵니다. 이후 해석은 대소문자를 가리지 않아 동작 차이는 없습니다.
- 짧은 크로스 명령은 이제 비교식 명령과 같은 규칙으로 데이터를 고릅니다. 예전에는 EMA20·50·200 세 열이 모두 유효해야 판정했지만, 이제는 그 명령이 쓰는 두 선만 봅니다(두 선 값이 비어 있으면 판정하지 않는 것은 같음). 650봉 창에서는 세 열이 모두 채워져 있어 실제 차이는 없습니다.

## 시험

- 새 시험 `tests/test_ema21_common121.py`: EMA21 이름·명령 문장 유지, 비교식·골든크로스·기울기 명령의 EMA21, 짧은 크로스가 어떤 길이든 받음(0 같은 잘못된 길이와 같은 두 선은 거부), 공통 저장소의 EMA21·EMA22가 전체 공식과 같은 값, 짧은 크로스(EMA21 대 EA EMA50, HMA18 대 HMA30)가 **진행봉에서만 넘으면 울리지 않고 확정봉에서 넘을 때만** 울림.
- "EMA21 = EMA20"을 전제로 하던 기존 시험 4곳(`test_command_dictionary90`, `test_schema_cleanup`, `test_ma_strategy_chain49`, `Part3/tests/test_common_recipe60`)을 새 규칙으로 바꿈.

## 그대로 둔 것

- MT5 EA: 실제로 EMA21을 계산하지 않습니다. 시작 안내 문장의 "EMA20/21/50/200" 글자만 남아 있으며, EA 수정 때(기존 녹화 호환 확인과 함께) 고칩니다.
- ATR 길이 14 → 공용 ATR14 재사용, EMA 길이 1 → 종가: 의미를 바꾸지 않는 계산 재사용이라 그대로 둠.

## 참고 (이번 범위 밖)

컴포저의 개인 전략 MA 조건(MA 상태·가격 대비·기울기)은 또 다른 계산 경로(`staff_compat`의 MA 열 추가)로 MA 값을 가져옵니다. 같은 MA를 두 경로에서 계산하는 셈이라, 공통 경로로 합칠지 따로 결정이 필요합니다.
