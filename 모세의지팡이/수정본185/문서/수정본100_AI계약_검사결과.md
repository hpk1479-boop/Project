# 수정본100 AI 계약·언어사전 검사

검사일: 2026-10-04. 수정본99를 복사하여 수정본100을 만들었습니다. 프로그램과 배포 제작 코드는 변경하지 않았습니다.

## 결과

**현재 기준으로 개발자용과 배포용의 AI 계약·언어사전·지원 규칙 누락은 발견되지 않았습니다.** 다만 AI에 보내는 문장의 선택값 나열 순서까지 항상 동일하게 고정되어 있지는 않습니다.

| 검사 항목 | 결과 |

| 명령 별칭·조건 용어·공통 규칙·참고 예제 | 동일 |

## 발견한 순서 문제

`Part1/program/oz_profiles.py`의 `VALIDATION_MODES`, `TRIGGER_MODES`는 순서가 고정되지 않는 `frozenset`입니다. `Part3/lab/ai/schema.py`에서 이를 정렬하지 않고 JSON의 선택값 목록으로 만듭니다.

그 결과 `NORMAL / BLIND` 또는 `OZ / BREAKER`가 반대 순서로 나열될 수 있습니다. 선택 가능한 값, 필수 필드, 해석 규칙이 사라지거나 바뀐 것은 아닙니다. 개발자용과 배포용 모두 같은 공통 코드에 존재하는 현상입니다. AI가 받는 문장을 정확히 고정하려면 이 목록을 정렬해야 합니다. 이 검사에서는 수정하지 않았습니다.

새 프로세스에서 5가지 해시 시드로 각각 개발자용과 배포용을 실행했습니다. 총 10회 검사에서 같은 조건의 두 환경은 일치했고, 선택값 순서만 표준화하여 비교하면 전체 내용이 일치했습니다. 순서 변경이 실제 AI 답변에 미치는 영향은 이 검사에서 측정하지 않았습니다.

## 배포 시 의도적으로 달라지는 설정

- 개발자의 API 키와 AI 연결 설정은 배포본에 전달하지 않습니다. 새 설치의 `settings/ai_settings.json`은 비워집니다.
- 프로그램 설정의 Telegram·Gemini 인증 값은 배포 시 제거합니다. AI 계약에 쓰이는 종목·세션 정보는 유지되며 비교 결과도 같았습니다.
- 개발자의 `Part3/generated`, `Part3/projects`, 전략 숨김 설정은 새 설치에 복사하지 않습니다. 사용자마다 추가·삭제한 전략이나 종목 설정이 다르면 AI가 조회하는 현재 목록도 달라질 수 있습니다.
- AI 모델 파일과 Ollama 등 실행 프로그램은 기존 정책대로 포함하지 않습니다.

## 검사 범위와 원본 보존

실제 배포 제작 함수 `source_paths`, `prepare_data`, `build_code_bundle`로 검사 자료를 만든 뒤, 원본 Python 코드가 없는 배포 구조에서 실제 `RuntimeBundle` 로더를 실행했습니다. 개발자 환경과 별도 프로세스에서 AI 요청 생성 결과를 비교했습니다. 새 Setup EXE 전체 빌드 및 실제 AI 모델/API 호출은 수행하지 않았습니다.

수정본99와 수정본100에 복사한 기존 파일 3,674개의 해시를 재확인했습니다. 두 버전 모두 기존 파일 변경은 없습니다. 검사 자료와 이 문서만 추가했습니다. 배포 산출물 및 재생성용 `.work`, `prerequisites`, `.buildenv`, `.buildtmp`는 버전 복사에서 제외했습니다.
