# 수정본138 설정 화면 정리

기준: `문서/체크리스트_설정화면정리.md`의 결정(2026-10-07). 수정본137을 복사해 시작했고, 137의 검증결과는 가져오지 않았다.

## 바뀐 것

### 설정 화면 (`Part3/web`)
- 설명 문단을 모두 지웠다. 칸 이름만 남기고, 형식이 필요한 칸은 입력칸 안의 예시로만 보여 준다.
- 저장 결과는 각 저장 버튼 옆에 나온다(라이브 / 백테스트 / 연결 위치 / AI). 창은 띄우지 않는다. 성공 문구는 4초 뒤 사라지고 오류는 빨간 글씨로 남는다.
  - 라이브: "설정이 저장되었습니다 · 라이브 다시 시작 후 적용", 나머지: "설정이 저장되었습니다".
- 텔레그램 칸 이름: 봇 토큰 / 알림방 (그룹·채널 번호) / 명령방 (내 텔레그램 번호).
- 한 칸짜리 묶음 셋(감시 종목·경제지표 알림·알림 기록)은 묶음 제목과 칸 이름이 같은 말을 반복해서 "기본" 묶음 하나로 합쳤다.
- [대화방 불러오기]: 봇이 받은 메시지에서 1:1 대화·그룹·채널을 찾아 목록으로 보여 준다. [알림방으로]/[명령방으로]를 누르면 그 칸에 넣고 바로 확인·저장한다. 명령방은 1:1 대화만 고를 수 있다.
  - 라이브가 돌고 있으면 "불러오려면 라이브 감시를 잠시 멈춰야 합니다. 멈추고 불러올까요?"를 먼저 묻는다. 확인하면 멈추고 읽은 뒤 라이브를 다시 시작한다.
  - 찾은 방이 없을 때 안내는 라이브가 돌던 경우와 아니던 경우를 나눠 보여 준다(아래 "남은 문제" 1).
- Gemini API 키 옆에 [확인]: Google에 키를 확인하고 바로 저장한 뒤 모델 목록을 다시 불러온다. 실패 문구에서는 키를 [숨김]으로 가린다.

### 서버 (`Part3/lab`)
- `unified_settings`: 엔진이 실제로 읽는 설정만 보여 주고 저장한다(`LIVE_KEYS` + `POINT_*`). 예전 config.txt에 남은 줄은 보이지 않고 저장도 거절한다.
- `telegram_chats` (`/api/mo/settings/telegram_chats`), `telegram_connection.recent_chats` 추가. 명령방 확인은 1:1 대화 번호만 통과한다.

### 안 쓰는 설정 9개와 예전 ZMQ 서버
- STAFF_BIND_ENDPOINT, STAFF_ENDPOINT, MANAGER_ALERT_ENDPOINT, ZMQ_TIMEOUT_MS, STAFF_BARS, STAFF_ALLOWED_TIMEFRAMES, CONFIG_RELOAD_SEC, ENGINE_SUBSCRIPTION_REFRESH_SEC, OZ_COMMAND_FILE를 화면·`config.txt`·코드에서 지웠다.
- `THE STAFF OF MOSES.py`의 `DataServer`·`main`과 `staff_snapshot.py`를 지웠다. 라이브는 `StaffPipeCache`만 쓴다.
- pyzmq를 통합설치 의존성에서 뺐다. 예전 서버를 검사하던 `Part2/validation_suite/test_staff_s1~s8`을 지웠다.

### LoRA 제거
- 실행 방식은 gemini / ollama / local_gguf / disabled. LoRA 코드·설정 칸·문서·시험을 지웠다.
- 여러 AI가 같이 쓰던 응답 형식 함수는 `common_ai/reply_format.py`로 옮겼다.

### 백테스트 작업 구간 크기(work_size) 제거
- 설정 칸, `--work-size`, 기본값·검사를 지웠다. `plan_periods(start, end, workers)`가 한 달 → 주 → 하루 순서로 나눈다(예전 자동 방식과 같은 규칙).

### 매뉴얼
- 텔레그램 장: 봇 토큰 → 대화방 불러오기 순서로 다시 썼다. getUpdates 주소를 직접 여는 절차와 옛 화면 그림 6장을 지웠다.
- AI 장: Gemini 키 [확인] 순서, "내 PC에서 AI 돌리기 · Ollama와 GGUF" 쪽을 추가했다.
- 9장 "설정 화면"(5쪽)을 새로 넣었다: 네 묶음과 저장 결과, 기본, 상세 설정, 세션 시간과 갱신 주기, 백테스트 설정과 데이터 폴더. 설명은 코드에서 확인한 실제 동작을 기준으로 썼다.
- 그림은 정리된 실제 화면(배포 config.txt 값)을 찍어 `매뉴얼/편집원본/그림/set_*.png`로 넣었다. 매뉴얼 40쪽, 간단사용서 3쪽.

## 결과가 달라지는 것
- 라이브 알림·백테스트 결과는 바뀌지 않는다. 지운 설정 9개는 읽는 곳이 없었고, 작업 구간 나누기는 예전 자동 규칙과 같다. 예전에 work_size를 직접 골라 저장한 PC는 그 값을 더 읽지 않는다. 조각 크기는 속도만 바꾸고 결과는 같다(앞 구간을 겹쳐 읽음).
- `provider=local_lora`로 저장된 PC는 AI 설정을 읽을 때 "AI 실행 방식" 오류가 난다. 변환 코드는 넣지 않았다(레거시 금지 결정). 설정 화면에서 다른 방식을 고르면 된다.

## 남은 문제
1. **라이브가 켜진 채로 보낸 /start·초대는 불러오기에 안 나온다.** 라이브(`event_host.telegram_loop`)는 봇 메시지를 계속 읽고 확인 처리하므로, 불러오기를 누르기 전에 이미 사라진다. 또 라이브가 `allowed_updates=["message"]`로 받기 때문에, 그 봇으로 라이브를 쓴 적이 있으면 채널 초대 알림이 텔레그램에 남지 않는다. 처음 연결할 때는 문제없다. 지금은 화면 안내와 매뉴얼에 "전체 종료 후 보내고 불러오기"로 적었다. 제대로 고치려면 라이브가 받은 대화방을 기록해 두고 불러오기가 그것을 읽어야 한다(Part1 변경이라 사용자 결정 필요).
2. `COMPOSER_POLL_SEC`: 예전 공식 체인(OFFICIAL_SPECS) 경로에서만 쓴다. 화면에서는 숨겼고 그 경로는 그대로 두었다.
3. `config.txt`의 `GEMINI_*` 줄: `Part3/lab/storage.py`가 예전 키를 읽는 대체 경로로 쓴다. 이번 범위가 아니라 두었다.
4. 기본 시험 묶음에 없는 예전 진단 파일(`verification/`, `build/`, `test_settings_korean59.cjs`, `test_model_choices_ui87.cjs`, `test_gemini_key_ui86.cjs` 등)은 지운 화면 문구·LoRA를 아직 가리킨다.
5. 전략 설정 창의 안내문 "…라이브 엔진이 자동으로 재시작됩니다"는 설정 화면 밖이라 그대로 두었다.
