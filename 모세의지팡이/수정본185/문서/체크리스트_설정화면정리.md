## A. 사용자 요청

1. **저장 반응이 없다.**
   - 요청: 저장을 누르면 그 버튼 옆 빈 공간에 "설정이 저장되었습니다"를 띄운다. 창은 띄우지 않는다. 모든 설정 저장 버튼에 똑같이 적용한다.
   - 원인: 결과 문구가 설정 화면 맨 아래(AI 설정 밑) 한 곳(`#settings-message`)에만 나온다. 위쪽의 "라이브 감시 설정 저장"을 누르면 문구가 화면 밖에 뜬다.
   - 대상: 라이브 감시 설정 저장 / 백테스트 설정 저장 / 연결 위치 저장 / AI 설정 저장.
   - "변경한 값이 없습니다"와 오류 문구도 같은 자리에 띄운다.
   - 전략 설정 창(✓ 저장·적용)과 거래시간 편집(이미 "설정되었습니다" 표시)도 같은 방식인지 맞춘다.
2. **제미나이 API 키에도 확인 버튼을 둔다.**
   - 요청: 봇 연결 키처럼 입력칸 옆에 [확인]을 둔다. 연결을 확인하면 저장한다.
   - 지금: "AI 설정 저장"을 눌러야 확인된다.
3. **텔레그램 칸 이름과 설명을 알 수 없다.** "알림을 받을 채팅방", "명령을 보낼 수 있는 채팅방"으로는 무엇을 넣어야 하는지 모른다. 실제로 넣는 값은 다음과 같다.
   - 알림방: 알림을 올릴 그룹·채널의 번호(예: -100…) 또는 @채널이름. 봇을 그 방에 넣고 메시지 권한을 줘야 한다.
   - 명령방: 봇과 1:1로 대화한 내 텔레그램 번호(숫자). 여러 개면 쉼표로 구분한다.
4. **챗 아이디를 자동으로 불러온다.**
   - 가능하다. 봇에게 아무 메시지나 보내거나, 봇을 그룹·채널에 넣고 글을 올리면 텔레그램(getUpdates)이 그 대화방 번호와 종류(개인·그룹·채널)를 알려 준다. [불러오기]로 목록을 보여 주고 골라 넣게 하면 된다.
   - 주의: 라이브가 같은 봇으로 메시지를 받는 중이면 서로 충돌한다(두 PC 409 문제와 같은 원인). 라이브를 멈춘 상태에서만 불러오거나, 라이브가 받은 대화방을 기록해 두었다가 보여 주는 방식이 필요하다.
   - 텔레그램 공식 문서로 확인한 내용(2026-10-07, core.telegram.org/bots/api, /bots):
     - **그룹·채널은 스타트가 필요 없다.** 봇을 그룹에 초대하거나 채널 관리자로 추가하면 텔레그램이 `my_chat_member`(봇의 멤버 상태 변경) 알림을 보낸다. 그 안에 그룹·채널 번호와 이름이 들어 있다.
     - **1:1 명령방은 스타트(또는 메시지 1번)가 꼭 필요하다.** 공식 문구: "Bots can't start conversations with users. A user must either add them to a group or send them a message first." 그래야 번호를 알 수 있고 봇이 답장할 수 있다.
     - 텔레그램은 이런 알림을 **24시간만** 보관한다. 초대한 뒤 24시간 안에 불러와야 한다.
     - 웹훅이 걸린 봇은 getUpdates를 쓸 수 없다(우리 프로그램은 웹훅을 쓰지 않음).
     - 우리 라이브는 `getUpdates`를 `allowed_updates=["message"]`로 받고 offset으로 확인 처리한다(`event_host.py`). 라이브가 도는 동안에는 초대 알림(`my_chat_member`)이 전달되지 않고, 라이브가 확인 처리한 알림은 사라진다. 그래서 불러오기는 라이브를 멈춘 상태에서 해야 한다.
     - 불러올 때는 `allowed_updates`에 `message`, `my_chat_member`, `channel_post`를 넣어야 한다.
   - 사용자 흐름(2026-10-07 확인):
     1. 봇 토큰을 넣고 [확인]을 누른다.
     2. 봇과의 1:1 대화에서 스타트(/start)를 누른다. 그 메시지에 내 번호(chat.id)와 이름·사용자명이 들어 있다.
     3. 알림방으로 쓸 그룹·채널에 봇을 초대한다.
     4. [불러오기]를 누르고 "그룹 ○○ / 채널 ○○ / 개인 이름(@사용자명)" 목록에서 알림방과 명령방을 고른다.
     - 다른 사람이 봇에게 보낸 대화도 목록에 나오므로 이름을 보고 고르게 한다. 예전에 스타트를 눌렀다면 아무 메시지나 한 번 보내면 된다.
   - 라이브가 켜져 있을 때 [불러오기] (2026-10-07, 사용자 제안: "불러오기를 누르면 라이브를 멈추시겠냐는 안내문구를 띄우는거 어때")
     - 라이브가 켜져 있을 때만 확인창을 띄운다: "불러오려면 라이브 감시를 잠시 멈춰야 합니다. 멈추고 불러올까요?" [멈추고 불러오기] [취소]. 꺼져 있으면 바로 불러온다.
     - 다 불러오면 라이브를 자동으로 다시 켠다(추천, 멈춘 것을 잊어 알림을 놓치지 않게).
     - 다른 PC에서 같은 봇이 돌아 409가 나면 "다른 PC에서 같은 봇이 실행 중입니다"를 보여 준다.
     - 저장 결과는 창 없이 버튼 옆에 띄우지만, 이 확인창은 라이브를 멈추는 동작이라 예외로 둔다.

## B. 동작과 다른 설명

5. **기본 종목 목록 (SYMBOLS)**
   - 설명: "참고할 종목"
   - 실제: 기본 스페셜 8개가 감시하는 종목이다(모두 `symbol_source=CONFIG`). 비우면 스페셜이 하나도 돌지 않는다.
6. **주요 거래 시간 (MAIN_ASIA·LONDON·NEWYORK)**
   - 설명: 명령이 쓰는 시간
   - 실제: 스페셜의 기본 거래시간도 이 값이다(`special_time_slot`). 바꾸면 스페셜 알림 시간이 바뀐다.
7. **장 시간 (ASIA·LONDON·NEWYORK)**
   - 설명: "시간대 판독 범위"
   - 실제: 런던·뉴욕 시작 시각은 외부유동성(SPECIAL2)의 "이전 세션 고가·저가" 기준이다(`sweep_levels`). 세 값 모두 "세션 시작" 조건에도 쓰인다. 시각은 한국시간이다.
8. **명령방 검사가 틀렸다.**
   - 확인 버튼은 그룹 번호도 통과시킨다(`telegram_connection._chat`).
   - 라이브는 1:1 개인 대화의 명령만 받는다(`event_host`: `type!='private'`이면 무시).
   - 그래서 그룹 번호를 넣으면 확인은 통과하는데 명령은 조용히 무시된다.
9. **참고 시간봉 목록 (STAFF_ALLOWED_TIMEFRAMES), 보관할 과거 봉 개수 (STAFF_BARS)**
   - 지금 라이브 엔진은 이 값을 쓰지 않는다. 예전 단독 데이터 서버(`DataServer`)에서만 쓴다.
10. **연결 주소 3개와 내부 통신 대기 시간 (STAFF_BIND_ENDPOINT, STAFF_ENDPOINT, MANAGER_ALERT_ENDPOINT, ZMQ_TIMEOUT_MS)**
    - 지금은 MT5 → 프로그램 한 곳에서 처리한다. 값을 읽기만 하고 쓰지 않는다. 예전 여러 프로그램 구조의 흔적이다.
    - "다른 감시 프로그램이 …" 같은 설명도 지금 구조와 다르다.
11. **전략 설정 변경 확인 간격 (CONFIG_RELOAD_SEC), 감시 목록 갱신 간격 (ENGINE_SUBSCRIPTION_REFRESH_SEC)**
    - 코드 어디에서도 읽지 않는다.
12. **감시 조건 확인 간격 (COMPOSER_POLL_SEC)**
    - 설명과 달리 주기적으로 확인하는 간격이 아니다.
    - 예전 방식 공식 체인에서 이평 상태가 유효한 시간으로만 쓰인다. 기본 스페셜 레시피는 이 경로를 쓰지 않는다.
13. **감시 명령 저장 파일 (OZ_COMMAND_FILE)**
    - 라이브 시작 때 경로만 기록하고 내용은 읽지 않는다. 사실상 쓰이지 않는다.

## 결정 (2026-10-07)

사용자 말: "일단 불필요한 설명 싹 걷어내고 필요하면 저 UI이미지를 그대로 해서 메뉴얼에 넣어서 거기에 자세한 설명을 넣어줘. 코드 수정하지마라"

  - 설정 화면의 설명 문장을 모두 걷어낸다. C 항목 전부와 항목마다 붙은 설명 문구가 대상이다.

- **매뉴얼**
  - 정리된 설정 화면을 실제로 캡처해 그대로 넣는다.

  - 대상 화면: 라이브 감시 설정(종목, 텔레그램, 개인채팅 알림, 경제지표, 알림 기록, 상세 설정 묶음), 백테스트 설정, 데이터 폴더와 실행 프로그램, 공통 AI 설정.
- **순서**
  - 코드 수정은 사용자가 지시할 때 한다(2026-10-07 현재 "코드 수정하지마라").
  - 화면 정리 → 정리된 화면 캡처 → 매뉴얼 작성 순서로 한다. 캡처는 화면을 정리한 뒤에 해야 한다.
