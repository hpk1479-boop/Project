# 작업 취소

백테스트와 데이터 구축의 정지·취소는 같은 방식으로 동작합니다.

- 처음 누르면 기존 정상 중지와 부분 결과 저장을 요청합니다. 화면은 `종료 중입니다. 진행 내용을 저장하고 있습니다.`를 표시합니다.
- 종료 중 다시 누르면 `강제 종료하시겠습니까?`를 확인합니다. 아니요는 기존 정상 종료를 계속 기다립니다. 예는 선택한 작업만 강제 종료합니다.
- 첫 중지 응답이 늦어도 같은 버튼으로 강제 종료를 요청할 수 있습니다. 작업이 실제로 끝날 때까지 상태 조회와 버튼을 유지합니다.
- 다른 백테스트·라이브 감시·사용자가 별도로 연 MT5는 종료하지 않습니다. 선택한 실행의 PID, 생성 시각, 관리 실행 ID와 프로젝트·창고 경로를 검증한 프로세스 및 해당 자식만 종료합니다.
- 정상 중지 기능, 이미 저장한 결과·녹화 데이터·창고의 복구 파일은 유지합니다. 강제 종료 시 저장하지 못한 결과 파일을 만들어내지 않습니다.

확인 결과는 `검증결과/revision111/backtest_cancel`에 기록했습니다.

- 백엔드 취소·종료·소유권·HTTP 경로: 67개 통과
- 기존 화면 및 별도 작업 프로세스의 정상 저장 후 중지: 16개, 18개 하위 검증 통과
- 실제 Part3 HTML·JavaScript를 연 독립 Edge에서 첫 요청 지연, 두 번째 취소, 예·아니요, 상태 복구, 실패 후 재시도: 8개 통과
- 실제 Windows에서 가짜 작업 2개를 동시에 실행하고 선택한 작업의 관리 프로세스·작업 프로세스·손자 프로세스를 강제 종료했습니다. 0.037초였으며 다른 작업과 손자는 계속 실행되었습니다. 이 시험은 실제 MT5나 사용자 데이터에 접근하지 않았습니다.

추가 기존 폴링 시험은 15/16이었습니다. 완료 결과 조회에 일시 오류가 발생하면 자동 재조회가 멈추는 기존 시험 하나가 실패했고, 수정 전 110에서도 동일 실패를 확인했습니다. 현재 요청의 취소 기능과 무관하여 이 동작은 변경하지 않았습니다.
