# 수정본 143: 기준 프레임 변경 의미 보존

SPECIAL8의 기준을 2분으로 고르면 처음부터 2분으로 작성한 전략처럼, 5분이면 처음부터 5분으로 작성한 전략처럼 시험한다. 골크·터치·취소 조건과 진입 확인봉·기본 손절이 모두 선택한 기준을 사용한다. 전략의 기존 조건, 기간, 확정봉·진행봉 의미는 유지한다.

## 수정한 두 가지

1. AI에서 “기준만 변경”과 “시간봉을 별도로 지정한 전체 설정”을 구분한다. 기준 변경은 `request.base_frame`에 목적 시간봉을 받고, 프로그램이 변경 전 정책 또는 레시피 기본값의 시간봉을 함께 옮긴다. SPECIAL9의 2분 기준은 전략도 2분/20분, 가상진입도 2분/20분이다. 사용자가 15분 추세를 별도로 지정한 전체 정책은 그대로 받는다. 전략을 고르는 확인 질문이 필요하면 미처리 기준 변경을 보존하고, 적용 후에는 실행 정책만 남겨 확인·기간 수정에서 다시 변경하지 않는다.
2. 화면에서 각 시간봉의 최초 기준과 선택 값을 기억한다. 예를 들어 1분 기준에서 표 밖 값인 2분 손절을 지정했다면, 1→3분으로 바로 바꾸거나 1→2→3분으로 바꾸거나 모두 2분 손절을 유지한다. 숫자 시간봉이 현재 기준과 같아졌다고 기준 참조로 바꾸지 않는다. 직접 시간봉을 수정한 경우는 그때의 기준에서 새 의미를 기록한다.

화면의 기억은 `virtual_entry_bindings`라는 별도 저장 정보로 남긴다. 전략·가상진입 실행 정책에는 넣지 않는다. 잘못된 저장 정보는 버리고 정상 실행 정책을 유지한다. 이전 수정본에서 저장한 정책은 최초 로드 시 현재 기준에서 의미를 정하며, 과거 선택 순서를 추측하지 않는다.

사용자가 정상이라고 확인한 3번 동작은 유지한다. SPECIAL8에서 15분 손절을 지정하고 최상위가 없는 4시간 기준으로 바꿔도 4시간 선택을 허용하며 15분을 유지한다.

AI의 기준 변경 연산은 입력한 변경 전 정책의 현재 기준 표를 사용한다. 화면의 과거 선택 정보는 AI 정책에 추가하지 않는다. 아직 파일로 저장되지 않은 연구 초안은 기준 변경에 필요한 등록 레시피를 찾지 못하면 실행을 거부한다.

## 검증 결과

서로 다른 pytest 시험 총 **507개 통과**: 관련 시험 505개, 실제 Edge 화면 시험 1개, 폴더 이동 후 저장·로드 시험 1개. 이 중 신규 회귀시험은 61개다. Edge 시험에는 실제 조작 4개 시나리오가 포함되고, 원문 함수·변경 이벤트 시험에는 9개 시나리오가 포함된다. Python 12개 파일과 JavaScript 3개 파일의 문법 검사도 통과했다.

- SPECIAL8: 2분·5분으로 직접 작성한 독립 전략과 실제 이동 전략에 같은 입력을 주어 알림 시점이 같은지 확인했다. 해당 시간봉의 확인봉 다음 시가 진입과 독립 계산한 Wilder ATR14 손절도 확인했다. 함께 넣은 1분 데이터는 방향과 ATR을 다르게 만들어 잘못 사용하면 시험이 실패하도록 했다.
- SPECIAL9: 15분·20분 추세가 서로 반대인 입력에서, 2분 기준 변경은 20분 추세로 진입 여부를 판단했다. 별도 지정한 15분 정책은 15분으로 판단했다.
- 확정봉·진행봉 경계, 진입 조건·손절·공통 정책, AI 전송·확인 경로의 관련 기존 시험을 통과했다.
- 실제 Edge의 HTML/CSS/JS에서 고정 시간봉의 직접·경유 선택, 저장 후 재로드, SPECIAL8 2분·5분 표시, SPECIAL9 20분·30분 추세, SPECIAL8 최상위 없는 4시간 선택을 확인했다. 스크린샷도 확인했다.
- 프로젝트 설정 폴더를 A에서 B로 옮긴 뒤 정책과 화면 저장 정보를 읽고 다시 저장할 수 있었다. 저장 파일에는 A·B의 절대 위치를 기록하지 않았다.

시험은 합성 입력과 가짜 API·AI 응답을 사용했다. 실제 MT5 실시간 연결, 텔레그램 발송, 실제 AI 모델의 자연어 해석 정확도는 이 시험에 포함하지 않았다. 전체 프로젝트의 모든 시험을 실행했다는 뜻은 아니다.
