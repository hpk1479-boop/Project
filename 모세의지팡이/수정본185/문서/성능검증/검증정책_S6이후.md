# 검증 정책 — 사용자 변경 지시 (2026-09-26)

이 정책은 S6–S8 및 이후 Event Engine/Fact DAG 리팩터링에 적용한다. 이전 단계의 내부 비트 동일성·private 구현 고정 요구보다 우선한다. S6의 구현 범위는 Wire v2에 한정하며 S7 이후는 시작하지 않는다.

## 필수 게이트

- SPECIAL/Watch/OZ/FVG 조건 판정과 상태 전이를 100% 보존한다.
- 최종 알림 발생 여부·시각·방향·문구·수신자를 100% 보존한다.
- source health/stale/reconnect/seq 누락의 의미를 보존한다.
- LIVE와 BACKTEST의 외부 결과를 일치시킨다.
- MT5 수신값, ATR14_GENERAL, OZ 상태·regime, FVG 구조, 원비 밴드 등 판정에 직접 들어가는 입력은 대표 샘플로 확인한다.

## 진단 항목

내부 DataFrame 비트 동일성, 내부 객체·캐시 구조, private 필드, 계산 중간값, set/frozenset 순서, 구현 방식은 필수 게이트가 아니다. 이 이유만으로 실패 판정하지 않는다. 대규모 내부 조합·반복 비교와 S0 골든 재생성은 하지 않는다. 이미 실행한 진단·실패 기록은 지우지 않는다.

## 외부 검증 범위

240초 합성 시나리오 외에 보존된 실제 MT5 캡처와 알림이 발생하는 확대 구간을 비교한다. 가능한 경우 여러 날 및 BTCUSD 주말 데이터를 포함한다. 구간·심볼·실제/합성 출처·비교 알림 수·조건/상태 전이 커버리지·확장하지 못한 사유를 보고한다. 알림이 없는 구간만으로 완료를 선언하지 않는다.

기존 테스트 수집 목록은 유지·기록한다. 내부 고정 구현/대규모 반복 항목은 이름과 사유를 진단 또는 미실행으로 명시하고 외부 동작 회귀를 숨기는 포괄적 예외 처리를 하지 않는다. 원비·ATR 혼용 방지와 연결/전송 견고성 테스트는 유지한다. 전체 실행은 단계 구현 완료 후 1회, 개발 중에는 영향 파일 관련 테스트만 실행한다.

## 의도된 변경

S7 원비 및 폴링→이벤트 전환의 알림 시점 변화처럼 의도된 기준 변경은 별도 사용자 승인 변경으로 기록한다. 달라진 알림과 원인을 남긴 뒤 새 기준선을 고정한다. 이번 S6에는 이러한 의미 변경을 승인받지 않았다.

S0 골든은 삭제·수정하지 않고 참고 기준으로 보존한다. 성능 정책·허용치 파일은 수정하지 않는다. S6 성능은 1회 참고 기록이며 판정하지 않는다. S5 사용자 승인 예외는 보존된 기준선으로 취급한다.


## S7 사용자 지시 및 검증 정책 (2026-09-26)
- 수정본13은 읽기 전용 기준이며 독립 복사본 수정본14에서 S7만 구현한다. S8은 시작하지 않는다.
- 원비 기준은 EA CalcOpenBands4의 OPEN 길이 4, 2-pass 모표준편차 계산이다. InpWonbiSigma는 시작 시 고정 입력이다. 설계서의 실행 중 sigma 파일 갱신안은 적용하지 않는다.
- SET_WONBI_SIGMA는 기대 sigma만 전달한다. 실제 밴드는 MT5 값을 그대로 사용한다. Python 원비 계산은 삭제하며 합성 입력 생성기만 EA식 포트를 허용한다.
- Part2 일반 회귀 묶음(validation_suite 기존 테스트, cadence_input_validation, conditional_validation, watch_ma_validation)은 게이트와 전체 실행 대상에서 제외한다. 파일은 보존하고 실행하지 않는다.
- part1_host 240초 3-way, 합성/실제 MT5/BTC 외부 동작 비교, 대표 판정 입력 샘플, S7 신규 테스트는 필수다. Part1 audit와 루트 tests는 계속 실행한다.
- 내부 DataFrame 비트/객체/private/set 순서는 진단만 한다. 외부 동작과 전략 의미 보존이 게이트다. 이전 Python 원비와 새 원비 수치 회귀 비교는 금지한다.
- 원비 변경 알림은 원인을 개별 분석하지 않고 건수와 '원비 원본 MT5 전환에 따른 승인된 기준 변경'으로 기록한다. S7 결과를 새 기준선으로 동결하고 S0 골든은 참고용으로 불변 보존한다.
- 개발 중 관련 파일/신규 테스트만 실행한다. 구현 완료 후 필수 전체 게이트는 최종 1회 실행하며 원인 분석에 필요한 실패 항목만 재실행한다. 성능은 참고 1회, 판정 없음.


## S8 사용자 지시 (2026-09-26, 이전 단계별 범위보다 우선)
- 수정본14 전체를 동결 후 독립 수정본15에서 S8 파이프·EA 최적화만 한다. 이벤트 엔진은 시작하지 않는다.
- S0–S7 기준선·expected·성능 정책·Part3·사용자 config 및 클라이언트/전략 계산식은 불변이다.
- EA 동일 XAU/BTC 구간 전후 Snapshot 흐름, baseline_S7 대비 5개 외부 시나리오 및 LIVE↔BACKTEST를 확인한다.
- Part1 audit/루트 tests 전체 각 1회와 S8 신규 테스트를 실행한다. Part2 기존 일반 회귀 4묶음은 실행하지 않는다.
- 성능은 동결된 CPU 고정 S0→후보 5쌍 규칙을 따른다. parser_650_rows와 oz_fvg_live_seconds만 판정하며 request_0~3은 참고다. S0 자체 범위 이탈도 실패이며 허용치를 바꾸지 않는다.


## S8 최종 사용자 승인 — 이전 보류 판정을 대체

S8은 **완료**다. `EA_separate_capture_values_identical`의 원시 실패는 그대로 보존하고, S7에서도 재현된 일봉 최초 2행·지표 24열 초기 버퍼 결함에 대해 **사용자 승인 예외**를 적용한다. 외부 동작 및 성능 게이트 통과를 완료 근거로 한다. 위 본문의 승인 보류/기준선 미동결 내용은 승인 전 이력이다.

현재 기준선: `검증결과/staff_s8/baseline_S8/manifest.json`. S7 기준선은 변경 없이 보존한다. 승인 전 보고서와 status는 `검증결과/staff_s8/approval_history/`, 원시 실패와 표본은 기존 위치에 보존한다.

E1은 이 지표 결함을 수정하지 않는다. MT5 별도 실행 간 비교에서만 `build/mt5_known_defect_exclusions.json`의 일봉 최초 이력 2개 시각 × 값 열 21~44(0-based)를 제외한다. 최초 FULL의 이력 시각에 고정하며 이후 매 창의 첫 두 행이나 ROW를 다시 제외하지 않는다. OHLC·거래량·원비·알림·health·seq 의미는 제외하지 않는다.

## E1 검증 범위 — 사용자 최신 지시
- MT5 실행 간 비교 캡처 및 S0 성능 5쌍 게이트는 실행하지 않는다. MT5는 STAFF_TIMER_MS input 변경 컴파일만 확인한다.
- 보존 MSP3의 최종 코드 묶음 처리 시간은 캡처별 1회 참고 측정한다. 개발 중 이전 측정이 있다면 별도 기록으로 보존한다.
- Part1 audit와 루트 전체는 각 1회, 실패 원인 분석 및 보완한 관련 시험만 재실행한다. Part2 일반 회귀 4묶음은 제외한다.
- checkpoint 압축 바이트 차이는 진단이다. 전체 디코드 값·타입·순서 있는 목록·외부 이벤트 검사는 유지하고 dict/set/frozenset 직렬화 순서만 정규화한다. 원시 실패와 재실행 증거를 함께 보존한다.
