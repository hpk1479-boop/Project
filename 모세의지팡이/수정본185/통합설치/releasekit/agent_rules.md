# 모세의지팡이 설치 폴더 AI 작업 규칙 (클로드 코드·코덱스 공용)

이 폴더는 설치된 모세의지팡이(MOSES) 프로그램이다. 원본 소스는 없고 엔진은 `runtime/code.bundle`에 들어 있다.
여기서 AI가 하는 일은 하나다. **엔진을 그대로 쓰면서 전략을 만들고, 세부 설정을 바꿔 가며 백테스트를 많이 돌리고, 결과를 정리해 보고한다.**

- 이 파일(`AGENTS.md`, `CLAUDE.md`)은 업데이트 때 새 파일로 바뀐다.
- 개발자 문서(`Part3/GPT_START_HERE.md`, `Part3/README.md`, `Part3/docs`, `Part3/ai_context`)와 이 파일이 다르면 이 파일을 따른다.
- 작업 파일(레시피 초안, 시나리오, 정책 파일, 결과 정리)은 `AI작업/` 폴더에 둔다.

## 1. 하지 않는 일

| 대상 | 규칙 |
|---|---|
| 프로그램: `runtime/`, `_internal/`, `MOSES.exe`, `python.exe`, `Part1/`·`Part2/`·`Part3/`의 프로그램 파일, `settings/strategy_registry.json`, `MT5/`, `매뉴얼/` | 고치거나 지우지 않는다 |
| `스페셜/기본` | 고치지 않는다(업데이트 때 바뀐다). 변형은 Part3로 새로 만든다 |
| 전략 파일(`*.recipe.json`, `Test_SPECIAL*.py`) | 손으로 쓰거나 고치지 않는다. 새 전략은 `Part3\cli.py generate`로만 만든다(8장의 복사만 예외) |
| `데이터창고`(녹화, 실행 결과 `runs/`) | 지우거나 옮기거나 고치지 않는다 |
| 데이터 구축(새 녹화) | 사용자 허락 없이 승인하지 않는다. `--yes`, `job confirm`을 쓰지 않는다 |
| 실시간 감시·설정: `Part1/special_settings.json`, `Part1/program/config.txt`, `settings/`, `Part3/projects/`, 텔레그램 | 바꾸지 않는다(`cli.py connect`도 쓰지 않는다). 실시간 시작·정지도 하지 않는다 |
| 비밀값(텔레그램 토큰, API 키) | 읽거나 옮기거나 보고하지 않는다 |
| 파일 삭제 | 하지 않는다. 지울 것이 있으면 목록을 사용자에게 알린다 |
| 다른 Python, 패키지 설치, 받은 코드 실행 | 하지 않는다 |

## 2. 명령 실행

- 모든 명령은 이 폴더에서 `python.exe`로 실행한다(PowerShell 기준 `.\python.exe`).
- 백테스트는 한 번에 하나만 돌린다. 앞 실행이 끝나면 다음을 시작한다.
- 전략·트리거 조합을 여러 개 시험할 때는 하나씩 돌리지 말고 6장의 레인 명령 하나로 돌린다.
- 돌고 있는 백테스트를 내 판단으로 멈추거나 다시 시작하지 않는다. 사용자에게 먼저 묻는다.
- 실시간 감시가 켜져 있으면 백테스트는 자동으로 낮은 우선순위로 돈다. 그래도 알림이 늦으면 안 되는 때는 사용자에게 묻고 `--cores`를 줄인다.
- 기간은 녹화에 찍힌 **브로커 서버 날짜**이고 끝 날짜는 포함하지 않는다(녹화 기준 9월 전체 = `--start 2026-09-01 --end 2026-10-01`). UTC 날짜나 한국 날짜가 아니다. 알림·거래 시각은 실제 한국시간으로 읽는다.
- 종목은 데이터창고에 녹화된 이름을 쓴다(예: `XAUUSD+`). 모르면 묻는다.

## 3. 전략 만들기 (Part3)

원하는 전략이 `스페셜/기본`·`스페셜/내 전략`에 없으면 Part3로 만든다.

1. 레시피 초안을 `AI작업/이름.json`에 쓴다: `{"recipe": {...}}`
   - 레시피 칸: `schema_version`(2), `base`("AI"), `name`, `description`, `symbols`, `strategy_intent`, 선택 `virtual_entry`(이 전략의 가상진입 기본값)
   - `symbols`는 `strategy_intent.symbols`와 같아야 한다.
   - 조건 어휘: `Part3/ai_context/STRATEGY_LANGUAGE.md`, `Part3/ai_context/MOSES_LANGUAGE.md`, `Part3/docs/AI_INTENT_SCHEMA.md`
   - 예시: `스페셜/기본/SPECIAL*.recipe.json`의 `recipe` 값
2. 검사(파일을 만들지 않음): `.\python.exe Part3\cli.py preview --recipe AI작업\이름.json`
   - `오류:`가 나오면 초안을 고쳐 다시 검사한다.
3. 생성: `.\python.exe Part3\cli.py generate --recipe AI작업\이름.json`
   - `Part3/TEST_SPECIAL/Test_SPECIAL번호.py`가 생긴다(번호 자동, 001~999).
4. 목록: `.\python.exe Part3\cli.py list`

- 같은 레시피를 두 번 생성하지 않는다(번호만 차지한다).
- 새 번호는 가장 큰 번호 다음이다. 999번이 있으면 더 만들 수 없으니 사용자에게 정리를 요청한다.

## 4. 백테스트: Part3로 만든 전략

```
.\python.exe Part3\cli.py backtest Test_SPECIAL005.py --start 2024-01-01 --end 2026-01-01 --symbol XAUUSD+ --action run --available-only
```

| 옵션 | 뜻 | 생략하면 |
|---|---|---|
| `--start`, `--end` | 기간 | (필수) |
| `--symbol` | 종목 | `XAUUSD+` |
| `--mode` | `BAR` / `EVENT` / `TICK` | `TICK` |
| `--action` | `plan`(계획만) / `run`(실행) | `plan` |
| `--available-only` | 있는 데이터만 쓰고 새로 녹화하지 않는다 | 꺼짐 → **항상 켠다** |
| `--result-mode` | `ALERT_ONLY`(알림만) / `VIRTUAL_ENTRY`(가상진입) | `ALERT_ONLY` |
| `--virtual-entry 파일.json` | 가상진입 정책(아래) | 레시피 값 |
| `--base-frame 2m` | 기준 프레임: 레시피를 그 시간봉으로 쓴 값으로 전략과 진입을 함께 옮긴다 | 레시피 시간봉 |
| `--spread-points` | 스프레드(포인트) | 0 |
| `--commission` | 수수료: 1랏 왕복 달러(예: 7) | 0 |
| `--cores` | 작업 프로세스 수 | 설정 화면 값(이 PC 최적값) |
| `--warehouse` | 데이터창고(상대 경로는 이 폴더 기준) | 연결 설정의 창고 |

- 녹화가 필요하면 "승인 대기"로 멈춘다. 승인하지 말고 계획(녹화할 구간)을 사용자에게 알린다.
- 스프레드를 0보다 크게 주려면 그 종목의 1포인트 가격이 있어야 한다. `종목 point (…) 값이 없습니다`가 나오면 설정 파일을 고치지 말고, 사용자에게 설정 화면(라이브 감시 설정 → 상세 설정 → 지표 → "NAS100 1포인트 가격"처럼 종목 이름이 붙은 칸)에 넣어 달라고 알린다.
- 수수료를 0보다 크게 주려면 그 종목의 1랏 크기(MT5 종목 사양의 계약 크기, 금은 보통 100온스)가 있어야 한다. `종목 1랏 크기 (…) 값이 없습니다`가 나오면 같은 화면의 "NAS100 1랏 크기"처럼 종목 이름이 붙은 칸에 넣어 달라고 사용자에게 알린다.
- 랏 수는 정하지 않는다. 가상진입은 거래마다 손절 = 1R로 계산하므로 수수료도 거래마다 `수수료 ÷ 1R`만큼 R에서 빠진다(손절폭에 맞춰 랏을 정한 것과 같은 값).
- 끝나면 `결과 폴더(창고 기준): runs/<실행 ID>`가 나온다.
- 상태·정지: `.\python.exe Part3\cli.py job status <실행 ID>`, `job stop <실행 ID>`

가상진입 정책 파일:
- 시작점은 이전 실행의 `runs/<실행 ID>/tested_settings.json` 안 `virtual_entry` 값이다. 그 값을 `AI작업/`에 파일로 저장해 숫자(손절 종류·배수, ATR 기간, 진입 조건·제한)만 고친다.
- 시간봉은 기준 프레임(`tf`)으로만 바뀐다. 칸마다 시간봉을 바꾸면 거절된다. 각 행의 `recipe_index`는 그대로 둔다.
- 이평 시가 위·아래: 조건 진입(`"mode": "CONFIRM"`)의 `conditions`에 하나만 넣는다. 알림 뒤 매 봉 시가가 그 봉 이평 이상(매도 이하, 같아도 진입)이 된 첫 봉에서 한 번만 판정한다. 알림 뒤 첫 봉이 이미 위여도 그 봉이다.
  - `{"kind": "MA_OPEN_POSITION", "family": "HMA", "period": 6, "tf": "SIGNAL", "max_atr": 0.3}`: 이평 종류·기간과 시가-이평 거리의 ATR 배수(이하면 진입)만 고친다. ATR은 `atr`(기간 14)이다.
  - 전봉 양봉 같은 다른 조건(예: `{"kind": "CANDLE_CLOSE"}`)은 같은 `conditions`에 넣는다. 그 봉에서 안 맞으면 패스한다(다시 기다리지 않는다).
  - 시가 기준 역크로스 패스는 `filters`의 이평 정배열 환경조건을 `"bar_state": "FORMING"`으로 둔다(예: HMA 6·17, `tf` SIGNAL). 기다리는 동안 매 봉 확인한다.
  - 결과의 `PASS_CONDITION`은 다른 진입 조건이 안 맞은 것, `PASS_DISTANCE`는 시가와 이평 거리가 넘은 것이다.
- `--virtual-entry`와 `--base-frame`은 함께 쓰지 않는다.
- 같은 전략·종목·기간·모드·기준 프레임에서 결과 방식·가상진입 값·스프레드·수수료만 바꾼 실행은 끝난 실행의 알림을 다시 써서 빠르다(그 실행 폴더가 남아 있을 때).

## 5. 백테스트: 기존 전략(스페셜/기본, 내 전략)

Part2 명령으로 돌린다. `Part2` 폴더에서 실행하고 창고를 반드시 지정한다.

`AI작업/s1.json`:
```json
{"symbol": "XAUUSD+", "start": "2024-01-01", "end": "2026-01-01", "mode": "TICK",
 "strategies": ["SPECIAL8"], "available_only": true,
 "result_mode": "VIRTUAL_ENTRY", "spread_points": {"XAUUSD+": 0}}
```
```
cd Part2
..\python.exe -m event_backtest run --scenario ..\AI작업\s1.json --warehouse ..\데이터창고
```

- `--warehouse`는 `Part3/projects/connections.json`의 `warehouse` 값이다. 상대 경로면 이 폴더 기준이므로 `Part2`에서는 앞에 `..\`를 붙인다(`데이터창고` → `..\데이터창고`). 빠뜨리면 다른 위치를 쓰므로 반드시 넣는다.
- 시나리오에 더 넣을 수 있는 칸

| 칸 | 뜻 |
|---|---|
| `triggers` | 전략별 올존 트리거: `{"SPECIAL2": "무지성 올존"}` (`올존`, `무지성 올존`, `브레이커 올존`, `무지성 브레이커 올존`) |
| `virtual_entry` | 가상진입 정책(4장과 같은 형식) |
| `commission` | 가상진입 수수료(1랏 왕복 달러): `{"XAUUSD+": 7}` (4장처럼 1랏 크기 필요) |
| `virtual_bases` | 기준 프레임 여러 개를 한 번에: `["1m", "2m", "3m"]` (가상진입, 전략 1개) |
| `trigger_variants` | 트리거 여러 개를 한 번에: `["올존", "무지성 올존"]` (올존 전략 1개) |
| `cores` | 작업 프로세스 수 |

- `virtual_bases`와 `trigger_variants`는 함께 쓰지 않는다.
- 이 시나리오의 가상진입은 전략 1개만 된다. 여러 전략·여러 트리거 조합은 6장의 레인 명령으로 돌린다.
- 시나리오에 넣지 않은 트리거·거래시간은 레시피 기본값이다(화면에 저장한 설정이 아니다). 실제로 쓴 값은 결과의 `tested_settings.json`으로 확인한다.
- 녹화가 필요하면 종료 코드 2와 `CONFIRMATION_REQUIRED`가 나온다. 승인하지 말고 사용자에게 알린다.

## 6. 여러 조합 한 번에 시험하기 (레인)

전략 여러 개 × 올존 트리거 여러 개를 시험할 때는 **조합마다 따로 돌리지 않는다.** 계획 파일 하나를 `lanes` 명령으로 돌린다. 녹화를 한 번만 읽고 모든 조합이 함께 재생되어 하나씩 돌리는 것보다 훨씬 빠르다.

### 레인 계산 방식

- 함께 쓰는 것(읽기만 함): 녹화 읽기, STAFF 스냅샷(봉·지표 묶음).
- 실행마다 따로인 것: 엔진 판단(전략 상태·올존·알림), 가상진입, 결과 기록(`runs/<실행 ID>/`).
- 그래서 각 조합의 결과는 그 조합 하나만 돌린 결과와 같다. 레인으로 돌렸다고 결과가 틀어지지 않는다.
- 실행 수가 `max_lanes`(기본 36)보다 많으면 자동으로 묶음으로 나눠 차례로 돈다(진행에 "묶음 2/4"). 묶음마다 녹화를 다시 읽는다.
- 보고에 어떻게 돌렸는지 적는다. 트리거만 레인으로 묶고 전략은 하나씩 따로 돌렸다면 그렇게 적는다.

### 순서

1. 전략 준비
   - 스페셜/기본·내 전략은 이름(예: `SPECIAL2`) 그대로 쓴다.
   - 조건을 바꾼 전략은 3장대로 만든다(`preview`로 검사 → `generate`). 시간봉 조합마다 전략이 하나다(예: 상위 2시간 + 하위 3분, 상위 2시간 + 하위 5분 → 전략 2개).
2. 계획 파일을 `AI작업/이름.json`에 쓴다(아래 칸과 예시).
3. 미리보기(아무것도 실행하지 않음): `.\python.exe Part3\cli.py lanes plan AI작업\이름.json`
   - 실행 수, 묶음 수, 쓰는 녹화 구간, 빠지는 구간이 나온다. 이미 끝난 실행은 빠진다.
   - `오류:`가 나오면 그 문장대로 계획 파일을 고친다.
   - "새로 녹화할 구간이 있습니다"가 나오면 실행하지 말고 사용자에게 알린다.
4. 미리보기를 사용자에게 보여 주고 시작해도 되는지 묻는다.
5. 실행: `.\python.exe Part3\cli.py lanes run AI작업\이름.json`
   - 끝날 때까지 진행이 나온다. 녹화 승인을 묻는 줄이 나오면 승인하지 말고 사용자에게 알린다.
6. 진행: `.\python.exe Part3\cli.py lanes status AI작업\이름.json` (몇 번째 묶음인지, 첫 묶음이 끝난 뒤에는 남은 시간)
   - 정지: `.\python.exe Part3\cli.py lanes stop AI작업\이름.json` (돌던 묶음에서 멈추고 다음 묶음은 시작하지 않는다)
   - 멈춘 뒤 같은 계획 파일로 `lanes run`을 다시 하면 끝난 실행은 건너뛰고 나머지만 돈다.
7. 결과: `.\python.exe Part3\cli.py lanes report AI작업\이름.json`
   - 표가 나오고 `AI작업/이름.report.md`에도 저장된다. 이 표로 보고한다.

계획 파일 옆에 `이름.lanes.json`(실행 기록)이 생긴다. 지우거나 고치지 않는다.

### 계획 파일 칸

| 칸 | 뜻 | 생략하면 |
|---|---|---|
| `symbol` | 종목(녹화된 이름, 예: `XAUUSD+`) | (필수) |
| `start`, `end` | 기간(2장: 브로커 서버 날짜, 끝 날짜 미포함) | (필수) |
| `mode` | `BAR` / `EVENT` / `TICK` (창고에 녹화가 있는 모드) | (필수) |
| `result_mode` | `ALERT_ONLY`(알림만) / `VIRTUAL_ENTRY`(가상진입) | (필수) |
| `strategies` | 전략 이름 목록. Part3 시험 전략끼리(`Test_SPECIAL005.py`) 또는 스페셜·내 전략끼리(`SPECIAL2`) | (필수) |
| `triggers` | 올존 트리거 목록: `올존`, `무지성 올존`, `브레이커 올존`, `무지성 브레이커 올존` | 전략 레시피의 트리거 |
| `spread_points` | 스프레드(포인트, 예: 금 20 = 0.2달러) | 0 → **항상 넣는다** |
| `commission` | 수수료: 1랏 왕복 달러(예: 7). 4장처럼 종목 1랏 크기가 필요하다 | 0 |
| `available_only` | 있는 데이터만 쓰고 새로 녹화하지 않는다 | `true` |
| `virtual_entries` | 전략별 가상진입 정책: `{"Test_SPECIAL005": {...}}` (4장 정책 파일과 같은 형식) | 레시피 값 |
| `max_lanes` | 한 번에 함께 재생할 실행 수 | 설정값(36) |
| `cores` | 작업 프로세스 수 | 설정 화면 값 |
| `special_settings` | 스페셜의 화면 저장 트리거·거래시간(보통 쓰지 않는다) | 레시피 값 |

- 실행 수 = 전략 수 × 트리거 수. 한 계획 안의 실행은 종목·기간·모드·결과 방식·스프레드·수수료가 모두 같다. 다르면 계획 파일을 나눈다.
- 계획 파일을 고치면 새 계획이다(앞 계획의 끝난 실행을 건너뛰지 않는다). 스프레드·수수료·가상진입만 바꾼 새 계획은 끝난 실행의 알림을 다시 써서 빠르다.

### 예시: 금 스페셜1, 상위 2시간 원비 × 하위 3분·5분 올존 × 트리거 4개 = 실행 8개

1. 레시피 초안 두 개(`AI작업/s1_2h_3m.json`, `AI작업/s1_2h_5m.json`)를 3장대로 검사·생성한다. 생성 결과가 `Test_SPECIAL051.py`, `Test_SPECIAL052.py`라고 하자(번호는 `generate`가 알려 준 것을 쓴다).
2. `AI작업/금_스페셜1_2시간.json`:
```json
{"symbol": "XAUUSD+", "start": "2020-01-01", "end": "2026-01-01", "mode": "BAR",
 "result_mode": "VIRTUAL_ENTRY", "spread_points": 20, "available_only": true,
 "strategies": ["Test_SPECIAL051.py", "Test_SPECIAL052.py"],
 "triggers": ["올존", "무지성 올존", "브레이커 올존", "무지성 브레이커 올존"]}
```
3. `lanes plan` → "runs": 8, "groups": 1 확인 → 사용자 확인 → `lanes run` → `lanes report`.

### 결과 표 읽기

| 열 | 뜻 |
|---|---|
| 거래 | 익절·손절로 끝난 가상 거래 수(같은 봉 익절·손절 미확정과 미청산은 빠짐) |
| 평균 R | 거래당 평균 손익(손절 1R 기준, 스프레드·수수료를 뺀 값) |
| t | 평균 R ÷ (표준편차 ÷ √거래 수). 2보다 작으면 우연과 구분하기 어렵다. 조합이 많을수록 더 큰 t가 필요하다 |
| 앞 70% → 뒤 30% | 기간 앞 70%와 뒤 30% 각각의 평균 R. 둘 다 플러스여야 꾸준한 것이다 |
| 비용 2배 | 스프레드·수수료를 한 번 더 뺀 평균 R(비용이 두 배여도 버티는지) |

- "꾸준한 조합"은 거래 30건 이상이고 앞·뒤 모두 플러스인 조합을 t 순으로 보여 준다.
- 스프레드 0으로 돌리면 표 위에 경고가 나온다. 그 결과로 판단하지 않는다.

### 자주 하는 실수

| 실수 | 바르게 |
|---|---|
| 전략 하나에 하위 시간봉 여러 개(예: 3분·5분)를 넣어 조합을 대신한다 | 시간봉 조합마다 전략을 하나씩 만든다 |
| 조합마다 `cli.py backtest`나 Part2 명령을 따로 돌린다 | 계획 파일 하나로 `lanes run` |
| Part2 시나리오 `strategies`에 여러 전략을 넣고 가상진입을 돌린다 | 여러 전략 가상진입은 `lanes`로만 |
| 종목·기간·모드가 다른 실행이나 Test_SPECIAL과 SPECIAL을 한 계획에 섞는다 | 계획 파일을 나눈다 |
| `available_only`를 `false`로 바꾸거나 녹화를 승인한다 | `true` 그대로 두고, 녹화가 필요하면 사용자에게 알린다 |
| 스프레드 0으로 돌린 결과로 판단한다 | `spread_points`를 넣고 다시 돌린다(알림을 다시 써서 빠르다) |
| CSV를 직접 계산해 다른 숫자로 보고한다 | `lanes report` 표로 보고한다 |
| `lanes plan` 없이 바로 `lanes run`을 한다 | 미리보기를 사용자에게 보여 준 뒤 실행한다 |

## 7. 결과 읽기

`데이터창고/runs/<실행 ID>/`

## 8. 남길 전략 (내 전략)

사용자가 남기라고 한 전략만 옮긴다.

1. `스페셜/내 전략`에 없는 번호를 고른다(SPECIAL100~SPECIAL999, `.py`·`.recipe.json` 모두 확인).
2. `Part3/TEST_SPECIAL/Test_SPECIAL005.py`를 `스페셜/내 전략/SPECIAL105.py`로 **복사**한다. 옆의 `.recipe.json`은 복사하지 않는다.
3. MOSES를 다시 열면 전략 목록에 나온다. 실시간 알림은 사용자가 전략 설정에서 직접 켠다.
