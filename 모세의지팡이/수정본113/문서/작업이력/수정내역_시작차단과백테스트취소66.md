# 수정본66 — 전략 설정 손상 차단과 백테스트 시작 직전 취소

이 문서는 1·2번 완료 당시 기록이다. 같은 수정본66에서 이어진 3·4번 작업은 [수정내역_엔진정상종료와중복시작66.md](수정내역_엔진정상종료와중복시작66.md)에 있으며 최신 전체 검증은 `CURRENT_VERIFY.md`에서 확인한다.

수정본65를 별도의 수정본66으로 복사한 뒤 우선순위 목록 1·2번을 처리했다. 이전 검증결과와 캐시는 복사하지 않았으며 원본·수정본65는 변경하지 않았다.

## 1. 손상된 전략 설정에서 라이브 시작 차단

`Part1/live_control.py`의 `load_special_settings()`는 설정 파일이 처음부터 없는 경우에만 `None`을 반환한다. 기존 파일의 읽기 오류, 잘못된 UTF-8·JSON·중복 JSON 키·SPECIAL 항목 구조·실행 여부·거래시간 등이 잘못되면 공개 오류 `SpecialSettingsError`를 발생시킨다. 웹과 독립 CLI의 `start_live()`가 이 오류를 받아 엔진 프로세스를 실행하기 전에 중단한다.

정상 저장 설정의 선택·OZ 트리거·거래시간 전달, 선택 전략이 없는 설정, 부분 설정과 기존 세션 bool 표기는 유지했다. 폐기된 OZ 프로필을 비활성화하고 `load_error`로 표시하던 기존 처리는 유지했다. SPECIAL 번호를 특정 개수로 제한하거나 전략 계산을 변경하지 않았다.

`Part3/lab/unified_live.py`의 전략 설정 조회는 손상 오류를 `settings_error`와 `needs_recovery`로 전달한다. 이때 화면의 전략 체크는 모두 해제된 복구용 표시다. 조회만으로 원래 파일을 변경하지 않으며 이 표시를 엔진 실행 설정으로 사용하지 않는다. 관계없는 예외를 정상 설정으로 숨기지 않는다.

사용자는 원래 설정 파일을 복구하거나, 전략 설정 화면에서 사용할 전략·조건·거래시간을 선택하고 **선택한 전략으로 복구 저장**을 누른다. 덮어쓰기 확인을 취소하면 저장 요청을 보내지 않는다. 확인한 요청의 `recover: true`가 있을 때만 손상된 파일을 새 선택으로 교체한다. 일반 저장 요청이나 `1`·문자열 `"true"`로 복구를 승인할 수 없다. 저장 후 엔진을 자동 실행하지 않으며 라이브 시작은 별도로 요청한다.

**전략 설정 새로고침**으로 현재 파일을 다시 읽을 수 있다. 화면을 열어 둔 사이 파일이 손상되면 기존 화면의 일반 저장도 서버가 차단하고 새로고침·복구 확인을 안내한다.

관련 API:

- `GET /api/mo/live/specials`: 기존 응답에 `settings_error`, `needs_recovery` 추가.
- `POST /api/mo/live/specials`: 손상 파일 복구 시 `recover: true` 필요. 정상 설정의 기존 요청 형식은 유지.
- `POST /api/mo/live/start`: 설정 손상 시 기존 오류 응답 경로로 시작 거부. 프로세스 실행 없음.

## 2. 백테스트 시작 직전 정지 요청 유지

`Part3/lab/unified_backtest.py`에서 프로세스 생성 직전 취소 여부 확인, `Popen`, 작업에 프로세스·현재 실행 단계 등록을 같은 잠금 안에서 처리한다. 정지 요청은 프로세스 생성 전에 취소를 기록하거나, 이미 생성된 프로세스의 실제 단계를 보고 정지를 전달한다.

- 계획 시작 전, 계획 종료 후 실행 전, 사용자 확인 대기 중, 확인 후 `starting`에서 정지하면 `cancelled`로 전환하고 이후 프로세스를 만들지 않는다.
- 실행 중이면 기존 `stop.request`를 기록해 Part2의 기존 안전 정지를 사용한다.
- 계획 프로세스가 이미 실행 중이면 기존 계획 종료 처리를 사용한다.
- 취소한 작업은 다시 확인해 실행할 수 없다. 취소한 작업의 예외 처리도 상태를 오류로 덮어쓰지 않는다.
- 이미 정상 완료한 Part2 결과는 뒤늦은 정지 요청 때문에 취소 결과로 바꾸지 않는다. 실행 중 결과의 완료·취소 판정은 기존 Part2 결과를 사용한다.

Part2의 정지 구현·결과 저장·계산식은 변경하지 않았다. 백테스트와 데이터 구축은 같은 웹 작업 실행 경로의 취소 처리를 사용한다.

이전 공식 검사의 제외를 늘리거나 기존 시험을 PASS로 강제하지 않았다. 신규 회귀 62 node와 새 Python 파일 문법 검사 3건을 추가했다. 제외 사유와 상세 로그는 `검증결과/current_verify/20261001_212102_483846/summary.json`, 공식 검사 목록은 `CURRENT_VERIFY.md`와 `verify_current_manifest.json`에 있다.

## 작업 범위와 다음 순서

Part1의 전략 계산 계층 `Part1/program`, Part2, Part3의 canonical schema·Recipe v2·validator·execution_plan·compiler·AI provider 및 기존 생성 전략은 변경하지 않았다. 이번 작업은 실행 제어·설정 오류 처리·복구 확인 UI에 한정한다.

수정본65와의 전체 파일 해시 비교와 보호 범위 확인: `검증결과/안전시작66/change_scope.json`. 이전 수정본의 증거를 가져오지 않고 이번 수정본에서 새로 작성했다.

다음 우선순위는 **정상 종료 요청 → 상태·전송 기록 저장 완료 확인 → 제한 시간 초과 시 강제 종료**다. 전체 수정본의 엔진 중복 조회/실제 준비 확인, 동시 저장·창고 제어, 생성 전략 작업 경로 통합, 실행 이력 복구, AI 대화 기록 제한은 후속 목록으로 남아 있다. 이 기능들을 이번 완료 범위에 포함하지 않는다.
