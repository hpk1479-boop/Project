# 수정본84: 공통 Strategy / Recipe와 관련 레거시 정리

수정본83을 별도의 수정본84로 복사하여 작업했다. 이전 검증결과 폴더는 복사하지 않았으며, 원본과 창고 데이터는 수정하지 않았다.

## 변경한 실행 구조

- `settings/strategy_registry.json`의 Recipe v2 데이터가 기본 preset의 조건·방향·봉 기준·시간·수명 규칙을 소유한다. SPECIAL1~7 번호로 실행 동작을 분기하지 않는다.
- 추가·삭제·수정은 registry와 Recipe로 처리한다. 실제 목록을 라이브 선택, 백테스트 선택, 진단 상태, 결과 metadata에 연결했다.
- Part1의 `strategy_recipe`가 공통 계약 검증, execution_plan, IntentMachine, IntentPort를 제공한다. Part3 schema/compiler와 생성 Python도 같은 경로를 사용한다. Part1/Part2는 Part3를 import하지 않는다.
- 사용하지 않는 SPECIAL1~7 전용 Python, 소스 복제용 special_templates, 번호별 OZ 선언·이름 변환·SPECIAL 전용 상태 파일 처리와 HMA 전체 이력 보정을 제거했다. 기존 WATCH의 공통 조건 실행은 유지한다.
- 실제 지표 계산은 기존 Fact/MA/OZ/FVG/SWEEP 계층을 사용한다. MT5 EA 및 Part2의 체결·통계·재생 계산식은 변경하지 않았다.

## 공통 언어 확장

- 시간 제한 없는 SEQUENTIAL/UNORDERED, 독립 분기, MA 상태·가격 교차·터치와 임의 양의 정수 기간
- 등록된 지표 값 비교, Percentile 계열 사건, 봉 마감, 당일 시가 기준
- 캡처한 FVG/OZ 사건 참조, 부모·자식 문맥, 지정 봉 수명, 재시작·교체·최초 성공 종료
- 활성화 시 확정봉 OHLC/ATR 스냅샷과 고정 스냅샷 대비 이동 폭 취소
- SOURCE/FINAL 시간봉 참조와 한국어 해석 표시

schema 참조는 AI 응답·도구 응답의 wrapper 안에서도 검증 가능하도록 연결했다. 모델명이나 교육 번호, 사용자 원문별 예외는 추가하지 않았다. 세부 필드와 사용 방법은 `문서/설계계약/공통Recipe84.md`에 있다.

## 종목 설정

기본 종목 목록은 `SYMBOLS` 한 개로 통합했다. STAFF 허용 종목, 명령의 기본 종목, 텔레그램 관련 기본 목록, Part3 설정은 공통 reader를 사용한다. 이전 두 설정 키는 값 이전을 위한 reader에서만 인식하고 저장할 때 제거한다. EA가 실제로 관측한 종목, 사용자가 명시한 명령 종목, 창고 캡처 목록은 별도 입력으로 유지한다.

## 저장 상태와 기존 자료

- 전략 상태는 공개 state provider를 통해 기존 엔진 저장 경계에서 checkpoint/restore한다. 재시작 때 현재 등록된 소유자와 현재 Recipe 상태에 맞는 OZ 감시만 복구한다.
- registry에서 삭제한 ID가 설정에 남아 있으면 UI에서 읽고 정리할 수 있다. 그대로 엔진을 시작할 때는 목록 변경을 알리고 차단하여 전체 preset이 잘못 활성화되는 것을 막는다.
- 캡처·DuckDB 구조와 원본 데이터는 그대로 사용한다. 데이터 재구축은 필요 없다. 변경된 전략의 결과는 새 규칙으로 다시 계산해야 한다.
- 이전 생성 Python 원본은 보존한다. 소스 복제/INHERITED 방식 파일은 공통 Recipe v2로 다시 생성해야 실행할 수 있다. 현재 canonical Recipe v2 파일은 AST로 Recipe 데이터만 읽고 공통 Port에 등록하며 원본 Python을 실행하지 않는다.

## 판정 및 검증 범위

과거 SPECIAL 결과를 정답으로 고정하지 않았다. 새로운 조건·확정봉/진행봉·순서·수명과 발생/비발생을 검사했고, 같은 입력의 LIVE/재생 알림을 확인했다. 번호별 내부 함수와 폐기된 소스 복제 구조를 고정한 검사는 이유를 기록해 진단용으로 분류했으며 유효한 저장·MA·Fact·시장·캡처·공개 연결 검사는 유지했다.

짧은 공개 엔진 비용 진단에서는 같은 HMA90/270 조건을 사용하는 두 전략에 진행봉 200틱을 넣어 MA 계산 2회, 다음 봉에서만 2회 추가를 확인했다. 캐시는 공유하며 불필요한 Processor/추가 Fact 호출과 엔진 오류는 없었다. 이것은 중복 계산 검사이고, 장기간 전체 백테스트의 속도 비교 결과는 아니다.

정식 schema로 표현·검증·컴파일·등록되는 기능을 확인했다. 교육 문장 1~100을 실제 AI 모델이 전부 올바르게 해석했다고 주장하지 않는다. 실제 MT5·텔레그램·AI 모델 연결 및 장기간 창고 백테스트는 이번 기본 검사에서 실행하지 않았다.

최종 검사 결과는 `검증결과/최종검증84.json`에 기록한다. 전체 변경 파일 목록은 `검증결과/change_inventory84.json`, 공식 검사/제외 사유는 `verify_current_manifest.json`에서 확인할 수 있다.
