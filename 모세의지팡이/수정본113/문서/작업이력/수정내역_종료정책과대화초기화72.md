# 수정본72 — 창 종료 정책과 대화 새로 시작

수정본71을 별도 수정본72로 복사했다. 이전 검증결과와 Python 캐시·가상환경은 복사하지 않았으며, 이번 검증 증거만 검증결과에 생성했다.

## 창 닫기

`START_MOSES.pyw`의 X 버튼을 누르면 새 백테스트 시작·계획 승인을 먼저 잠시 차단하고 실행 중인 공통 작업을 조회한다. 백테스트나 데이터 구축이 있으면 다음을 확인한다.

> 백테스트 또는 데이터 구축이 진행 중입니다.
> 작업을 중지하고 프로그램을 종료하시겠습니까?
> 중지 시점까지의 결과를 저장한 뒤 종료합니다.

- 아니오: 종료 차단을 해제하고 창·작업을 유지한다.
- 예: 모든 일반/생성 전략/AI 명령 작업에 기존 Part2 정지 요청을 전달한다. 관리 프로세스와 Part2 프로세스의 PID·생성 시각으로 종료를 확인하고, 실행된 작업의 완료·취소 결과 JSON 저장도 확인한다. 이후 기존 라이브 종료·저장 처리를 수행하고 Part3 소유 로컬 모델 프로세스·UI 서버·창을 종료한다.
- 작업 없음: 작업 종료 확인창 없이 정리한다.
- 정지·저장·프로세스 조회 실패 또는 시간 초과: 창을 유지하고 재시도를 안내한다. Part2를 강제 종료하지 않는다. 누락된 결과는 다음 종료 시도에서도 계속 확인한다.

전체 최근 목록의 20개 제한을 사용하지 않는다. 현재 창고와 현재 세션에서 실행·승인했던 다른 창고의 작업도 조회한다. 확인창이 뜬 사이 새 작업이 시작되거나, 설정의 창고를 바꿔 기존 작업이 종료 대상에서 빠지는 경우를 막는다. 종료 실패 시 새 백테스트·라이브 시작 차단을 해제한다. 저장된 작업과 결과 파일은 보존하며 자동 재실행하지 않는다.

브라우저 실행기의 서버 종료도 같은 정리 함수를 사용한다. 브라우저 탭 종료는 기존 유예·접속 감시 후 정리하며, 위 프로그램 종료 확인창은 전용 창의 X 버튼에서 제공한다. 별도 CLI로 실행한 독립 Part2 작업과 알 수 없는 외부 창고는 공통 작업 기록으로 식별할 수 없어 이 정책의 대상이 아니다. 외부 Ollama 프로그램은 종료하지 않는다.

## 대화 새로 시작

기존 버튼을 접힌 로컬 AI 연결 설정에서 AI 전략 연구 제목 옆 상단으로 옮겼다. 좁은 화면에서도 제목 아래에 표시된다. 현재 전략 대화·해석 확인·입력 초안·미리보기를 비우고 입력창으로 이동한다. 다음 전략은 직전 intent의 수정 문맥 없이 새 대화로 해석한다.

저장 설정, 생성 전략 파일, 다른 창의 전략 대화, 백테스트 명령 대화와 실행 작업, 모델 캐시는 유지한다. 기존 `/api/ai/reset`의 현재 session 제거를 그대로 사용한다.

## 변경 범위

- `Part3/lab/runtime_lifecycle.py`: 전용 창과 브라우저 서버의 공통 종료 순서.
- `Part3/lab/backtest_jobs.py`: 종료 확인 중 시작 차단, 전체 실행 작업 조회, 세션 창고 추적, 안전 정지와 저장·프로세스 종료 확인, 실패 재시도.
- `Part3/lab/backtest_supervisor.py`: 실제 run 시작 사실을 작업 기록의 `run_started`로 남김. Part2 계산·실행 명령은 유지.
- `Part3/lab/desktop_window.py`, `Part3/run.py`: 공통 정리 연결과 전용 창의 확인·취소 동작.
- `Part3/lab/unified_live.py`: 다른 종료 단계 실패 시 시작 차단 복구 API.
- `Part3/lab/ai/model_runtime.py`: 실행 중 AI 요청 종료를 기다린 뒤 소유 모델 worker 정리. 추론·schema·도구 계약은 유지.
- `Part3/web/index.html`, `style.css`, `ai_chat.js`, `unified.js`: 상단 초기화 버튼, 입력 초안 초기화, 어느 화면에서도 보이는 종료 안내.
- 새 검사: `verification/test_close_runtime72.py`, `verification/test_ai_reset72.py`, `verification/ui72_ai_reset.cjs`.
- 기존 종료 테스트 5개 파일의 실제 창고·엔진·모델 접근을 격리했다. 기존 동작 판정은 유지한다. 선택적 Windows 프로세스 검사도 자신이 만든 프로세스만 대상으로 한다.
- `verify_current_manifest.json`, `CURRENT_VERIFY.md`, `README_MOSES_DESKTOP.md`: 현재 검사 목록과 사용법.

Part1 313파일·Part2 1723파일의 변경·추가·삭제가 없고, Agent와 canonical schema/intent, Recipe 검증·execution_plan·compiler, 기존 Ollama provider는 그대로다. 범위 증거는 `검증결과/수정본72_작업범위.json`이다.

## 검증

새 종료 회귀 20건은 취소·승인·중복 X·새 작업 경쟁·시간 초과·재시도·다른 창고·결과 누락·AI 요청 대기·소유 모델 worker 종료를 검사한다. 실제 관리 프로세스와 임시 가짜 Part2를 실행해 정지 요청 → CANCELLED 부분 결과 저장 → 정확한 프로세스 종료 → 창 닫기 순서도 확인했다. 실제 시장 데이터나 MT5를 사용한 재생 시험은 아니다.

대화 초기화 기본 회귀 4건, 실제 Edge의 신규 UI 6건과 기존 수정 대화 UI 7건이 통과했다. 420px 화면에서 버튼 표시와 가로 넘침을 확인했다.

전체 공식 검증 결과와 제외 이유는 `CURRENT_VERIFY.md` 및 `검증결과/current_verify/latest.json`의 이번 수정본 결과에서 확인한다. UI 증거는 `검증결과/AI대화초기화72/`, `검증결과/AI수정대화_현재72/`에 있다.
