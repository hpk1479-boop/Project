# Part1 메인 대시보드 UI 재구성

## 범위

- 목표 시안의 정보 계층에 맞춰 Part1 메인 창을 간결한 헤더, 한 줄의 작업 버튼 3개, 2열 × 4행 상태 카드, 낮은 하단 상태 바로 재구성했다.
- Canvas 위젯으로 카드·버튼·상태점·모듈별 선 아이콘을 그렸다. 카드 전체 클릭은 기존 모듈 로그 창을 연다. 반복되던 `로그 보기` 문구는 제거하고 작은 chevron만 남겼다.
- 승인된 2열 × 4행 레이아웃과 크기를 유지했다. 전체 배경·헤더에는 매우 약한 네이비 그라데이션을, 전체 시작 버튼 안쪽에는 약한 수직 블루 그라데이션을 적용했다. 둥근 외곽은 Canvas polygon으로 그려 모서리 계단 현상을 피했다.
- 모듈 카드는 기본 색상을 유지하고 호버 때 배경·테두리·chevron만 조금 강조했다. 상태 색상은 연결중=녹색, 연결 대기=청회색, 오류=빨간색이다. 패널과 아이콘 박스는 명도 차이로 구분했다.
- 상태 표시 문구를 `연결 대기 / 연결중 / 오류`로 통일했다. 상태 판단 조건은 유지했다.
- Part2 디자인과 기능은 수정하지 않았다. 거절된 Part2 다크 화면과 그 검증 자료는 제거했다.

## 실제 화면 확인

- Part1 컨트롤러를 실제 Tk 창으로 실행해 `검증결과/part1_canvas_final.png`와 OZ 카드 호버 상태 `검증결과/part1_canvas_hover.png`를 캡처했다. 캡처를 위해 전체 시작·종료 버튼은 누르지 않았고, 모듈 상태는 기존 진단 스냅샷의 값을 그대로 표시했다.
- 최초 목표 시안과 헤더→주요 작업→상태 카드→상태 바의 정보 계층, 카드 간격, 버튼 크기, 명암 단계를 직접 대조했다. 실제 모듈 8개는 사용자 지시에 따라 2열 × 4행으로 배치했다.
- 창 폭을 860에서 1020으로 늘리거나 최소 740 × 650으로 줄였을 때 카드가 잘리지 않는 것을 확인했다.

## 기능 보존 확인

- 수정본30 대비 `MosesController`의 `__init__`을 제외한 모든 메서드 AST가 같다. 시작·종료·전략 설정·닫기 동작의 기존 콜백을 그대로 연결했다.
- 수정본30 대비 Part2의 모든 Python 소스 해시가 같다. 공유 `special_ui.py`도 수정본30과 동일하게 복원했다.
- Part1 Canvas UI 단위 시험 3개와 기존 모듈 로그 반응속도 시험 3개 통과. 2열 × 4행 배치, 버튼 비활성화·호출, 카드 클릭 연결, 세 상태 문구와 기존 상태 조건을 확인했다.
- 수정한 Part1 Python 파일의 구문 분석 통과. 실제 텔레그램 전송, 전체 시작 및 종료 버튼 실행은 하지 않았다.
- `build/part1_immutable_sha256.json`과 소스 무결성 체인에 수정된 UI 소스 해시를 등록했다. 소스 무결성 진단 6건은 수정본30에도 동일하게 존재한다. 실행 중 생성되는 로그·캐시는 수시로 바뀌므로 전체 파일 목록은 운영 중 고정되지 않는다.
