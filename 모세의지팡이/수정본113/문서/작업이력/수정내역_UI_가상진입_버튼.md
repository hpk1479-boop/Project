# Part2 가상 진입 실행 버튼 높이

수정본33을 수정본34로 복사해 작업했다. 이전 수정본의 `검증결과`는 복사하지 않았으며 이번 화면 확인 자료만 `검증결과/UI_가상진입_버튼/`에 두었다.

## 원인과 수정

결과 옵션의 오른쪽 카드는 높이가 208px로 고정되어 있었다. 가상 진입을 선택하면 스프레드 입력 행이 추가되어 같은 카드 아래의 실행·정지 버튼 공간이 부족해졌다. 처음 선택한 화면에서는 두 버튼의 높이가 알림 온리 48px, 가상 진입 43px로 확인됐다.

첫 높이 조정만으로는 반복 전환을 해결하지 못했다. **데이터 구축 → 가상 진입**으로 전환하면 숨겨진 `초기화 후 녹화` 체크박스의 빈 부모 행이 계속 공간을 차지했다. 224px 카드에서도 버튼이 31px로 줄어드는 것을 실제 창에서 재현했다.

`Part2/event_backtest/gui.py`의 중간 좌우 카드 높이를 모두 224px로 맞췄다. 또한 데이터 구축이 아닌 모드에서는 체크박스뿐 아니라 그 부모 행도 배치에서 제거하고, 데이터 구축으로 돌아올 때만 다시 표시한다. 스프레드 행도 가상 진입 모드에서만 배치한다. 모드 선택 값, 숨겨진 입력값, 실행·정지 callback, 설정 저장, 백테스트 로직은 바꾸지 않았다.

## 확인

| 모드 | 변경 전 실행/정지 | 변경 후 실행/정지 |
|---|---:|---:|
| 알림 온리 | 48/48px | 48/48px |
| 가상 진입 | 43/43px | 48/48px |

반복 전환에서 발견된 중간 상태: 높이만 늘린 버전은 데이터 구축 뒤 가상 진입에서 **31/31px**. 최종 수정은 데이터 구축 ↔ 가상 진입을 포함한 8회 연속 전환에서 매번 **48/48px**다. 체크박스 부모 행은 데이터 구축일 때만 화면에 남았다.

실제 Tk 창을 열어 두 모드와 반복 전환 후 화면의 스크린샷을 저장했다. 최소 창 크기 1000×770에서도 알림 온리·가상 진입·데이터 구축 세 모드의 실행/정지 버튼이 모두 48px로 표시되고 창 안에 남는 것을 확인했다. 사용자 config의 SHA256은 수정본33과 같다.
