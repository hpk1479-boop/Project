# 수정본39 — 워커 배정 검증 도구

운영 변경은 `Part2/event_backtest/runner.py`와 신규 `worker_schedule.py`뿐입니다. Part1, 전략, 설정, 청크 분할, 워밍업 계산, 실제 `run_chunk` 함수는 수정본38 그대로입니다.

## 포함 도구

- `process_probe.py`: 실제 `run_chunk`를 spawn 프로세스풀로 실행합니다. DuckDB가 없는 경우 기존 수정본37 검증 로더를 사용하며 **부모 SQL 검증으로 취급하지 않습니다**. 단일 하루 입력과 검증 전용 고정 6개 구간을 지원합니다. 구간 내부 이벤트·워밍업을 생략하지 않습니다.
- `run_regressions.py`: 현재 Part2/워커 관련 기존 검사 196개를 실행합니다. 환경상 실패를 숨기지 않습니다.
- `verify_workers.py`: 실제 외부 창고에서 수정본38/39의 정상 `run()` 전체를 비교합니다. DuckDB 필수이며 입력·의존성 우회가 없습니다. 두 버전에 같은 워커 수·분할·워밍업을 적용합니다.
- `../../tests/test_worker39.py`: 배정 순서, 작업 불변성, 제한된 제출, 완료·실패·중단, 진행률 파일의 재시도, 실제 부모 제어 흐름의 회귀검사입니다. 부모 제어 흐름 단위검사의 SQL/워커는 명시적 테스트 대역입니다.

## 실제 창고 전체 비교

아래 명령의 두 프로젝트 폴더와 창고 위치는 실행할 컴퓨터에 맞게 지정합니다. 입력 기간과 이전 3거래일 녹화가 모두 있어야 합니다. 입력 누락이면 실패로 남기며 새 녹화나 합성 입력을 만들지 않습니다.

```powershell
python -X utf8 -B build/optimization39/verify_workers.py `
  --before "..\수정본38" --after "." --warehouse "..\실제창고" `
  --start 2026-09-01 --end 2026-09-08 `
  --workers 4 --overlap-days 3 --work-size MONTH --repeat 3
```

이 명령은 이 배포본의 검증 환경에서 실행하지 않았습니다. 실제 1주 녹화와 DuckDB가 없었습니다. 운영 사용 시 사용하는 워커 수를 `--workers`에 넣습니다. 새로운 코어 수를 자동 추천하거나 기간을 재분할하는 도구가 아닙니다. 두 버전에 동일한 값을 적용합니다.

비교 시 실행마다 다른 `run_id` 열만 제외하고 CSV 헤더·나머지 모든 열·행 순서·중복 행, 청크 경계/워밍업/번들 수, 설정, 캡처 목록을 비교합니다. 정상 부모 실행의 준비·재생·병합 전체 경과시간을 기록합니다. 이 도구는 CSV를 정렬해 차이를 숨기지 않습니다.

## 포함 하루 녹화로 재현

프로젝트 루트에서 실행합니다. 창고 역할을 하는 폴더가 검증 도구에서는 프로젝트 안에 있어도 되며, 운영 `settings()`의 외부 창고 규칙은 변경하지 않았습니다.

```powershell
python -X utf8 -B build/optimization39/process_probe.py "." `
  "검증결과/worker39/replays" "검증결과/worker39/replays/tests/recheck39" `
  --strategy ALL --layout multi --workers 2 --context spawn --optimized --trace --affinity ""
```

수정본38을 비교할 때는 첫 인수를 해당 프로젝트 폴더로 바꾸고 `--optimized`를 빼며, 출력 폴더는 별도로 지정합니다. `--layout multi`는 실제 하루 녹화를 6개 고정 출력 구간으로 평가하는 **배정 검증용 부하**입니다. 운영 `partition.py`를 수정하거나 실제 1주 데이터를 복원한 것이 아닙니다. 각 청크는 동일한 00:00 워밍업 시작을 사용하므로 전체 1,378개 입력에 워밍업 반복 1,920개가 더해져 3,298번들이 처리됩니다.

## 실행 환경과 범위

측정은 Linux/Python 3.13의 spawn 프로세스풀에서 했습니다. 실제 Windows/MT5, 전체 부모 DuckDB 경로, 실제 1주·장기 구간의 검증은 포함하지 않습니다. 실행 순서를 바꾸는 최적화이므로 **작업이 1개이거나 한 번에 모두 실행되는 경우에는 큰 시간 개선을 기대하는 구조가 아닙니다**. 측정 수치와 원시 표본은 `검증결과/worker39/final_report.md`에 있습니다.
